## 目标
把当前实际工作树上的文档从“内容扩充但语言/事实/校验尚未闭环”推进到可发布状态；保留所有现有未提交变更，不重置、不覆盖截图或临时脚本。

## 当前判断与优先级
目前源码已在既有 15 篇基础上新增 7 篇中文文档（搜索规则、音乐库、移动端、推荐、帐户安全、数据管理、故障排查），导航和结构检查也已开始扩展，但新增页尚未进入其他语言目录，校验基线与 README 仍需同步。旧页面中还存在用户容易误解的关键矛盾：登录与收藏“同步”表述和本地存储事实不符；第三方清单把默认开启的跨源补齐放在“默认关闭”一节；数据权利章节的承诺需与实际导出/删除能力明确区分。

## 实施范围
1. **先完成当前 22 篇文档的信息架构与语言矩阵**
   - 保留现有 7 篇中文新文档，按正式中文稿补齐另外 9 种语言的对应页，使 10 语言 × 22 篇结构完整。
   - 完成侧栏各条目与分组的 10 语言文案，避免英文、日文或其他语言静默回退到简体中文。
   - 更新 README 中的文档清单、页面数、版本与验证说明（按实际 22 × 10 = 220 篇内容页；根入口页另计）。
2. **跨语言修正文档事实与权利闭环**
   - 全语言明确：收藏、歌单与偏好仅保存在各自浏览器，不提供跨设备云同步；同步修正快速开始、条款、隐私说明、页面描述及 README 中的误导性用语。
   - 将第三方共享清单拆分为“默认启用的查询/补齐链路”与“需部署者开启的可选服务”，使标题、表格默认值和图注一致。
   - 明确数据导出/删除现有能力与限制：不把画像摘要称为完整数据导出，不声称浏览器具有通用 localStorage/IndexedDB 导出功能；分别说明可查询、可清除、未提供导出的数据类别及人工权利请求途径。
   - 对 API/部署/法律文档只陈述当前仓库或可核实来源支持的事实；无法从本仓库确认的上游接口细节及最终许可证裁决，不臆造结论，改为清楚标注权威来源/待核验边界，必要时在实施时检查相邻 Sonic 源码仓库。
3. **修复语言入口和加入回归检查**
   - 扩展 `functions/_lib.js` 的 Accept-Language 协商，覆盖全部 10 种语言、区域变体与 q 权重；繁体中文进入 `zh-tw`，简体中文进入默认根路径，未支持语言回落简中。
   - 更新 `public/index.html` 的静态备用入口，提供全部语言的可选链接。
   - 给语言协商加入无需第三方依赖的测试，并接入 `pnpm validate`。
4. **让校验与文档承诺一致**
   - 修正结构检查器的旧文档数/描述，验证 22 篇在所有语言均存在并保持既定结构。
   - 修正锚点/资源检查，使其识别 `/sonic/images/...` 的实际构建路径；补充本地文档链接目标检查，避免当前“0 图片错误”实际漏检带 base 前缀资源的情况。
   - 同步 README、`package.json` 中的命令说明及当前页面计数；运行完整构建和 `pnpm validate`，处理检查发现的问题。
