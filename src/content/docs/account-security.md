**修订日期：2026 年 11 月 2 日｜版本：1.8**

本页说明 Sonic 账户体系之运作方式与安全使用建议。技术实现之完整说明见[数据处理与安全维护](/data-security/)第 3.2 节；合同约定见[用户条款](/terms-of-service/)第 3 节。

## 1. 登录方式

最新公开 RC `rc/sonic-20261031@a75f5cb`（2026-11-01 UTC）实现 Epomail OAuth 2.0（PKCE），不设独立注册：账号入口 → Epomail 授权 → 返回 Sonic。流程检查 state、PKCE 和回调，认证端点默认每分钟每 IP 30 次。较早默认分支 `main@ce443c8`（2026-10-27 UTC）的旧认证路径不具备这些完整控制，仅供相容性对照，不能证明 RC 已部署；线上版本未知。登录字段不证明年龄，年满 16 岁是测试服务使用门槛而非已验证年龄；OAuth 身份验证不是可选画像分析同意，也不自动接受全部条款。

## 2. 会话机制

1. **会话与 Cookie**：最新公开 RC 的 `sonic_session` 默认有效 30 日，使用 `HttpOnly; Secure; SameSite=Lax`（本地 HTTP 开发环境可能不同）；签章只保证完整性，不是加密，且会话之外的帐号资料仍可能持久保存。较早 `main@ce443c8` 的回调／query 凭证风险不能当作 RC 或现网事实；实际部署仍须核验，不要使用真实生产凭证；
2. **跨分页同步**：同一浏览器分页是否共用登录状态依实现而定，不是跨设备音乐库备份，也不证明被复制凭证已撤销；
3. **本地资料与金钥**：API Key 不应置于 URL；前端 `auth` localStorage 可能保留电子邮件地址与头像信息，头像路径也可能把标识发送给外部服务。OAuth 交易 Cookie 默认 600 秒；实际部署的期限与属性仍须核验。

## 3. API Key 保管

若实例提供 API Key，它是您的个人凭证；最新公开 RC 使用版本化 `sonic_live_v2` 与 HMAC-SHA256 签章，凭证不得放入 URL，签发期限和撤销仍须按实际实例核验。较早 `main@ce443c8` 仅作相容性对照，不能证明 RC 或现网部署：

1. 仅经请求标头传递，永不置于 URL；
2. 不得转交第三方或嵌入公开发布之客户端；
3. 重新签发须出示目前有效金钥；外泄时尽速退出登录并请求撤销，核验远端结果而非假定成功（见第 4 节）。

## 4. 撤销与退出登录

| 操作 | 位置 | 效果 |
| --- | --- | --- |
| 退出登录 | 播放器内 | 清理目前 Cookie；被复制凭证的远端撤销依赖设置与请求成功 |
| 金钥撤销 | `POST /api/auth/revoke` | 需要支持的撤销储存及请求成功，不保证每个实例可用 |
| 批次作废 | 部署者设置 | 静态 jti／主体清单与签发时间下限须完成设置及验证 |

## 5. 安全使用建议

1. 共用设备使用后退出登录并清理浏览器账号资料；被复制的凭证仍可能需要运营者协助撤销，浏览器清理不删除远端画像；
2. Epomail 账号建议启用两步骤验证（于 Epomail 端设置）；
3. 账号不出借、不共用——共用账号之资料混同无法区分与复原；
4. 发现异常播放记录或来源不明之会话时，立即退出登录并致函 `admin@epocanvas.com`；
5. 本服务不搜集密码（登录由 Epomail 完成），任何“Sonic 密码验证”请求均属冒名。

## 6. 帐号管理入口

侧栏底部之账号入口显示当前登录状态：未登录时提供登录引导；登录后显示账户昵称并提供账号管理连结（指向 Epomail 之个人资料与收件匣）。登录状态跨分页自动同步。
