**生效日期：2026 年 11 月 2 日｜版本：1.5**

本页说明 Sonic 帐户体系之运作方式与安全使用建议。技术实现之完整说明见[数据处理与安全维护](/data-security/)第 3.2 节；契约约定见[用户条款](/terms-of-service/)第 3 节。

## 1. 登录方式

本服务以 Epomail 帐号经 OAuth 2.0（PKCE）登录，不设独立注册系统。登录流程：点击侧栏帐号入口 → 跳转 Epomail 授权页确认 → 返回本服务即完成登录。授权回调经 state、PKCE、授权码与重放四重校验；认证端点限每分钟每 IP 30 次。

## 2. 会话机制

1. **会话 Cookie**：登录成功后签发 `HttpOnly; Secure; SameSite=Lax` 之会话 Cookie，有效期至多 30 日；Cookie 内含签名 API Key，脚本不可读；
2. **跨标签页同步**：登录状态在同一浏览器之各标签页间自动同步；在任一标签页登出，其余标签页同步感知；
3. **金钥边界**：API Key 不写入 URL、查询参数或 localStorage；OAuth 事务 Cookie 有效期仅 600 秒。

## 3. API Key 保管

API Key 为您的个人凭证（格式 `sonic_live_v2.…`，HMAC-SHA256 签名）：

1. 仅经请求标头传递，永不置于 URL；
2. 不得转交第三方或嵌入公开发布之客户端；
3. 重新签发须出示当前有效金钥；外泄时立即登出并撤销（见第 4 节）。

## 4. 撤销与登出

| 操作 | 位置 | 效果 |
| --- | --- | --- |
| 登出 | 播放器内 | 即时撤销当前会话与金钥识别码（jti） |
| 金钥撤销 | `POST /api/auth/revoke` | 撤销当前 API Key |
| 批量作废 | 部署者配置 | jti 清单、主体清单与全局签发时间下限 |

## 5. 安全使用建议

1. 于共用设备使用后务必登出（会话 Cookie 内含签名金钥）；
2. Epomail 帐号建议启用两步验证（于 Epomail 侧设置）；
3. 帐号不出借、不共用——共用帐号之资料混同无法区分与恢复；
4. 发现异常播放记录或来源不明之会话时，立即登出并致函 `admin@epocanvas.com`；
5. 本服务不收集密码（登录由 Epomail 完成），任何「Sonic 密码验证」请求均为冒名。

## 6. 帐号管理入口

侧栏底部之帐号入口显示当前登录状态：未登录时提供登录引导；登录后显示帐户昵称并提供帐号管理链接（指向 Epomail 之个人资料与收件箱）。登录状态跨标签页自动同步。
