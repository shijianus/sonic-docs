## 1. 数据生命周期

| 阶段 | 当前可核对的事实与边界 |
| --- | --- |
| 收集 | 登录由 Epomail OAuth 提供；播放、搜索和推荐可能产生事件。最新公开 RC 默认开启个性化，不能把该默认值当作可选画像的同意；线上版本未知。 |
| 传输 | 浏览器、边缘、数据面和上游之间的路径依部署而变。内部及部分上游路径使用明文 HTTP，不能声称全链路 TLS；MV、封面、字体或头像可能由浏览器直接请求。 |
| 存储 | 浏览器可保存帐号资料、队列、历史、偏好、本地音乐和缓存；行为数据、日志、备份及供应商记录的实际位置和期限须按部署核实。 |
| 使用与共享 | 搜索、播放和登录用于回应请求；画像、Auto DJ、搜索统计和公共建议可能使用行为或搜索上下文。接收者和开关见[第三方共享与传输清单](/sub-processors/)。 |
| 删除 | 当前画像重置主要针对当前身份的部分事件或反馈，不保证覆盖雷达、搜索聚合、备份、日志、外部服务或旧匿名标识；撤销也取决于撤销存储配置和请求是否成功。 |

## 2. 处理矩阵

| 活动 | 可能涉及的数据 | 处理边界与期限 |
| --- | --- | --- |
| 请求的搜索、播放、歌词和登录 | 查询、内容标识、会话、Epomail 返回的帐号资料 | 以回应请求为限；登录资料可能在浏览器和会话中存在。 |
| 行为画像、Auto DJ 和推荐 | 播放、进度、跳过、收藏、拒绝、搜索、假名标识和本地上下文 | 属于画像或可能支持画像的处理；当前默认开启，拒绝或撤回后的停止和删除不得推定已经完成。 |
| 搜索统计与公共建议 | 搜索原文、计数及相关上下文 | 现有路径可能展示用户搜索词；在过滤、阈值和期限未落实前，不应称其为匿名聚合或安全公开。 |
| 限流和安全 | 原始 IP、Cookie、认证头、User-Agent、上下文及帐号或会话派生键 | 可能随请求转发至数据面引擎；仅限防滥用、连接和安全所需的说法须以实际路由核实。 |
| 本地资料与评论 | localStorage、IndexedDB、导入音乐、下载缓存、本地评论及上游评论资料 | 本地音频 Blob 未发现上传路径；歌词和推荐仍可能发送标题、艺人、专辑、时长或标识，内嵌封面图片可能随事件进入远端曲目目录。上游评论可能含他人姓名、头像和文字并进入公共缓存。 |
| 支持、争议和法定义务 | 主动提交的邮箱、说明、必要证据和处理记录 | 只在处理请求、争议或义务所需期间保存；没有统一已核验的宿主备份期限。 |

法律依据、保存期限和接收者须结合实际目的、用户和部署配置逐项判断；免费、个人维护或开源不自动降低安全或告知要求。

## 3. 安全维护措施

### 3.1 传输与接入

1. 公开入口可配置 HTTPS、OAuth、签名会话和服务间密钥；这些代码控制不能证明实际入口、代理和上游均使用 TLS。
2. 控制面与数据面是否经加密隧道、数据面是否只绑定回环地址，取决于托管配置。内部明文 HTTP 路径已足以否定“全链路加密”的笼统表述。
3. 代理路由的目标校验和域名限制仅覆盖实际经过代理的请求。审计发现原始 IP 可能随 Cookie、认证头和上下文转发到引擎；不能把引擎称为只接收假名资料。
4. 音频流的请求可能使用浏览器 User-Agent，而非固定值；浏览器直连 MV、封面、Google Fonts 或头像服务时，对应服务可能看到 IP 和连接元数据。

### 3.2 认证与金钥

1. 最新公开 RC 使用 OAuth state 与 PKCE，签章工作阶段默认 30 日；实际 Cookie 属性、期限和线上部署仍须核验。签章不是加密，凭证酬载可能含邮箱、使用者或角色识别码。较早 `main@ce443c8` 的 URL 凭证风险仅作旧版相容性警示。
2. API Key 的版本、签名、时间和 `jti` 校验失败时应拒绝请求；不得把名称、环境变量或设计注释当作完整认证控制证明。
3. 登出或批量撤销是否即时生效取决于撤销存储、开关和请求是否成功；未启用或未验证时不能保证所有已复制凭证立即失效。

### 3.3 出站请求防御

代码包含部分 SSRF、私网和重定向校验以及音乐域名白名单。它们不等于所有上游或第三方浏览器请求都被代理、净化或匿名化。DiceBear 当前存在以明文邮箱作为 seed 的头像 URL 路径；Google Fonts、MV 和封面直连可能使相应服务看到 IP。部分提供方使用 HTTP，不能声明全链路 TLS。

### 3.4 存储与日志

1. 浏览器端的 `auth`、`audio`、`library`、`global`、`settings`、`recommend` 及 IndexedDB 会按功能保留资料，退出登录不自动清除全部设备数据。
2. 服务端行为数据如以假名标识关联，假名化仍可能与其他资料结合识别；它不是匿名化，也不覆盖搜索、雷达或第三方数据。
3. 应用、Cloudflare、宿主和上游日志，以及备份的实际轮转、访问权限和到期销毁未由本次核对统一确认；不能填写虚构备份期限或“零日志”承诺。
4. 可选 Meilisearch 可能处理原始查询或目录资料；Gorse 的删除是否与本地删除同步未核实。外部推荐或搜索存储不能被本地重置成功替代。

### 3.5 已知局限

1. 个性化及 Auto DJ 默认开启，缺少可证明的事前、独立和可撤回选择；这不是同意。
2. 公共搜索建议可能复用原始搜索词，存在暴露个人或敏感信息的风险。
3. 删除主要覆盖当前身份的部分事件，未核实覆盖雷达、备份、日志、外部服务、Meilisearch、Gorse 和旧匿名标识；雷达耐久引擎路由未确认，不对其存储状态作肯定断言。
4. 内部明文 HTTP、Google Fonts、直接 MV/封面请求、浏览器 User-Agent 及 DiceBear 明文邮箱 URL 使“全链 TLS”或“邮箱不外传”的表述不准确。
5. 限流、撤销、日志和第三方开关依实例环境变量及供应商配置；GDStudio 代码在未设置时默认开启，但环境或 Compose 可设为关闭，不能仅凭清单声称默认关闭。

## 4. 资料外泄应变

GDPR 适用时，安全措施应依资料性质、处理规模、实施成本和实际风险保持相称（GDPR 第 32 条）。运营者应记录每宗资料外泄；除不太可能对个人权利和自由造成风险外，应无不当迟延且可行时在知悉后 72 小时内向有管辖权的监督机关通报，迟报说明原因（GDPR 第 33 条）；高风险时还应无不当迟延通知当事人，适用法定例外除外（GDPR 第 34 条）。这不是自动向某一国家机关报告的承诺，也不免除其他适用法律。

实际处置应隔离受影响系统，保护或撤销凭证，确认资料类别、范围、接收者和时间线，并记录判断和补救。可通过 `privacy@epocanvas.com` 提交疑似事件；不要发送密码、完整令牌、会员 Cookie 或不必要的个人资料。

## 5. 资料保护的设计与默认

GDPR 第 25 条要求在确定处理手段时考虑设计与默认保护。本项目目前不能声称已完全落实：

1. 可选画像应默认关闭，并提供同等便利的接受、拒绝、撤回和记录；当前源码默认开启，登录或继续使用不能替代同意。
2. 公共搜索建议应先停用或实现最小展示、过滤、阈值、期限和删除控制。
3. 头像 seed 不应使用明文邮箱；Google Fonts、MV、封面和其他直连资源应在评估 IP、Cookie 和标识符传输后再启用。
4. 应核查可关联的旧假名标识、雷达、搜索、共享曲目及封面、日志、Meilisearch、Gorse 和备份，依法处理适用删除范围，并在适用时通知接收者；法定保留例外应说明理由、范围和期限，不能以当前身份部分清理冒充完整删除。

## 6. 自行部署运营者的义务

自行部署实例独立运营。本页的检查提示不对部署者创设超出实际法律与许可证的合同义务，也不构成作者的运营承诺。GDPR 是否适用须按地域连接和实际活动判断（GDPR 第 3 条），不能因免费或个人项目一概排除。以下要求仅在各自法定条件满足时适用：

1. 按资料性质、规模、实施成本和实际风险采取相称措施（GDPR 第 32 条），核对传输、密钥、日志、恢复和删除，而非默认要求小型项目配置专职团队或认证。
2. 不满 250 人不自动豁免处理活动记录；处理并非偶发、可能危及个人权利和自由、涉及特殊类别或刑事定罪及犯罪资料，任一情况均可能排除该例外（GDPR 第 30 条）。
3. 数据保护官按触发条件指定，包括公共机关，以及核心活动涉及大规模定期且系统性监测，或大规模特殊类别、刑事定罪及犯罪资料处理等情形（GDPR 第 37 条）。
4. 资料保护影响评估针对处理前可能导致高风险的活动，不是每次哈希、登录或每个免费项目都自动需要（GDPR 第 35 条）。
5. 境外主体适用 GDPR 第 3 条第 2 项时，通常须指定欧盟代表。第 27 条的偶发处理例外须同时满足偶发、不包括大规模特殊类别或刑事定罪及犯罪资料处理、且结合性质、情境、范围和目的不太可能造成风险；免费或非营利本身不构成例外。
6. 核对 `SONIC_RECOMMEND_RETENTION_DAYS`、数据库路径、内存回退、第三方链路、限流和撤销开关，并以实际值写入自己的告知、期限和删除流程。
