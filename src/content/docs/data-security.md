## 1. 数据生命周期

| 阶段 | 说明 |
| --- | --- |
| 收集 | 经 Epomail OAuth 登录取得帐户识别资料（不落盘）；经播放器批量上报行为事件（可关闭，单批至多 50 条、64 KB）；匿名限流暂用 IP |
| 传输 | 全链路 HTTPS/TLS；控制面与数据面之间经 Cloudflare Tunnel 加密通道，并以服务间密钥（X-Sonic-Engine-Key）强制验证；边缘至引擎之客户端地址标头仅于引擎侧验证服务密钥后方被接受 |
| 存储 | 数据面 SQLite（WAL 模式），落于命名卷 `sonic-data` 之 `/app/data/sonic-recommend.sqlite`；生产环境打开失败时拒绝服务（fail-closed），不静默降级 |
| 利用 | 假名化标识符关联之统计计算（推荐、热度、相似度）；不为人工资核，不作内容审查，不作自动化决策 |
| 共享 | 见[第三方共享与传输清单](/sub-processors/)；不出售、不为广告利用 |
| 删除 | 行为事件 90 日自动销毁（按每 1500 次写入与启动时点触发清理）；一键清空即时删除；限流记录 120 秒过期 |

## 3. 安全维护措施

### 3.1 传输与接入

1. **全程加密**：浏览器至边缘、边缘至数据面均经 TLS；数据面经 Cloudflare Tunnel 加密通道接入，不直接暴露公网端口，宿主侧仅映射 `127.0.0.1:8080`；
2. **服务间验证**：数据面对全部 `/api`、`/proxy`、`/palette` 路由强制验证 X-Sonic-Engine-Key；引擎侧剥除不可信入站标头并以套接字地址重建客户端地址标头，伪造一律失效；
3. **降级即明示**：边缘降级模式下响应标头标明 `X-Sonic-Degraded: 1`，界面同步显示降级提示，不静默切换。

### 3.2 认证与金钥

1. **OAuth 流程**：`state` 参数与 PKCE（S256）防授权码拦截与重放；事务 Cookie 有效期 600 秒且限 `/api/auth` 路径；回调时校验 state、PKCE、授权码与重放，任何一环缺失或异常一律拒绝；
2. **API Key**：`sonic_live_v2` 版本化格式，HMAC-SHA256 签名，服务器端以 Web Crypto `crypto.subtle.verify` 常数时间比对；严格检查版本、`kid`、`iat`／`exp` 与 `jti`；无签名金钥与旧版 v1 金钥一律拒绝（fail-closed）；签发有效期 30 日、校验上限 90 日；金钥仅经请求标头传递，`?api_key=` 查询参数通道已完全移除，避免金钥泄漏至访问日志、浏览器历史或 Referer；
3. **撤销机制**：登出即时撤销当前会话；`jti` 撤销清单、主体撤销清单与全局签发时间下限（`SONIC_REVOKED_JTIS`／`SONIC_REVOKED_SUBS`／`SONIC_TOKEN_MIN_IAT`）支持批量作废；绑定 KV 并开启 `SONIC_ENABLE_KEY_REVOCATION=1` 时支持即时撤销；未配置即时撤销时相关端点返回 501 并提示改用清单方式，不假装撤销成功；
4. **会话属性**：`HttpOnly; Secure; SameSite=Lax`，有效期至多 30 日；登录回调重定向仅携带 `?auth=success` 状态参数，不回传金钥。

### 3.3 出站请求防御

1. **SSRF 拦截**：回环地址、RFC 1918 私网、Docker 内部网桥与云端中继资料地址（如 `169.254.169.254`）之出站请求一律阻断，IPv4 与 IPv6 双栈校验，每次重定向重新校验目标与 DNS 解析结果；
2. **域白名单**：音频、封面与转发代理仅允许受控音乐 CDN 域名清单（`SONIC_ALLOWED_MUSIC_DOMAINS`）内之 HTTPS 目标与标准端口；
3. **请求净化**：上游请求剥离 `Set-Cookie` 与凭证标头，仅携带固定 User-Agent、对应官网 Referer 与必要之 Range 标头；出口 IP 标示为部署者配置之占位地址（缺省 RFC 5737 文档地址），非任何用户之 IP。

### 3.4 存储与日志

1. **假名化存储**：行为事件以单向哈希标识符（`usr_`／`anon_` 前缀之 SHA-256 截断值）关联，无明文电子邮件列、无 IP 列；存储共 6 张表（曲目规范数据、平台曲目映射、全文索引、行为事件、曲目共现、搜索词聚合），其中与个人关联者仅行为事件表；
2. **fail-closed 存储**：生产环境数据库打开失败时拒绝服务而非静默降级；内存回退仅限开发测试或显式配置 `SONIC_RECOMMEND_ALLOW_MEMORY_FALLBACK=1`；
3. **日志最小化**：数据面访问日志为逐行 JSON，仅含请求标识、方法、路径、状态码与耗时；查询字符串、IP、User-Agent、Cookie、Authorization 与请求体一律不记录；未处理异常仅记录请求标识、错误名称与截断消息；日志归 Docker 标准输出，轮转策略随宿主 Docker 配置；Cloudflare Pages 侧无本专案自建之全局访问日志；
4. **备份**：数据库备份以一致性快照（VACUUM INTO）配合完整性检查执行；备份文件含假名化行为数据，应与生产数据同等级保护；
5. **容器隔离**：数据面运行于 Docker 容器堆叠，ncm-api 辅助容器仅于 compose 内部网络可达（`ncm-api:3000`），不经公网暴露；`.env` 配置文件权限要求 600。

### 3.5 已知局限

本服务为开源专案，运营者公开下列已知局限，持续改善：

1. 未绑定 Cloudflare 原生限流器之部署形态下，限流以 KV 或进程内存计数，非严格全局精确；
2. DNS rebinding 防护未完全消除，部署者应配套网络层措施；
3. `sonic_session` Cookie 内含签名 API Key，Cookie 被盗等同于金钥被盗，应配合设备安全与及时登出；
4. SQLite 为单写者架构，不适合高并发写入之部署形态；
5. 无内置 Prometheus 指标端点，监控需依赖日志与外部探活。

上述局限之完整清单见上游仓库 `docs/OPERATIONS.md`；自行部署运营者应依其部署形态评估。

## 4. 资料外泄应变

1. **内部记录**：全部个人资料外泄事件均予记录（GDPR 第 33 条第 5 项），不因评估为低风险而免于记录；
2. **通报监督机关**：外泄可能致当事人风险时，于知悉后 72 小时内向运营者所在地之主管监督机关通报，说明外泄性质、涉及资料类别与数量、可能后果与已采取之措施（GDPR 第 33 条第 1 项、第 3 项）；
3. **通知当事人**：外泄可能致当事人高风险时，以站内公告或其他有效方式无不当迟延地通知受影响之当事人，说明外泄性质与建议措施（GDPR 第 34 条）；风险已有效消除致高风险不复存在者，得免于通知，惟决定理由应记录；
4. **应变措施**：即时隔离受影响系统、撤销受影响金钥与会话（含 `jti` 清单与全局签发时间下限）、评估并修复成因、记录处置全过程。

## 5. 资料保护之设计与默认

本服务于设计阶段落实下列措施（GDPR 第 25 条）：

1. **假名化为默认**：行为事件自收集之始即以哈希标识符关联，电子邮件地址不落盘，数据库无 IP 列；
2. **零收集模式**：个性化关闭时事件不入库，公开模式于服务端直接丢弃，回执中如实标示忽略数量；
3. **最小客户端数据**：推荐上下文仅携带限条数之收藏、最近艺人与搜索词，内存使用不落盘；播放器不读写 `document.cookie`，金钥不进 localStorage；
4. **默认关闭之高风险链路**：第三方聚合上游（GDStudio、Lyriva）与解灰链路默认严格关闭，需部署者显式开启（环境变量置 1）方生效；
5. **一键清空**：删除权以自助功能直接落实，无需人工请求；「清除全部本地数据」同时清理服务端画像、localStorage、sessionStorage 与 IndexedDB。

## 6. 自行部署运营者之义务

您自行部署本服务之时点起，即为您用户之数据控制者，应履行下列义务：

1. **告知义务**：向您的用户告知资料处理事项（可以本站[隐私政策](/privacy-policy/)为基础文本）；
2. **处理活动记录**：维持处理活动记录（GDPR 第 30 条）；
3. **影响评估**：处理可能致高风险时实施资料保护影响评估（GDPR 第 35 条），评估范围至少包括：匿名设备标识、行为事件、限流 IP 之暂时使用、OAuth 电子邮件之哈希派生；
4. **配置核对**：确认下列参数与您的政策承诺一致——行为事件保留天数（`SONIC_RECOMMEND_RETENTION_DAYS`，缺省 90、下限 7）、落盘路径（`SONIC_RECOMMEND_DB_PATH`，设为 `memory` 关闭落盘）、内存回退开关（`SONIC_RECOMMEND_ALLOW_MEMORY_FALLBACK`）、第三方链路开关（`SONIC_ENABLE_GDSTUDIO` 等）、限流参数（`SONIC_RATE_LIMIT_ANON_RPM`／`SONIC_RATE_LIMIT_AUTH_RPM`）；
5. **安全维护与受监督**：依第 3 节之措施配置（含服务密钥强度不低于 32 字符、`.env` 权限 600、数据面不暴露公网），并依您所在地法律接受主管机关之检查与监督。

## 7. 可审计性

本服务之安全声明可经源码核验：全部处理逻辑、开关缺省值、存储结构与日志形态均公开于开源代码库；上游仓库另备有安全审计整改记录（`docs/AUDIT_REMEDIATION.md`）与运维手册（`docs/OPERATIONS.md`）。本站文档之技术事实随版本更新核对，发现与源码不一致时以源码为准并即时修正文档。
