本页说明 Sonic 服务（下称「本服务」）之数据生命周期、各项处理活动之性质、安全维护措施与资料外泄应变程序。本页是[隐私政策](/privacy-policy/)第 10 节之展开；技术事实以开源代码之实际实现为准。

## 1. 数据生命周期

| 阶段 | 说明 |
| --- | --- |
| 收集 | 经 Epomail OAuth 登录取得帐户识别资料；经播放器上报行为事件（可关闭）；匿名限流暂用 IP |
| 传输 | 全链路 HTTPS/TLS；控制面与数据面之间经 Cloudflare Tunnel 加密通道，并以服务间密钥（X-Sonic-Engine-Key）强制双向验证 |
| 存储 | 数据面 SQLite（WAL 模式），落于命名卷 `sonic-data`；帐户识别资料不落盘 |
| 利用 | 假名化标识符关联之统计计算（推荐、热度、相似度）；不为人工资核，不作自动化决策 |
| 共享 | 见[第三方共享与传输清单](/sub-processors/)；不出售、不为广告利用 |
| 删除 | 行为事件 90 日自动销毁；一键清空即时删除；限流记录 120 秒过期 |

## 2. 处理矩阵

| 处理活动 | 涉及资料 | 身份关联 | 法律依据 | 保存期限 |
| --- | --- | --- | --- | --- |
| 帐户识别与登录 | Epomail 标识符、电子邮件、昵称、头像链接、角色 | 电子邮件（会话内） | 契约必要 | 不落盘；会话期间 |
| 行为事件记录 | 事件类型、曲目、歌手、流派、语言、搜索词、进度、权重 | 假名化哈希（`usr_`／`anon_`） | 正当利益＋反对权 | 90 日（下限 7 日） |
| 推荐画像计算 | 行为事件之聚合特征 | 假名化哈希 | 正当利益＋反对权 | 随事件销毁 |
| 全局聚合统计 | 搜索词计数、曲目共现 | 不关联个人 | 正当利益 | 随库维护 |
| 限流与滥用防制 | IP（匿名桶）、电子邮件哈希（认证桶） | 暂时使用 | 正当利益 | 120 秒／60 秒窗口 |
| 会话与金钥安全 | 会话 Cookie、API Key 载荷、撤销清单 | 电子邮件哈希 | 契约必要、安全义务 | 至多 30 日 |

## 3. 安全维护措施

### 3.1 传输与接入

1. **全程加密**：浏览器至边缘、边缘至数据面均经 TLS；数据面仅经 Cloudflare Tunnel 加密通道接入，不直接暴露公网端口；
2. **服务间验证**：数据面所有 API、代理与调色路由强制验证 X-Sonic-Engine-Key；边缘至引擎转发之客户端地址标头仅于引擎侧验证服务密钥后方被接受；
3. **回环绑定**：数据面 HTTP 服务默认仅绑定 `127.0.0.1`，宿主侧仅映射回环端口。

### 3.2 认证与金钥

1. **OAuth 流程**：state 参数与 PKCE（S256）防授权码拦截与重放；事务 Cookie 有效期 600 秒；回调校验失败一律拒绝；
2. **API Key**：`sonic_live_v2` 版本化格式，HMAC-SHA256 签名，服务器端常数时间比对；无签名金钥与旧版金钥一律拒绝（fail-closed）；金钥仅经请求标头传递，永不接受 URL 查询参数；
3. **撤销机制**：登出即时撤销当前会话；金钥识别码（jti）撤销清单与全域签发时间下限支持批量作废；
4. **会话属性**：`HttpOnly; Secure; SameSite=Lax`，有效期至多 30 日。

### 3.3 出站请求防御

1. **SSRF 拦截**：回环地址、RFC 1918 私网、Docker 内部网桥与云端中继资料地址（如 `169.254.169.254`）之出站请求一律阻断，IPv4 与 IPv6 双栈校验，每次重定向重新校验目标与解析结果；
2. **域白名单**：音频、封面与转发代理仅允许受控音乐 CDN 域名清单内之 HTTPS 目标；
3. **请求净化**：上游请求剥离 Set-Cookie 与凭证标头，仅携带固定 User-Agent、对应官网 Referer 与必要之 Range 标头。

### 3.4 存储与日志

1. **假名化存储**：行为事件以单向哈希标识符关联，无明文电子邮件列、无 IP 列；
2. **日志最小化**：数据面访问日志仅含路径、方法、状态码与耗时；查询字符串、IP、User-Agent、Cookie、Authorization 与请求体一律不记录；
3. **备份**：数据库备份以一致性快照（VACUUM INTO）配合完整性检查执行，备份文件含假名化行为数据，应与生产数据同等级保护；
4. **容器隔离**：数据面运行于 Docker 容器堆叠，ncm-api 辅助容器仅于内部网络可达。

### 3.5 已知局限

本服务为开源专案，运营者公开下列已知局限，持续改善：

1. 未绑定原生限流器之部署形态下，限流非严格全局计数；
2. DNS rebinding 防护未完全消除，部署者应配套网络层措施；
3. 会话 Cookie 内含签名 API Key，Cookie 被盗等同于金钥被盗；
4. SQLite 为单写者架构，不适合高并发写入之部署形态。

上述局限之完整清单见上游仓库 `docs/OPERATIONS.md`；自行部署运营者应依其部署形态评估。

## 4. 资料外泄应变

1. **内部记录**：全部个人资料外泄事件均予记录（GDPR 第 33 条第 5 项）；
2. **通报监督机关**：外泄可能致当事人风险时，于知悉后 72 小时内向运营者所在地之主管监督机关通报（GDPR 第 33 条第 1 项）；
3. **通知当事人**：外泄可能致当事人高风险时，以站内公告或其他有效方式无不当迟延地通知受影响之当事人，说明外泄性质与建议措施（GDPR 第 34 条）；
4. **应变措施**：即时隔离受影响系统、撤销受影响金钥与会话、评估并修复成因、记录处置过程。

## 5. 资料保护之设计与默认

本服务于设计阶段落实下列措施（GDPR 第 25 条）：

1. **假名化为默认**：行为事件自收集之始即以哈希标识符关联，电子邮件地址不落盘；
2. **零收集模式**：个性化关闭时事件不入库，公开模式直接丢弃；
3. **最小客户端数据**：推荐上下文仅携带限条数之收藏、艺人与搜索词，内存使用不落盘；
4. **默认关闭之高风险链路**：第三方聚合上游（GDStudio、Lyriva）与解灰链路默认严格关闭，需部署者显式开启；
5. **一键清空**：删除权以自助功能直接落实，无需人工请求。

## 6. 自行部署运营者之义务

您自行部署本服务之时点起，即为您用户之数据控制者，应履行下列义务：

1. **告知义务**：向您的用户告知资料处理事项（可以本站[隐私政策](/privacy-policy/)为基础文本）；
2. **处理活动记录**：维持处理活动记录（GDPR 第 30 条）；
3. **影响评估**：处理可能致高风险时实施资料保护影响评估（GDPR 第 35 条），评估范围包括匿名设备标识、行为事件、限流 IP 与 OAuth 电子邮件；
4. **配置核对**：确认行为事件保留天数（`SONIC_RECOMMEND_RETENTION_DAYS`）、落盘路径（`SONIC_RECOMMEND_DB_PATH`，设为 `memory` 可关闭落盘）、第三方开关与限流参数符合您的政策承诺；
5. **安全维护**：依第 3 节之措施配置，并依您所在地法律接受主管机关之监督。
