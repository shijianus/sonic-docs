**発効日：2026年11月2日｜バージョン：1.5**

Sonic のアカウントの仕組みと、安全に利用するためのポイントを説明します。技術的な実装の全体像は[データ処理とセキュリティ](/ja/data-security/)第3.2節、契約上のルールは[利用規約](/ja/terms-of-service/)第3節を参照してください。

## 1. ログイン方法

本サービスは Epomail アカウントによる OAuth 2.0（PKCE）でログインし、独立した登録システムは設けていません。手順は、サイドバーのアカウント入口を選ぶ → Epomail の認可ページで確認する → 本サービスに戻る、です。認可コールバックは state、PKCE、認可コード、再送の4段階で検証されます。認証エンドポイントには IP ごとに毎分30回の制限があります。

## 2. セッションの仕組み

1. **セッション Cookie**：ログインに成功すると、`HttpOnly; Secure; SameSite=Lax` のセッション Cookie が発行され、最長30日有効です。Cookie には署名済み API キーが含まれ、スクリプトから読み取ることはできません；
2. **タブ間の同期**：同じブラウザのタブ間ではログイン状態が自動的に共有されます。いずれかのタブでログアウトすると、ほかのタブにも反映されます；
3. **キーの保存範囲**：API キーを URL、クエリパラメータ、localStorage に保存することはありません。OAuth の取引 Cookie の有効期間は600秒だけです。

## 3. API キーの管理

API キーは本人だけが使う認証情報です（形式 `sonic_live_v2.…`、HMAC-SHA256 署名）。

1. リクエストヘッダーでのみ送信し、URL に含めません；
2. 第三者に渡したり、公開するクライアントへ埋め込んだりしないでください；
3. 再発行には現在有効なキーが必要です。漏えいした可能性がある場合は直ちにログアウトし、取消しを依頼してください（第4節参照）。

## 4. 取消しとログアウト

| 操作 | 場所 | 効果 |
| --- | --- | --- |
| ログアウト | プレイヤー内 | 現在のセッションとキー識別子（jti）を直ちに無効化 |
| キーの取消し | `POST /api/auth/revoke` | 現在の API キーを無効化 |
| 一括無効化 | 展開者の設定 | jti リスト、主体リスト、発行時刻の全体的な下限を設定 |

## 5. 安全に利用するためのヒント

1. 共有端末では利用後に必ずログアウトしてください。セッション Cookie には署名済みのキーが含まれます；
2. Epomail 側の設定で2段階認証を有効にすることをおすすめします；
3. アカウントを貸したり共有したりしないでください。共有されたアカウントのデータは区別・復元できません；
4. 見覚えのない再生履歴や不明なセッションに気付いたら、直ちにログアウトして `admin@epocanvas.com` へ連絡してください；
5. 本サービスはパスワードを収集しません。ログインは Epomail で行われるため、「Sonic のパスワード確認」を求める連絡はなりすましです。

## 6. アカウント管理の入口

サイドバー下部のアカウント入口にはログイン状態が表示されます。ログアウト中はログイン案内、ログイン後はアカウント名と、Epomail のプロフィール・受信トレイへ移動するアカウント管理リンクが表示されます。ログイン状態は同じブラウザのタブ間で自動的に共有されます。
