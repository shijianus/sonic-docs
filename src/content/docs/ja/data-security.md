## 3. 安全管理措置

### 3.1 通信とアクセス

1. 公開入口は HTTPS、OAuth、署名付きセッション、サービス間キーを設定できますが、コード上の制御だけで実際の入口、プロキシ、上流すべての TLS 使用は証明できません。
2. 制御プレーンとデータプレーンが暗号化トンネルを通るか、データプレーンをループバックだけにバインドするかはホスティング設定によります。内部の平文 HTTP 経路だけでも「全経路暗号化」という包括的な表現は否定されます。
3. プロキシの宛先検証とドメイン制限は、実際にプロキシを通る要求だけに及びます。監査では生 IP が Cookie、認証ヘッダー、コンテキストとともにエンジンへ転送され得るため、エンジンが仮名データだけを受け取るとは言えません。
4. 音声ストリームの要求は固定値ではなくブラウザの User-Agent を使う場合があります。MV、カバー、Google Fonts、アバターへのブラウザ直接接続では、各サービスに IP と接続メタデータが見える場合があります。

### 3.2 認証とキー

1. 確認した RC は OAuth state と PKCE を使い、署名付きセッションは既定30日です。実際の Cookie 属性と期間は展開での検証が必要です。署名は完全性のためで暗号化ではなく、ペイロードはメール、ユーザー・ロール識別子を含み得ます。
2. API Key のバージョン、署名、時刻、`jti` の検証に失敗した要求は拒否すべきです。名称、環境変数、設計コメントを完全な認証制御の証明としてはなりません。
3. ログアウトや一括失効が即時に有効になるかは、失効ストレージ、スイッチ、要求成功に依存します。未有効・未検証の場合、複製された全認証情報の即時失効は保証できません。

### 3.3 送信要求の防御

コードには一部の SSRF、内部ネットワーク、リダイレクトの検証と音楽ドメイン許可リストがありますが、上流や第三者へのすべてのブラウザ要求がプロキシ化、無害化、匿名化される意味ではありません。DiceBear には平文メールアドレスを seed に使うアバター URL 経路があります。Google Fonts、MV、カバーへの直接接続は各サービスに IP を伝え得ます。一部提供者は HTTP を使用し、全経路 TLS とは言えません。

### 3.4 保存とログ

1. ブラウザの `auth`、`audio`、`library`、`global`、`settings`、`recommend` と IndexedDB は機能ごとにデータを保持し、ログアウトしても全端末データが自動消去されるわけではありません。
2. サーバーの行動データを仮名識別子で関連付けても、他の情報と組み合わせて識別され得ます。仮名化は匿名化ではなく、検索、レーダー、第三者データを網羅するものでもありません。
3. アプリ、Cloudflare、ホスト、上流のログとバックアップの実際のローテーション、アクセス権、期限後破棄は、今回の確認で一律に検証していません。架空のバックアップ期間や「ゼロログ」を記載してはなりません。
4. 任意の Meilisearch は検索原文やカタログを処理し得ます。Gorse の削除がローカル削除と同期するかは未確認です。ローカルリセットの成功は、外部推薦・検索ストレージへの対応に代わりません。

### 3.5 既知の制約

1. パーソナライズと Auto DJ は既定 ON で、事前・独立・撤回可能と証明できる選択が不足しています。これは同意ではありません。
2. 公開検索候補は検索原文を再利用し、個人情報や機微情報を露出させるおそれがあります。
3. 削除は主に現在の識別子の一部イベントで、共有曲目カタログとカバー、レーダー、バックアップ、ログ、外部サービス、Meilisearch、Gorse、旧匿名識別子までの対象範囲は未確認です。レーダーの耐久的なエンジン経路も未確認で、保存状態を断定しません。
4. 内部の平文 HTTP、Google Fonts、MV・カバー直接要求、ブラウザ User-Agent、DiceBear の平文メール URL により、「全経路 TLS」「メールは外部に出ない」という表現は不正確です。
5. レート制限、失効、ログ、第三者スイッチはインスタンスの環境変数と提供者設定によります。GDStudio はコード上で未設定なら ON、環境や Compose では OFF にでき、一覧だけで既定 OFF と言えません。

## 4. データ侵害への対応

GDPR 適用時、安全措置はデータの性質、規模、実施費用、実際のリスクに相応すべきです（GDPR 第32条）。運営者はすべての侵害を記録し、個人の権利と自由にリスクが生じる可能性が低い場合を除き、不当な遅滞なく、可能なら認識後72時間以内に管轄監督機関へ通知し、遅れた場合は理由を説明する必要があります（GDPR 第33条）。高リスクでは法定例外を除き本人にも不当な遅滞なく通知します（GDPR 第34条）。特定国の機関への自動報告の約束ではなく、その他の適用法を免除するものでもありません。

実際の対応では、影響システムの隔離、認証情報の保護・失効、データ種類、範囲、受領者、時系列の確認と、判断・是正の記録を行うべきです。疑われる事案は `privacy@epocanvas.com` に報告できます。パスワード、完全なトークン、会員 Cookie、不要な個人データを送らないでください。

## 5. 設計と既定によるデータ保護

GDPR 第25条は処理手段を決める際に設計・既定による保護を考慮するよう求めます。本プロジェクトは現在、以下を完全実装済みとは主張できません。

1. 任意のプロファイリングは既定 OFF とし、同程度に容易な受諾、拒否、撤回、記録を提供すべきです。現在のコードは既定 ON で、ログインや継続利用は同意の代わりになりません。
2. 公開検索候補はまず無効化するか、最小表示、フィルタ、閾値、期間、削除管理を実装すべきです。
3. アバター seed に平文メールを使うべきではありません。Google Fonts、MV、カバー等の直接リソースは、IP、Cookie、識別子の移転を評価してから有効化すべきです。
4. 削除は関連付け可能な旧仮名識別子、レーダー、検索、共有曲目カタログ、ログ、外部サービス、Meilisearch、Gorse、バックアップを、適用される法的範囲で確認すべきです。受領者には法律上必要な場合に通知し、法定保存例外を説明します。現在の識別子の部分消去を完全削除と偽ってはなりません。

## 6. 自己展開運営者の義務

自己展開インスタンスは独立して運営されます。本ページの確認事項は実際の法律・ライセンスを超える契約義務を展開者に生じさせず、作者の運営上の約束でもありません。GDPR の適用は地域的接点と実際の活動で判断し（GDPR 第3条）、無料や個人プロジェクトを理由に一律除外できません。以下は、それぞれの法定条件を満たす場合のみ適用されます。

1. データの性質、規模、実施費用、実際のリスクに相応する措置（GDPR 第32条）を取り、通信、キー、ログ、復元、削除を確認します。小規模プロジェクトに専任チームや認証を一律に求めるものではありません。
2. 250人未満でも処理活動記録が自動免除されるわけではありません。非偶発的処理、権利・自由へのリスク、特別なカテゴリー、刑事有罪判決・犯罪データのいずれかがあれば、例外から外れ得ます（GDPR 第30条）。
3. データ保護責任者は、公共機関、主要活動が大規模な定期的・体系的監視、特別なカテゴリーや刑事有罪判決・犯罪データの大規模処理などの条件に応じて選任します（GDPR 第37条）。
4. データ保護影響評価は、高リスクを生じ得る活動の処理前に行うもので、すべてのハッシュ、ログイン、無料プロジェクトに自動的に必要なわけではありません（GDPR 第35条）。
5. 域外の主体に GDPR 第3条第2項が適用される場合、通常は EU 代理人の選任が必要です。第27条の偶発的処理の例外には、偶発的であること、特別なカテゴリーや刑事有罪判決・犯罪データの大規模処理を含まないこと、性質・状況・範囲・目的に照らしリスクが生じる可能性が低いことを同時に満たす必要があります。無料・非営利だけでは例外になりません。
6. `SONIC_RECOMMEND_RETENTION_DAYS`、DB パス、メモリフォールバック、第三者経路、レート制限・失効のスイッチを確認し、実際の値を自らの告知、期限、削除手順に反映してください。
