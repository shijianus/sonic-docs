本ページは、Sonic サービス（以下「本サービス」）のデータライフサイクル、各処理活動の性質、安全措置、既知の制約、データ漏洩対応手続きを説明します。本ページは[プライバシーポリシー](/ja/privacy-policy/)第10節の展開であり、技術的事実はオープンソースコードの実際の実装に従い、ソース監査により検証できます。

## 1. データライフサイクル

| 段階 | 説明 |
| --- | --- |
| 収集 | Epomail OAuth ログインによるアカウント識別データ（ディスク保存なし）。プレイヤーがバッチ送信する行動イベント（無効化可能、1 バッチ最大 50 件／64 KB）。匿名レート制限のための IP の一時利用 |
| 伝送 | 全経路 HTTPS/TLS。制御プレーンとデータプレーンの間は Cloudflare Tunnel 暗号化チャネルで、X-Sonic-Engine-Key 検証を強制。エッジからエンジンへ転送されるクライアントアドレスヘッダーは、エンジン側でサービス鍵の検証を経た後にのみ受理 |
| 保管 | データプレーンの SQLite（WAL モード）、命名ボリューム `sonic-data` の `/app/data/sonic-recommend.sqlite` に保存。本番環境でデータベースを開けない場合はサービスを拒否し（fail-closed）、静かに降格しません |
| 利用 | 偽名化識別子で紐付けた統計計算（レコメンド・ヒートチャート・類似度）。人間による内容審査なし、自動化意思決定なし |
| 共有 | [第三者提供と国際伝送](/ja/sub-processors/)参照。販売せず、広告利用なし |
| 消去 | 行動イベントは 90 日で自動消去（1,500 書き込みごとと起動時に清理を発動）。ワンクリック消去は即時削除。レート制限記録は 120 秒で失効 |

## 3. 安全措置

### 3.1 伝送と接続

1. **全経路暗号化**：ブラウザからエッジまで、エッジからデータプレーンまで TLS。データプレーンは Cloudflare Tunnel 暗号化チャネル経由でのみ到達可能で、公開ポートはなくホスト側は `127.0.0.1:8080` のみマッピングします；
2. **サービス間検証**：データプレーンは全 `/api`・`/proxy`・`/palette` ルートで X-Sonic-Engine-Key の検証を強制します。エンジン側は信頼できない入力ヘッダーを剥離し、ソケットアドレスからクライアントアドレスヘッダーを再構築するため、偽造は無効です；
3. **降格は明示**：エッジ降格モードの応答には `X-Sonic-Degraded: 1` を標示し、画面にも降格表示を表示します。黙って切替えることはありません。

### 3.2 認証と鍵

1. **OAuth フロー**：`state` パラメータと PKCE（S256）が認可コードの横取り・再生攻撃を防ぎます。トランザクション Cookie は 600 秒有効で `/api/auth` パス限定。コールバック時は state・PKCE・認可コード・再生の四点を検証し、一つでも欠落や異常があれば一律拒否します；
2. **API キー**：`sonic_live_v2` バージョン付き形式、HMAC-SHA256 署名、サーバー側は Web Crypto `crypto.subtle.verify` による定数時間比較。バージョン・`kid`・`iat`／`exp`・`jti` を厳格に検査します。無署名鍵と旧版 v1 鍵は一律拒否（fail-closed）。発行有効期間 30 日、検証上限 90 日。鍵はリクエストヘッダーのみで伝送され、`?api_key=` クエリ経路は完全に廃止済みです。アクセスログ・ブラウザ履歴・Referer への鍵漏洩を防止します；
3. **取消メカニズム**：ログアウトは現在のセッションを即時取消します。`jti` 取消リスト・主体取消リスト・グローバル発行時間下限（`SONIC_REVOKED_JTIS`／`SONIC_REVOKED_SUBS`／`SONIC_TOKEN_MIN_IAT`）が一括無効化に対応します。KV バインドと `SONIC_ENABLE_KEY_REVOCATION=1` により即時取消に対応します。未設定の場合、当該エンドポイントは 501 を返しリスト方式を案内します。取消成功を偽装しません；
4. **セッション属性**：`HttpOnly; Secure; SameSite=Lax`、最長 30 日有効。ログインコールバックのリダイレクトは `?auth=success` 状態パラメータのみを運び、鍵を返しません。

### 3.3 外向きリクエストの防御

1. **SSRF 遮断**：ループバックアドレス、RFC 1918 私設網、Docker 内部ブリッジ、クラウドメタデータアドレス（`169.254.169.254` など）への外向きリクエストは一律遮断します。IPv4・IPv6 両スタックで検証し、リダイレクトのたびに目標とその解決結果を再検証します；
2. **ドメイン許可リスト**：音声・カバー・転送プロキシは、管理された音楽 CDN ドメインリスト（`SONIC_ALLOWED_MUSIC_DOMAINS`）内の HTTPS 目標と標準ポートのみを許可します；
3. **リクエスト浄化**：上流リクエストは `Set-Cookie` と認証ヘッダーを剥離し、固定 User-Agent、対応公式サイトの Referer、必要な Range ヘッダーのみを運びます。出口 IP は展開者が設定したプレースホルダーアドレス（既定は RFC 5737 文書アドレス）であり、いかなる利用者の IP でもありません。

### 3.4 保管とログ

1. **偽名化保管**：行動イベントは一方向ハッシュ識別子（`usr_`／`anon_` 接頭辞の SHA-256 切詰め値）で紐付けます。平文の電子メール列はなく、IP 列もありません。ストレージは 6 テーブル（トラック規範データ、プラットフォームトラック対応、全文インデックス、行動イベント、トラック共起、検索語集計）で構成され、個人と紐付くのは行動イベントテーブルのみです；
2. **fail-closed 保管**：本番環境でデータベースを開けない場合は静かに降格せずサービスを拒否します。メモリへのフォールバックは開発テストまたは明示的な `SONIC_RECOMMEND_ALLOW_MEMORY_FALLBACK=1` の場合に限られます；
3. **ログの最小化**：データプレーンのアクセスログは行区切り JSON で、リクエスト識別・メソッド・パス・ステータスコード・所要時間のみを含みます。クエリ文字列、IP、User-Agent、Cookie、Authorization、リクエストボディは記録しません。未処理の異常はリクエスト識別・エラー名・切詰めメッセージのみを記録します。ログは Docker 標準出力に帰属し、輪転方針はホストの Docker 設定に従います。Cloudflare Pages 側に本プロジェクト自前のグローバルアクセスログはありません；
4. **バックアップ**：データベースのバックアップは一致性スナップショット（VACUUM INTO）と整合性検査で実行します。バックアップファイルは偽名化行動データを含むため、本番データと同等の保護が必要です；
5. **コンテナ分離**：データプレーンは Docker コンテナスタックで動作し、ncm-api 補助コンテナは compose 内部ネットワークからのみ到達可能（`ncm-api:3000`）で公開されません。`.env` 設定ファイルの権限は 600 が要求されます。

### 3.5 既知の制約

本サービスはオープンソースプロジェクトとして、次の既知の制約を公開し、継続的に改善します。

1. Cloudflare ネイティブレート制限器をバインドしない展開形態では、KV またはプロセスメモリで計数するため厳格な全体計数ではありません；
2. DNS rebinding 対策は完全には消除されておらず、展開者はネットワーク層の措置を併用すべきです；
3. `sonic_session` Cookie は署名済み API キーを含みます。Cookie の盗難は鍵の盗難と同等であり、デバイスの安全と適時のログアウトを併用すべきです；
4. SQLite は単一書き込み者アーキテクチャであり、高並行書き込みの展開形態には適しません；
5. 内蔵の Prometheus メトリクスエンドポイントはなく、監視はログと外部探活に依存します。

制約の完全なリストは上流リポジトリの `docs/OPERATIONS.md` にあります。自己ホスト運営者は自らの展開形態に応じて評価してください。

## 4. データ漏洩対応

1. **内部記録**：すべての個人データ漏洩事象を記録します（GDPR 第33条第5項）。低リスク評価でも記録は免除されません；
2. **監督機関への通報**：本人へのリスクが生じ得る漏洩は、知悉後 72 時間以内に運営者所在地の監督機関へ通報し、漏洩の性質、対象データの区分と概数、考えられる結果、講じた措置を説明します（GDPR 第33条第1項・第3項）；
3. **本人への通知**：本人への高リスクが生じ得る漏洩は、サイト内公告その他の有効な方式で、不当な遅延なく影響を受ける本人に通知し、漏洩の性質と推奨措置を説明します（GDPR 第34条）。高リスクが実効的に解消された場合は通知を省略でき、決定理由は記録します；
4. **対応措置**：影響を受けたシステムの即時隔離、影響を受けた鍵とセッションの取消（`jti` リストとグローバル発行時間下限による）、原因の評価・修復、対応過程の記録。

## 5. 設計と既定によるデータ保護

本サービスは設計段階で次の措置を実装します（GDPR 第25条）。

1. **偽名化が既定**：行動イベントは収集の時点からハッシュ識別子で紐付け、電子メールアドレスはディスクに保存せず、データベースに IP 列はありません；
2. **ゼロ収集モード**：パーソナライズ無効時、イベントは保存されず、公開モードではサーバー側で直接廃棄し、無視した件数を応答に正直に標示します；
3. **最小クライアントデータ**：レコメンドコンテキストは条数制限付きのお気に入り・最近のアーティスト・検索語のみを運び、メモリ内で使用しディスクに書き込みません。プレイヤーは `document.cookie` を読み書きせず、鍵が localStorage に入ることはありません；
4. **高リスク経路の既定無効**：第三者アグリゲーション上流（GDStudio・Lyriva）と解灰経路は既定で厳格に無効で、展開者の明示的操作（環境変数を 1 に設定）が必要です；
5. **ワンクリック消去**：消去権を自助機能として直接実装し、人的請求を要しません。「全ローカルデータの消去」はサーバー側プロファイル・localStorage・sessionStorage・IndexedDB を同時に清理します。

## 6. 自己ホスト運営者の義務

あなたが本サービスを自己展開した時点から、あなたはその利用者のデータ管理者であり、次の義務を負います。

1. **告知義務**：あなたの利用者にデータ処理事項を告知します（本サイトの[プライバシーポリシー](/ja/privacy-policy/)を基礎テキストにできます）；
2. **処理活動記録**：処理活動の記録を維持します（GDPR 第30条）；
3. **影響評価**：処理が高リスクを生じ得る場合はデータ保護影響評価を実施します（GDPR 第35条）。評価範囲には少なくとも匿名デバイス識別子、行動イベント、レート制限 IP の一時利用、OAuth 電子メールのハッシュ派生が含まれます；
4. **設定の照合**：次のパラメータがあなたのポリシー約束と一致することを確認します。行動イベントの保存日数（`SONIC_RECOMMEND_RETENTION_DAYS`、既定 90、下限 7）、保存パス（`SONIC_RECOMMEND_DB_PATH`。`memory` に設定するとディスク保存を無効化）、メモリフォールバックスイッチ（`SONIC_RECOMMEND_ALLOW_MEMORY_FALLBACK`）、第三者スイッチ（`SONIC_ENABLE_GDSTUDIO` など）、レート制限パラメータ（`SONIC_RATE_LIMIT_ANON_RPM`／`SONIC_RATE_LIMIT_AUTH_RPM`）；
5. **安全措置と監督への服従**：第3節の措置に従って設定し（サービス鍵は 32 文字以上、`.env` の権限 600、データプレーンの公開露出なし）、あなたの所在地の法律の要求に従い主管機関の検査と監督を受けます。
