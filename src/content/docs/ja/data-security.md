本ページは、Sonic サービス（以下「本サービス」）のデータライフサイクル、各処理活動の性質、安全措置、データ漏洩対応手続きを説明します。本ページは[プライバシーポリシー](/ja/privacy-policy/)第10節の展開であり、技術的事実はオープンソースコードの実際の実装に従います。

## 1. データライフサイクル

| 段階 | 説明 |
| --- | --- |
| 収集 | Epomail OAuth ログインによるアカウント識別データ。プレイヤーが送信する行動イベント（無効化可能）。匿名レート制限のための IP の一時利用 |
| 伝送 | 全経路 HTTPS/TLS。制御プレーンとデータプレーンの間は Cloudflare Tunnel 暗号化チャネルで、サービス間鍵（X-Sonic-Engine-Key）による双方向検証を強制 |
| 保管 | データプレーンの SQLite（WAL モード）、命名ボリューム `sonic-data` に保存。アカウント識別データはディスクに書き込まない |
| 利用 | 偽名化識別子で紐付けた統計計算（レコメンド・ヒートチャート・類似度）。人間による内容審査なし、自動化意思決定なし |
| 共有 | [第三者提供と国際伝送](/ja/sub-processors/)参照。販売せず、広告利用なし |
| 消去 | 行動イベントは 90 日で自動消去。ワンクリック消去は即時削除。レート制限記録は 120 秒で失効 |

## 3. 安全措置

### 3.1 伝送と接続

1. **全経路暗号化**：ブラウザからエッジまで、エッジからデータプレーンまで TLS。データプレーンは Cloudflare Tunnel 暗号化チャネル経由でのみ到達可能で、公開ポートを露出しません；
2. **サービス間検証**：データプレーンの全 API・プロキシ・パレットルートは X-Sonic-Engine-Key の検証を強制します。エッジからエンジンへ転送されるクライアントアドレスヘッダーは、エンジン側でサービス鍵の検証を経た後にのみ受理されます；
3. **ループバックバインド**：データプレーンの HTTP サービスは既定で `127.0.0.1` のみにバインドし、ホスト側はループバックポートのみをマッピングします。

### 3.2 認証と鍵

1. **OAuth フロー**：state パラメータと PKCE（S256）が認可コードの横取り・再生攻撃を防ぎます。トランザクション Cookie は 600 秒有効で、コールバック検証の失敗は一律に拒否します；
2. **API キー**：`sonic_live_v2` バージョン付き形式、HMAC-SHA256 署名、サーバー側で定数時間比較。無署名鍵と旧版鍵は一律に拒否します（fail-closed）。鍵はリクエストヘッダーのみで伝送し、URL クエリパラメータは一切受け付けません；
3. **取消メカニズム**：ログアウトは現在のセッションを即時取消します。鍵識別子（jti）取消リストと全局発行時間下限により一括無効化を支援します；
4. **セッション属性**：`HttpOnly; Secure; SameSite=Lax`、最長 30 日有効。

### 3.3 外向きリクエストの防御

1. **SSRF 遮断**：ループバックアドレス、RFC 1918 私設網、Docker 内部ブリッジ、クラウドメタデータアドレス（`169.254.169.254` など）への外向きリクエストは一律に遮断します。IPv4・IPv6 両スタックで検証し、リダイレクトのたびに目標とその解決結果を再検証します；
2. **ドメイン許可リスト**：音声・カバー・転送プロキシは、管理された音楽 CDN ドメインリスト内の HTTPS 目標のみを許可します；
3. **リクエスト浄化**：上流リクエストは Set-Cookie と認証ヘッダーを剥離し、固定 User-Agent、対応公式サイトの Referer、必要な Range ヘッダーのみを運びます。

### 3.4 保管とログ

1. **偽名化保管**：行動イベントは一方向ハッシュ識別子で紐付けます。平文の電子メール列はなく、IP 列もありません；
2. **ログの最小化**：データプレーンのアクセスログはパス・メソッド・ステータスコード・所要時間のみを含みます。クエリ文字列、IP、User-Agent、Cookie、Authorization、リクエストボディは記録しません；
3. **バックアップ**：データベースのバックアップは一致性スナップショット（VACUUM INTO）と整合性検査で実行します。バックアップファイルは偽名化行動データを含むため、本番データと同等の保護が必要です；
4. **コンテナ分離**：データプレーンは Docker コンテナスタックで動作し、ncm-api 補助コンテナは内部ネットワークからのみ到達可能です。

### 3.5 既知の局限

本サービスはオープンソースプロジェクトとして、次の既知の局限を公開し、継続的に改善します。

1. ネイティブレート制限器をバインドしない展開形態では、レート制限は厳格な全局計数ではありません；
2. DNS rebinding 対策は完全には消除されておらず、展開者はネットワーク層の措置を併用すべきです；
3. セッション Cookie は署名済み API キーを含みます。Cookie の盗難は鍵の盗難と同等です；
4. SQLite は単一書き込み者アーキテクチャであり、高並行書き込みの展開形態には適しません。

局限の完全なリストは上流リポジトリの `docs/OPERATIONS.md` にあります。自己ホスト運営者は自らの展開形態に応じて評価してください。

## 4. データ漏洩対応

1. **内部記録**：すべての個人データ漏洩事象を記録します（GDPR 第33条第5項）；
2. **監督機関への通報**：本人へのリスクが生じ得る漏洩は、知悉後 72 時間以内に運営者所在地の監督機関へ通報します（GDPR 第33条第1項）；
3. **本人への通知**：本人への高リスクが生じ得る漏洩は、サイト内公告その他の有効な方式で、不当な遅延なく影響を受ける本人に通知し、漏洩の性質と推奨措置を説明します（GDPR 第34条）；
4. **対応措置**：影響を受けたシステムの即時隔離、影響を受けた鍵とセッションの取消、原因の評価・修復、対応過程の記録。

## 5. 設計と既定によるデータ保護

本サービスは設計段階で次の措置を実装します（GDPR 第25条）。

1. **偽名化が既定**：行動イベントは収集の時点からハッシュ識別子で紐付け、電子メールアドレスはディスクに保存しません；
2. **ゼロ収集モード**：パーソナライズ無効時、イベントは保存されず、公開モードでは直接廃棄されます；
3. **最小クライアントデータ**：レコメンドコンテキストは条数制限付きのお気に入り・アーティスト・検索語のみを運び、メモリ内で使用しディスクに書き込みません；
4. **高リスク経路の既定無効**：第三者アグリゲーション上流（GDStudio・Lyriva）と解灰経路は既定で厳格に無効で、展開者の明示的操作が必要です；
5. **ワンクリック消去**：消去権を自助機能として直接実装し、人的請求を要しません。

## 6. 自己ホスト運営者の義務

あなたが本サービスを自己展開した時点から、あなたはその利用者のデータ管理者であり、次の義務を負います。

1. **告知義務**：あなたの利用者にデータ処理事項を告知します（本サイトの[プライバシーポリシー](/ja/privacy-policy/)を基礎テキストにできます）；
2. **処理活動記録**：処理活動の記録を維持します（GDPR 第30条）；
3. **影響評価**：処理が高リスクを生じ得る場合はデータ保護影響評価を実施します（GDPR 第35条）。評価範囲には匿名デバイス識別子、行動イベント、レート制限 IP、OAuth 電子メールが含まれます；
4. **設定の照合**：行動イベントの保存日数（`SONIC_RECOMMEND_RETENTION_DAYS`）、保存パス（`SONIC_RECOMMEND_DB_PATH`。`memory` に設定するとディスク保存を無効化）、第三者スイッチ、レート制限パラメータがあなたのポリシー約束と一致することを確認します；
5. **安全措置と監督への服従**：第3節の措置に従って設定し、あなたの所在地の法律の要求に従い監督機関の監督を受けます。
