## 4. コード上の処理とバージョン間の差異

### 4.1 ログインとセッション

候補版 `a75f5cb` の Epomail OAuth は、state の検証と PKCE を使用します。`sonic_session` は HttpOnly の署名付きセッション Cookie で、既定の有効期間は30日です。`sonic_oauth_state` と `sonic_oauth_verifier` のトランザクション Cookie は約600秒で、HTTPS 環境では Secure が設定されます。署名は完全性を保護するもので、暗号化ではありません。認証情報のペイロードには、メールアドレス、ユーザー識別子、ロール識別子が含まれる場合があります。これらのソースコードの既定値は、オンライン環境の期間を証明するものではありません。

フロントエンドの `auth` ローカルストレージには、メールアドレスやアバターを含む一部のユーザーデータが保持され、旧ログインストレージを読み取る互換処理の経路もあります。アカウント情報はメモリ上だけにあるとはいえません。ログアウトは現在の Cookie を消去しますが、複製またはエクスポートされた認証情報が直ちに失効するかどうかは、失効情報用ストレージ、設定、リクエスト結果に依存します。ログアウトと、すべての複製の即時失効を同一視することはできません。

旧 `main@ce443c8` のコールバックと互換フロントエンドには、URL と localStorage を介してログイン情報や認証情報を受け渡し、保存する経路があり、上記の PKCE、署名検証、失効処理の保護が十分には備わっていません。旧版の README の記載を、実装済みである証拠として扱ってはなりません。必要な保護が未整備のデプロイ環境では、実際のユーザーの認証情報を処理すべきではありません。URL、スクリーンショット、ログに認証情報が含まれている場合は転送せず、運営者に対応を依頼してください。
### 4.2 行動イベント、プロファイリング、検索統計

以下の行動イベント、SQLite のプロファイル、検索統計の経路は、候補版で確認できます。旧 `main` には同じ完全な実装が見当たらず、これらの機能が既にあると推定することはできません。

候補版は、メールアドレスから派生した識別子、またはブラウザが生成した `anon_` 識別子でイベントを関連付け、再生、お気に入り、拒否などの行動と、アーティスト、アルバム、プレイリスト、MV へのフィードバックを処理します。推薦リクエストには、ローカルのお気に入り、最近のアーティスト、検索コンテキストも含まれる場合があります。未ログインは匿名という意味ではありません。ハッシュやランダム識別子は関連付けに利用できるため、仮名化された個人データとして扱う必要があり、「不可逆」であることを理由に GDPR の適用を排除することはできません。

スマート検索は検索語を別途集計し、公開の検索候補にその検索語が表示される場合があります。パーソナライズを無効にするだけでは、この経路は停止しません。検索には氏名、連絡先、機微な情報が含まれる可能性があり、回数の集計だけで匿名になるわけではありません。必要性、適法な根拠、フィルタリング、表示のしきい値、保存と削除の管理が整うまでは、ユーザーの検索から公開の検索候補を生成する経路を無効にする必要があります。

### 4.3 ブラウザストレージとローカルファイル

| ストレージ | 主な内容 | 消去と限界 |
| --- | --- | --- |
| localStorage の `audio`、`library`、`global`、`settings` | キュー、お気に入り、プレイリスト、再生／検索履歴、設定 | ユーザーまたはブラウザが消去するまで保持。汎用のクラウドバックアップではありません |
| 候補版の `recommend`、`auth`、レーダーおよび旧ログイン互換ストレージ | スイッチ、識別子、拒否記録、ユーザーデータ、レーダーと旧ログインの状態 | 一部はネットワークリクエストに使用。どのログアウト操作でも旧キーが消去されるとは限りません |
| IndexedDB `SonicMusicPlayerDB` | 取り込んだ音楽ファイル、メタデータ、カバー画像、ダウンロードキャッシュ | ファイル本体のアップロード経路は見当たりません。ブラウザによる消去で永久に失われる場合があります |
| 候補版のセッションと OAuth の Cookie | 認証セッションとログイントランザクション | 第4.1節参照。端末での消去はリモートの削除と同じではありません |

ローカル音声ファイルの本体にアップロード経路は見当たりませんが、歌詞の照合、お気に入りのフィードバック、推薦コンテキストによって、タイトル、アーティスト、アルバム、曲の識別子が送られる場合があります。埋め込みカバー画像を抽出した `data URL` も、お気に入りまたはお気に入り解除のイベントとともに送信され、遠隔の共有曲目カタログに入り、全サイト検索や公開の推薦候補から返される場合があります。そのため、音声ファイル本体が端末に残ることは、カバー画像または関連情報が外部に送られないことを意味しません。共有曲目カタログと任意の外部検索・推薦インデックスは、個人プロファイルのリセットで削除されるとは限りません。関連付け可能性に応じて個人データかどうかを判断する必要があります。

ローカルの再生履歴は直近100曲まで、検索履歴は20件まで自動保存されます。ローカル再生履歴だけを無効にする独立したスイッチは見当たりません。リモートのパーソナライズを無効にしても、このローカル履歴は停止しません。候補版のコメント、返信、いいねの書き込みはローカルでのシミュレーションですが、上流から取得したコメントは他人のデータを含み、キャッシュされる場合があります。画面上の名称は、遠隔への投稿や匿名化の証明にはなりません。

明示的に要求された再生、ログイン、設定のために厳密に必要な端末への保存・読み出しに限り、電子プライバシー規則の必要性に基づく例外が適用される可能性があります。任意のプロファイリング識別子や必須でない保存・読み出しには、事前の有効な同意が必要です。Cookie、localStorage、IndexedDB のいずれも、「ファーストパーティ」であることや端末に保存されることだけで自動的に適用除外とはなりません。具体的な要件は、適用される加盟国の実施法にもよります。

### 4.4 ネットワーク、ログ、外部リソース

インスタンスとインフラは、IP、パス、時刻、接続情報を処理する場合があります。候補版のレート制限は、生の IP または識別情報から派生したキーを使用する場合があり、エッジは、アドレス、セッション、コンテキストを設定されたデータエンジンに転送することもあります。アプリケーションログの最小化は、ホスト、プロキシ、エラーログ、Cloudflare、受領者のいずれも記録しないことを意味しません。通信・処理経路全体の「ゼロログ」保証は確認されていません。

アラート用 webhook が設定され、アラートが発動した場合、受信サービスは、システムの計数値、リリースバージョン、時刻、認証情報をマスキングした概要を受け取り、送信ノードの出口 IP も確認できる場合があります。通常のペイロードにエンドユーザーの識別子や検索が自動的に付加されるわけではありませんが、管理者の備考やエラー情報には個人データが含まれる可能性があります。マスキングは完全な匿名化ではありません。実際に有効にする前に内容を最小化し、受領者と保存・移転に関する取決めを確認する必要があります。

音声プロキシを介すると、上流にはプロキシの出口アドレスが見えるようにできますが、一部のリクエストにはブラウザ情報が含まれる場合があります。MV、カバー画像、アバター、フォント、直接接続するコンテンツは、IP などのメタデータを外部サービスに開示する場合があります。コードは Google Fonts を読み込み、平文のメールアドレスを DiceBear のアバターの seed として使う経路もあります。運営者は、必須でない自動的な外部接続を避け、当該アバターの経路をローカルリソースやメールアドレスを含まない方法に置き換える必要があります。一部の上流では HTTP を使用しているため、全経路がエンドツーエンドで暗号化されているとはいえません。実際の受領者と任意機能のスイッチは[第三者提供と国際移転の一覧](/ja/sub-processors/)を参照してください。

運営者は、データの性質、規模、費用、リスクに応じて、最小権限、認証情報と通信の保護、更新、削除と復元の確認を含む適切な措置を講じる必要があります。個人プロジェクトは、絶対的な安全、無停止、専任のセキュリティチーム、認証を追加で約束するものではありませんが、必要な措置は実施する必要があります。旧版と候補版の保護は異なり、一つのブランチの設計だけに基づいてオンライン環境の安全性を保証することはできません。

GDPR が適用される個人データ侵害は記録する必要があります。権利と自由にリスクが生じる可能性が低い場合を除き、不当な遅滞なく、可能な場合は認識後72時間以内に管轄機関へ通知し、遅れた場合は理由を説明する必要があります。高リスクの場合は、法定の例外を除き、不当な遅滞なく本人にも通知する必要があります。ある国の機関が、実際に管轄権を持つ機関に代わると推定してはなりません。詳細は[データ処理とセキュリティ](/ja/data-security/)を参照してください。
