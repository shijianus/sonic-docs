## 1. 製品の位置づけ

Sonic は独自開発のマルチソース音楽ストリーミングプラットフォームおよびアグリゲーションゲートウェイで、「Cloudflare エッジ制御プレーン + Linux ローカルプロトコルエンジン・データプレーン」の二層アーキテクチャで動作し、高音質ストリーミング、ミリ秒単位の文字下げ歌詞、利用者が制御できるレコメンド体験のために設計されています。本プロジェクトはオープンソースソフトウェアであり、ソースコードは公開され、誰でも自己ホスティングできます。

| 項目 | 説明 |
| --- | --- |
| ホストインスタンス | `sonic.epocanvas.tech`（本サイト）と `sonic.epocanvas.com`（予備ミラー）。運営チームが運用します |
| 自己ホストインスタンス | オープンソースコードにより個人・団体が自有サーバーに展開する私有インスタンス。展開者がそのインスタンスの運営者かつデータ管理者となります |
| ソースライセンス | リポジトリルートの `LICENSE` ファイル（MIT License）に従います。非商用オープンソースとして位置づけられ、過去の README には CC BY-NC-SA 4.0 の意図が記載されていますが、維持者の決定前に `LICENSE` ファイルが優先します。商標とブランドはソースライセンスに含まれません |
| ログイン | Epomail OAuth 2.0（PKCE）。独立した登録システムは持ちません |
| ソフトウェア構成 | Cloudflare Pages フロントエンドとエッジ関数（制御プレーン）、Node.js 22 ローカルエンジンと ncm-api 補助コンテナ（データプレーン）、Vue 3 ウェブプレイヤー |

## 3. アーキテクチャ概観

### 3.1 制御プレーン（Cloudflare エッジ）

制御プレーンは Cloudflare Pages と Pages Functions で動作し、次を担います。

1. **ルーティングと認証**：API リクエストの統一入口、認証チェックと署名鍵の検証；
2. **段階別レート制限**：匿名毎分 240 回、認証済み毎分 600 回（既定値、設定可能）。認証エンドポイントには毎分毎 IP 30 回の専用制限もあります；
3. **多層キャッシュ**：`sonic:*` を鍵とするエッジキャッシュ、新鮮期間 8 分、失効後は容災延長状態へ；
4. **三状態サーキットブレーカー**：連続 3 回の失敗または 4.5 秒予算の超過で OPEN に移行し、後続リクエストは 0ms でエッジ直連兜底（QQ／Kugou 公開検索インターフェースと AMLL／LRCLIB）へ。30 秒冷却後に HALF_OPEN プローブへ移り、成功で CLOSED に復帰します。降格中の応答には `X-Sonic-Degraded: 1` を標示し、プレイヤーは降格表示を表示します。

### 3.2 データプレーン（Linux プロトコルエンジン）

データプレーンは運営者の自有 Linux ノード上の Docker Compose スタックです。

| コンポーネント | 説明 |
| --- | --- |
| sonic-engine 本体コンテナ | Node.js 22 HTTP サービス、ポート 8080 で待ち受け、ホスト側は `127.0.0.1` のみマッピング。全 `/api`・`/proxy`・`/palette` ルートでサービス間鍵（X-Sonic-Engine-Key）の検証を強制 |
| ncm-api 補助コンテナ | NetEase プロトコル補助サービス。compose 内部ネットワーク限定（`ncm-api:3000`）で公開されません |
| SQLite 3（WAL モード） | 行動イベントと実体重みの永続化。命名ボリューム `sonic-data`（コンテナ内 `/app/data/sonic-recommend.sqlite`）に保存。バックアップは一致性スナップショット（VACUUM INTO）と整合性検査で実行 |
| ネイティブプロトコルモジュール | 純 TypeScript による NetEase linuxapi/eapi、QQ、Kugou KRC、Kuwo プロトコル解析 |

制御プレーンとデータプレーンは Cloudflare Tunnel 暗号化チャネルで通信し、データプレーンに公開ポートはありません。

### 3.3 音声ストリーム経路

音声ストリームは既定で同源バイトレンジ・エッジプロキシ経由で公式 CDN から取得され、HTTP `Range` と `206 Partial Content` の部分取得に対応します。上流 CDN に見えるのはプロキシサーバーのアドレスのみで、クライアント IP には触れません。`?mode=redirect` の 302 直接送出モードは、明示的に呼び出す API 利用者にのみ提供されます（ウェブプレイヤーは使用しません）。直接モードではあなたのブラウザが公式 CDN と直接接続します。

## 4. 音源と歌詞チェーン

| ソース | 占有率の位置づけ | 状態 |
| --- | --- | --- |
| ローカルネイティブ解析（NetEase／QQ／Kugou／Kuwo 公式インターフェース + ncm-api） | 主経路（90% 超） | 既定有効 |
| AMLL TTML 文字単位歌詞 + LRCLIB 同期歌詞 | 歌詞補完（約 10%） | 既定有効 |
| GDStudio／Lyriva 第三者アグリゲーション上流 | 応急バックアップ | 既定厳格無効 |
| ListenBrainz／MusicBrainz 類似アーティスト強化 | 任意の強化 | 既定無効 |

試聴検出は音声実体の長さとメタデータを検出し、公式 30 秒試聴の切詰めを識別します。識別結果はフロントエンドで透明に標示され、クロスプラットフォーム全曲マッチング（QQ／Kugou／Kuwo の無料全曲が対象）を発動でき、成功時は円滑に切替えて代替ソースを標示します。本プロジェクトは課金回避の非正規コンポーネントを統合しません。

## 5. スマートレコメンドエンジン

レコメンドエンジンは完全にデータプレーンのローカルで動作し、シグナルの重みはソースコードで公開されています。

| シグナル | 重み | 説明 |
| --- | --- | --- |
| favorite（お気に入り追加） | +4.0 | 極めて強い正向 |
| replay（リピート） | +3.5 | 強い正向 |
| play_complete（有効完聴） | +2.5 | 標準正向 |
| play_progress（進行度聴取） | +0.2 ～ +1.8 | 聴取比率に応じて段階計分 |
| skip（高速スキップ） | -0.8 | 折り返し以降の切替は +0.25 |
| dislike（明示的拒否） | -5.0 | ハードフィルタとブラックリスト登録 |

ノイズと偽シグナルの浄化：ネットワーク遅延（network_stall）、デコード失敗（playback_error）、試聴切詰め（trial_end）、ストリーム不可（stream_unavailable）、バッファタイムアウト（buffer_timeout）、自動切替失敗（auto_switch_error）による切替は、重みが恒等的にゼロで保存されません。

ヒートモデルは有効再生（35%）、独立リスナー（25%）、完聴（20%）、お気に入り転化（15%）、成長勾配（5%）を総合し、指数時間減衰（24 時間急上昇チャートと 7 日累計チャート）、ベイズと Wilson Score 平滑を併用します。類似度はアーティスト関係グラフと音声特徴コサインを融合し、MMR 辺際関連性リランクで精度と多様性を両立します。セッション単位の検索インテントは長期プロファイルと階層的に分離され、完聴・お気に入り等の高価値行為のみが長期プロファイルに蓄積されます。

## 6. セキュリティ設計の概観

1. **認証**：Epomail OAuth 2.0 認可コードフロー、`state` パラメータと PKCE（S256）により認可コードの横取り・再生攻撃を防止。OAuth トランザクション Cookie は 600 秒有効；
2. **API キー**：`sonic_live_v2.<header>.<payload>.<signature>` バージョン付き形式、HMAC-SHA256 署名、ペイロードは `sub`／`iat`／`exp`／`jti`／`kid`／`role`／`uid` を含む。発行有効期間 30 日、検証上限 90 日。サーバー側は Web Crypto による定数時間比較で、無署名鍵と旧版鍵は一律拒否（fail-closed）。鍵は `X-Sonic-Key` または `Authorization` リクエストヘッダーのみで伝送され、URL クエリ経路は完全に廃止済み；
3. **取消**：ログアウトで現在のセッションと鍵識別子（jti）を直ちに取消。jti 取消リスト・主体取消リスト・グローバル発行時間下限に対応し、KV バインド時は即時取消に対応します；
4. **セッション**：`HttpOnly; Secure; SameSite=Lax` の `sonic_session` Cookie、最長 30 日有効。鍵を URL・localStorage・スクリプトから参照可能な場所に書き込むことはありません；
5. **SSRF 対策**：ループバックアドレス、RFC 1918 私設網、Docker 内部ブリッジ、クラウドメタデータアドレス（`169.254.169.254` など）への外向きリクエストは一律遮断。IPv4・IPv6 両スタックで検証し、リダイレクトのたびに目標と DNS 解決結果を再検証します。

## 7. プライバシー設計の概観

1. **偽名化が既定**：行動イベントは収集の時点から一方向ハッシュ識別子で紐付け、電子メールアドレスはディスクに保存しません；
2. **パーソナライズ自主スイッチ**：プレイヤー設定でいつでも無効化できます。無効時はイベントが保存されず、公開モードではサーバー側で直接廃棄されます；
3. **ワンクリック消去**：設定ページの「レコメンドプロファイルの消去」でサーバー側の全行動イベントを即時消去、「全ローカルデータの消去」でブラウザのローカルストレージと IndexedDB を即時消去；
4. **ログの最小化**：データプレーンのアクセスログはパス・メソッド・ステータスコード・所要時間のみを含みます。

プライバシーに関する約束の全体は[プライバシーポリシー](/ja/privacy-policy/)に、技術的措置は[データ処理とセキュリティ](/ja/data-security/)に記載します。

## 8. 適合する人としない人

適合する人：自有の Epomail アカウントでログインし、レコメンドプロファイルの透明性と消去可能性を重視する個人リスナー。マルチソース検索と文字単位歌詞を必要とするヘビーリスナー。Linux と Docker の基礎を持ち、運営者責任を自ら引き受ける自己ホストユーザー。

適合しない人：商用音楽サービスの許諾保障を求める場面——本プロジェクトは音楽を保管・ホスティングせず、コンテンツの再許諾もしません。サービス水準合意（SLA）や商用サポートを期待するチーム。「試聴クリップの透明標示、クロスソース補完はベストエフォート」を受け入れられない利用者。

## 9. コンテンツと著作権の境界

Sonic は検索・アグリゲーション・再生のツールであり、音楽ファイルを保管・ホスティングしません。録音・歌詞・ジャケット・アーティスト画像などの権利は各自の権利者に帰属し、本プロジェクトは音楽コンテンツの再許諾を行いません。正規会員カタログは展開者が自有の認証情報（`NETEASE_COOKIE` など。展開者のアカウントでありエンドユーザーのものではありません）でマウントし、公開カタログは公式の公開プロトコルに従います。

本サービスの利用にあたっては[受け入れ可能な利用ポリシー](/ja/acceptable-use/)を遵守してください。展開者はその利用形態が現地法・上流サービス規約・コンテンツライセンスに適合することを自己確認する責任を負います。

## 10. 展開形態

| 形態 | 構成 | 要点 |
| --- | --- | --- |
| Cloudflare Pages エッジゲートウェイ | フロントエンド SPA + Pages Functions | 構築後に `wrangler pages deploy` で公開。`SONIC_SECRET`、`SONIC_ENGINE_SECRET`、`SONIC_LOCAL_ENGINE_URL` の設定が必要 |
| Linux ローカルプロトコルエンジン | sonic-engine + ncm-api + SQLite | `docker compose up -d --build` で展開。`.env` の権限は 600。Cloudflare Tunnel 経由で接続 |

二形態が揃って完全なサービスとなります。データプレーンなしでエッジゲートウェイのみ展開した場合、サービスは自動で降格モード動作となります。環境変数の完全なリストは上流リポジトリの `.env.example` と `docs/OPERATIONS.md` を参照してください。
