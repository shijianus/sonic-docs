**発効日：2026年11月2日｜バージョン：1.5**

Sonic のレコメンドエンジンについて、どのシグナルがモデルに入り、どのように重み付け・並べ替えされるか、利用者がどのように制御できるかを説明します。ルールはすべてソースコードで公開されています。データ収集の法的根拠と範囲は[プライバシーポリシー](/ja/privacy-policy/)第4.2節と第5節を参照してください。

## 1. 行動シグナルと重み

| シグナル | 重み | 説明 |
| --- | --- | --- |
| favorite（お気に入りに追加） | +4.0 | 非常に強いプラス |
| replay（再度再生） | +3.5 | 強いプラス |
| play_complete（有効な再生完了） | +2.5 | 標準的なプラス |
| play_progress（再生の進み具合） | +0.2 ～ +1.8 | 聴いた割合に応じて段階的に加点 |
| skip（すぐにスキップ） | -0.8 | 半分以上聴いてからの曲変更は +0.25 として加点 |
| dislike（明確に拒否） | -5.0 | 強制的に除外し、ブロックリストに追加 |

**ノイズの除去**：ネットワーク停止（network_stall）、再生エラー（playback_error）、試聴終了（trial_end）、ストリーム利用不可（stream_unavailable）、バッファリングのタイムアウト（buffer_timeout）、自動切替エラー（auto_switch_error）による曲変更は、利用者がスキップしたものとは扱いません。重みは常に0で、保存もされません。

## 2. 人気度モデル

サイト内のトレンドランキングは、正常な再生（35％）、ユニーク視聴者（25％）、再生完了率（20％）、お気に入りへの転換（15％）、成長率（5％）の5要素を加重して算出します。さらに指数関数による時間減衰（24時間急上昇ランキングと7日間の累計ランキング）と、ベイズ／Wilson スコアによる平滑化を用い、再生数が少ないのに完了率だけ高い一時的な曲が不自然に上位へ来ることを抑えます。

## 3. セッションの意図と長期的な嗜好

セッション単位の検索意図（連続して入力した検索語、クリックしたアーティストやジャンル）は、短期的な重みを高くして即時の並べ替えに反映します。一方、長期的な嗜好とは分けて扱います。再生完了やお気に入りなど価値の高い行動だけが長期プロファイルに蓄積され、たまたま行った検索が長期的な傾向をすぐに変えることはありません。

## 4. 多様性のための並べ替えと Auto DJ

1. **類似度**：アーティストの関係グラフ、ジャンル・言語タグの集合類似度、音声特徴量のコサイン類似度を組み合わせます；
2. **MMR による並べ替え**：限界関連性によって「的確さ」と「新しさ」のバランスを取り、1人のアーティストや1つのジャンルだけに偏ることを避けます；
3. **Auto DJ**：プレイリストが自然に終わると、現在の曲のスタイルに応じて再生可能な曲を自動で続けます。設定から無効にできます。

## 5. 音楽・スタイルレーダー

検索を1回完了すると、ホームのレーダーが検索意図と嗜好シグナルに基づいて、一致する結果を人気曲と同じ形式で表示します。レーダーが変えるのは表示されるおすすめの順番だけで、保存されているデータは変更しません。

## 6. 利用者が変更できる項目

| 項目 | 場所 | 効果 |
| --- | --- | --- |
| パーソナライズ全体スイッチ | 設定 → プライバシーとローカルデータ | 無効にするとイベントを収集せず、おすすめは公開情報だけのモードになります |
| Auto DJ スイッチ | 設定 → プライバシーとローカルデータ | 再生終了後に自動で続けるかを制御します |
| レコメンドプロファイルのリセット | 設定 → プライバシーとローカルデータ | サーバー上の行動イベントをすべて直ちに破棄します |
| 曲を拒否 | プレイヤー内の dislike | 強制的に除外し、レコメンドに再び表示しません |

アルゴリズムの技術的な事実はソースコードの更新に合わせて変わります。本文書とソースコードが一致しない場合はソースコードを基準に本文書を修正します。確認手順は[開発ガイド](/ja/development/)第4節を参照してください。
