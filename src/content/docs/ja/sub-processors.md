## 1. インフラと委託処理関係

| 対象 | 機能 | 関係し得るデータと設定上の限界 |
| --- | --- | --- |
| Cloudflare Pages と Functions | ホスティング、エッジ API、キャッシュ、レート制限 | IP、パス、ヘッダー、接続メタデータ。具体的な記録はインスタンスと提供者の設定によります |
| Cloudflare Tunnel | エッジとデータプレーンの間の経路 | リクエストの通信と接続メタデータ。トンネルによってすべての内部・上流 HTTP 経路が自動的に暗号化されるわけではありません |
| Cloudflare KV とレート制限器 | レート制限、認証情報の失効等の設定可能な保存 | IP または識別情報由来のキー、失効識別子。有効化の有無と期間の確認が必要です |
| データプレーンのホストまたはホスティング提供者 | エンジン、データベース、ログの実行環境 | エンジンはエッジから生 IP、Cookie、認証ヘッダー、コンテキストを受け取り得ます。ホストの主体とノード所在国は未確認です |

委託処理に当たるかは、目的を決定する者、指示に従って処理する者、実際の取り決めによって判断し、製品名だけでは決まりません。GDPR が適用され委託処理関係がある場合は、第28条が要求する取り決めを実施すべきです。ここで契約を締結・確認済みとは主張しません。管理者の完全な身元と送達可能な情報も補足が必要です。[プライバシーポリシー](/ja/privacy-policy/)第2節を参照してください。

## 2. 認証提供者（ログインに必要）

Epomail（`mail.epocanvas.com`）は OAuth ログインを提供します。ブラウザが認証サービスと通信し、Sonic は認可コードを交換してユーザー情報を照会します。ユーザー識別子、メールアドレスと検証フラグ、ニックネーム、アバター URL、ロールを取得する場合があります。一部はブラウザの `auth` ストレージと署名付きセッションに保存され、「メモリ内だけ」ではありません。

ログイン接続や共通ブランドだけで、Epomail が自動的に Sonic の委託処理者になるわけではありません。アカウント体系の独立した処理と指示に基づく処理は、実際の目的と取り決めに応じて別々に判断すべきです。Sonic は自ら決定する受領、保存、その後の開示について引き続き責任を負います。

## 3. 上流コンテンツとブラウザの直接接続

| 提供元 | 主な用途 | 送受信し得るデータ |
| --- | --- | --- |
| NetEase Cloud Music、QQ Music、Kugou、Kuwo と関連 CDN | 検索、音声、MV、カバー、コンテンツ情報 | 検索原文、コンテンツ識別子、メタデータ、プロキシ出口またはブラウザ直接接続の情報 |
| AMLL、LRCLIB | 歌詞照会と補完 | 曲識別子、タイトル、アーティスト等の照合情報と接続メタデータ |
| Google Fonts | フォント読み込み | ブラウザの IP、User-Agent 等の接続情報 |
| DiceBear | 外部アバター | 現在の経路では URL の seed に平文メールアドレスが含まれ得て、ブラウザ接続情報も開示されます |

音声プロキシは CDN にプロキシ出口を見せられますが、すべての要求に個人データが含まれないという意味ではありません。ストリーム要求は統一の固定値ではなく、ブラウザの User-Agent を使う場合があります。MV、カバー、フォント、アバターはブラウザが直接要求し得ます。一部提供者は HTTP を使用するため、全経路の TLS は保証できません。DiceBear のメール seed は、ローカルアバターかメールを含まない識別子に変更すべきです。

上流コメントは他人の氏名・ニックネーム、アバター、本文を含み、公開キャッシュに入る場合があります。その目的には、要求された MV のコメント表示があります。投稿者は本サービスのログイン契約の当事者ではなく、GDPR 第6条第1項第b号だけに基づいてそのデータを処理することはできません。GDPR 適用時は公開情報でも第14条の間接収集の告知が自動的に免除されません。運営者は独立した処理根拠、保存期間、告知の例外を評価・記録し、法定期間内に適用される告知を提供すべきです。必要な保護措置が未整備なら取得や公開キャッシュを停止すべきであり、すべての投稿者に個別連絡できるとは約束しません。ローカルで作成したコメントは現在 localStorage にのみ保存され、コメントサーバーへの投稿経路は見つかっていません。

ローカル音声 Blob のアップロード経路は見つかっていませんが、歌詞照合や推薦コンテキストではタイトル、アーティスト、アルバム、長さ、識別子が送られる場合があります。埋め込みカバーを data URL として抽出した画像も、お気に入りイベントとともに送信され、遠隔の共有曲目カタログに入り、全サイト検索や公開候補に返され得ます。プロファイルリセットは、このカタログや任意の外部インデックスの完全な削除を保証しません。音声ファイル本体が端末に残ることは、関連情報が外部に送られないという意味ではありません。

## 4. 任意の経路と設定の差異

| 経路 | 用途と関係し得るデータ | 確認範囲 |
| --- | --- | --- |
| GDStudio（`music-api.gdstudio.xyz`） | 集約検索、ソース間補完、照会またはコンテンツ識別子 | スイッチ未設定時はコード上で既定 ON、環境例と Compose では OFF。実際の状態は確認が必要です |
| Lyriva（`api.lyriva.xyz`） | 歌詞の代替、コンテンツ識別子・照合パラメータ | `SONIC_ENABLE_LYRIVA` 等の設定によります |
| Musixmatch（`apic-desktop.musixmatch.com`） | 歌詞補完 | RC に実装は残っていますが、`isSourceEnabledByPolicy` に Musixmatch 分岐がなく、実際の呼び出しは false の門番で阻止されます。旧 `main` の歌詞 fallback は呼び出せる場合があるため、展開ごとに確認してください。RC が有効化済み、または通常のスイッチで有効化できるとは書けません |
| 運営者が設定するアラートサービス | 有効な `SONIC_ALERT_WEBHOOK_URL` が設定され、アラートが発動した場合だけ送信。システム計数値、リリースバージョン、時刻、認証情報をマスキングした概要、送信ノードの出口 IP | 有効化、受領者、役割、移転、保存期間はインスタンスごとに確認が必要。管理者の備考やエラー情報には個人データが含まれる場合があり、マスキングは匿名化ではありません |
| ListenBrainz / MusicBrainz | 類似アーティストの補強、アーティスト・録音識別子 | `SONIC_ENABLE_LISTENBRAINZ` 等の設定によります |
| Gorse | 外部推薦、仮名識別子、行動フィードバック、曲目カタログのメタデータ | `SONIC_GORSE_URL` 等で接続。タイトル、アーティスト、タグ等のカタログ入力や一部のフィードバックが送られ得る。現在のリセットは外部フィードバックまたは曲目情報の同期削除を保証しません |
| Meilisearch | 任意の検索サービス、検索原文とカタログ情報 | 接続の有無と保存期間はインスタンスで確認し、匿名照会とは扱えません |
| ソース間補完 | プラットフォーム間のコンテンツ照合、曲のメタデータ | 実際の要求は照合経路によります。機能が利用可能でもコンテンツの許諾を得たとは限りません |

スイッチの設定はユーザーの同意ではありません。既定 ON のパーソナライズと Auto DJ における同意の不足は[プライバシーポリシー](/ja/privacy-policy/)第5節を参照してください。必要な根拠と選択を整備していない任意処理は停止すべきであり、第三者の名前を変えて要件を回避してはなりません。

## 5. 法的要求に基づく共有

提出要求を受けた場合は、要求者の身元、管轄権、具体的根拠、範囲を確認し、法律上必要なデータだけを提供して理由を記録すべきです。本人への通知は適用法と有効な制限に従って判断します。通報、違反の疑い、サービス終了だけで、すべてのデータを警察へ自動共有するわけではありません。

開示の根拠となる法的義務も、国際移転の要件に代わるものではありません。公開 Issue やコミュニティに問題を投稿する前に、個人データ、認証情報、他人のコメント内の私的情報を取り除いてください。

## 6. 国際移転

GDPR の適用は第3条で判断し、無料・非営利であることや EU からアクセスできることだけで自動的に否定・確定されません。具体的な個人データ移転に GDPR 第V章が適用される場合に、実際の受領者、場所、処理上の役割ごとに、第44条の要件、適用される十分性認定（第45条）、その他の有効な保護措置（第46条）を確認します。すべての海外 IP やコンテンツ要求を一律に第V章の移転と記述することはできません。全 GDPR 制度を世界共通の契約保証とはせず、管理者所在地、データプレーン所在国、全要求の送信先も未確認です。台湾でのホスティングや特定法域の管轄を推定できません。

1. GDPR が適用される第三国移転は、第44条の要件を個別に満たし、適用される十分性認定（第45条）または他の有効な保護措置（第46条）を確認すべきです。
2. 標準契約条項を使用しても、適用主体、処理範囲、移転評価、必要な補完措置の確認が必要です。提供者が条項を公開しているだけでは、このインスタンスで実施済みとはなりません。
3. ISO／SOC 認証、提供者のプライバシーポリシー、本ページへの同意は、自動的に適法な移転根拠にはなりません。検索テキスト、IP、仮名識別子も一律に個人データから除外できません。
4. 法に基づき `privacy@epocanvas.com` へ保護措置の説明や写しを請求できます。必要な営業秘密は適切に伏せられますが、機密性を理由に法定の透明性義務をなくすことはできません。
