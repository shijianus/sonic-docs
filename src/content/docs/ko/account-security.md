Sonic 계정 체계의 작동 방식과 안전한 이용 방법을 설명합니다. 기술 구현의 전체 설명은 [데이터 처리 및 보안 유지](/ko/data-security/) 3.2절, 약정 내용은 [이용약관](/ko/terms-of-service/) 3절을 참조하십시오.

## 1. 로그인 방식

본 서비스는 Epomail 계정으로 OAuth 2.0(PKCE) 로그인을 제공하며 별도의 회원가입 시스템을 두지 않습니다. 사이드바의 계정 진입점 선택 → Epomail 인가 페이지에서 확인 → 본 서비스로 돌아오면 로그인이 완료됩니다. 인가 콜백은 state, PKCE, 인가 코드, 재전송의 네 가지를 검증합니다. 인증 엔드포인트에는 분당 IP당 30회의 전용 요청 제한이 별도로 적용됩니다.

## 2. 세션 메커니즘

1. 세션 쿠키: 로그인에 성공하면 `HttpOnly; Secure; SameSite=Lax` 세션 쿠키가 발급되며 최대 30일 동안 유효합니다. 쿠키에는 서명된 API Key가 들어 있고 스크립트에서는 읽을 수 없습니다.
2. 탭 간 동기화: 같은 브라우저의 탭 사이에서 로그인 상태가 자동으로 동기화됩니다. 어느 탭에서 로그아웃해도 다른 탭에 반영됩니다.
3. 키의 저장 경계: API Key를 URL, 쿼리 매개변수 또는 localStorage에 기록하지 않습니다. OAuth 트랜잭션 쿠키의 유효 기간은 600초뿐입니다.

## 3. API Key 보관

API Key는 사용자의 개인 인증 정보입니다(형식 `sonic_live_v2.…`, HMAC-SHA256 서명).

1. 요청 헤더로만 전달하며 URL에는 절대 넣지 않습니다.
2. 제3자에게 넘기거나 공개 배포 클라이언트에 포함하지 마십시오.
3. 재발급에는 현재 유효한 키가 필요합니다. 유출 시에는 즉시 로그아웃하고 폐기하십시오(4절 참조).

## 4. 폐기와 로그아웃

| 작업 | 위치 | 효과 |
| --- | --- | --- |
| 로그아웃 | 플레이어 안 | 현재 세션과 키 식별자(jti)를 즉시 폐기함 |
| 키 폐기 | `POST /api/auth/revoke` | 현재 API Key를 폐기함 |
| 일괄 무효화 | 배포자 설정 | jti 목록, 주체 목록, 전역 발급 시점 하한을 지원함 |

## 5. 안전한 이용 방법

1. 공용 기기에서는 사용 후 반드시 로그아웃하십시오. 세션 쿠키에 서명된 키가 들어 있습니다.
2. Epomail 계정에서 2단계 인증을 켜는 것이 좋습니다.
3. 계정을 빌려주거나 공유하지 마십시오. 공유 계정에서 발생한 데이터 혼재는 구분하거나 복구할 수 없습니다.
4. 이상한 재생 기록이나 출처를 알 수 없는 세션을 발견하면 즉시 로그아웃하고 `admin@epocanvas.com`으로 연락하십시오.
5. 본 서비스는 비밀번호를 수집하지 않습니다. 로그인은 Epomail에서 처리하므로 「Sonic 비밀번호 확인」을 요구하는 연락은 사칭입니다.

## 6. 계정 관리 진입점

사이드바 하단의 계정 진입점에서 현재 로그인 상태를 확인할 수 있습니다. 로그아웃 상태에서는 로그인 안내가, 로그인 후에는 계정 닉네임과 Epomail의 프로필·받은편지함으로 연결되는 계정 관리 링크가 표시됩니다. 로그인 상태는 같은 브라우저의 탭 사이에서 자동으로 동기화됩니다.
