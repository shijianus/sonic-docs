**개정일: 2026년 11월 2일｜버전: 1.8**

이 페이지의 기능 확인은 최신 공개 RC `rc/sonic-20261031@a75f5cb`(2026-11-01 UTC)에 근거합니다. 이전 기본 브랜치 `main@ce443c8`(2026-10-27 UTC)은 호환성 비교 대상일 뿐 RC 기능의 배포를 입증하지 않습니다. 실제 서비스 버전과 설정은 알 수 없습니다.

이 페이지는 Sonic의 주요 데이터가 어디에 저장되는지, 현재 무엇을 조회할 수 있는지, 어떻게 삭제하는지, 어떤 데이터에 제품 내장 다운로드·내보내기 기능이 없는지를 정리합니다. 법적 근거와 권리 체계는 [개인정보 처리방침](/ko/privacy-policy/) 4·6·9절, 기술 조치는 [데이터 처리 및 보안 유지](/ko/data-security/)를 참조하십시오.

## 1. 저장 위치 개요

| 데이터 | 위치 | 신원 연계 | 보존 기간 |
| --- | --- | --- | --- |
| 즐겨찾기, 플레이리스트, 선호 | 주로 브라우저 localStorage. 레이더에는 별도의 원격 경로가 있음 | 일부 피드백과 추천 맥락이 전송될 수 있음 | 로컬 사본은 삭제할 때까지. 원격 자료는 별도 처리 |
| 재생 기록 | 브라우저 localStorage와 별도로 전송되는 재생 이벤트 | 이벤트에는 연결 가능한 가명 식별자가 사용될 수 있음 | 로컬 삭제로 원격 이벤트가 삭제되지는 않음 |
| 다운로드 및 로컬 음악 | 브라우저 IndexedDB | 오디오 파일 본체 업로드는 발견되지 않았으나 제목, 아티스트, 앨범, 식별자와 내장 커버 이미지는 전송될 수 있음 | 로컬은 삭제 또는 브라우저 회수까지. 원격 자료는 별도 처리 |
| 행동 이벤트·엔티티 피드백 | 실제 활성화된 경우 서버 데이터베이스 또는 외부 서비스에 있을 수 있음 | 가명 식별자는 익명과 같지 않음 | RC 기본 90일, 최소 7일. 정리는 불완전하며 각 기록이 만료되는 즉시 파기되지 않으므로 전면 자동 삭제를 약속해서는 안 됨 |
| 검색 집계·레이더 프로필 | 원격 검색 저장소. 레이더의 내구성 있는 엔진 저장은 미확인 | 검색 원문은 개인을 식별하고 공개 표시될 수 있음 | 검증된 통일적 자동 보존 기한이 없으며 초기화가 전체를 포함하지 않음 |
| 공유 곡목 카탈로그·외부 인덱스 | 서버 곡 데이터베이스와 선택적 추천·검색 시스템 | 사용자 이벤트에 제목, 아티스트와 내장 커버가 포함될 수 있으며 전체 사이트 검색에 제공될 수 있음 | 개인 프로필 초기화로 모두 정리되지 않으며 연결 가능성에 따라 처리 |
| 검색 기록(로컬) | 브라우저 localStorage | 검색어는 검색을 위해 전송되며 통계·맥락에도 포함될 수 있음 | 로컬 삭제로 원격 사본이 삭제되지는 않음 |

이메일 주소와 아바타 정보는 브라우저 `auth`에 보관되며, 자격 증명의 서명은 암호화가 아닙니다. 원본 IP 키가 KV나 요청 제한기에 들어갈 수 있고 클라이언트 주소, 세션과 맥락이 엔진으로 전달될 수 있습니다. 표에 IP 필드가 없다고 IP 처리가 없다는 뜻은 아닙니다. 범용 기기 간 클라우드 백업을 보장하지 않습니다.

## 2. 조회: 추천 프로필 개요

최신 공개 RC는 서버 측 프로필 요약 조회를 위한 `GET /api/sonic/events` 또는 설정 페이지의 프로필 영역을 제공합니다. 이전 `main@ce443c8`은 호환성 비교 대상일 뿐 RC가 배포되었다는 증거가 아닙니다. 인스턴스가 요약을 제공하더라도 완전한 개인정보 내보내기나 모든 이벤트 원문의 사본은 아닙니다. 현재 전체 서버 이벤트를 다운로드할 수 있다고 사용자에게 약속해서는 안 됩니다.

## 3. 내보내기와 백업

1. 브라우저 데이터: 즐겨찾기, 플레이리스트, 선호, 다운로드와 로컬 음악은 주로 브라우저에 보관됩니다. 일부 피드백, 메타데이터와 맥락은 별도로 전송됩니다. 서비스에는 범용 localStorage·IndexedDB 내보내기 도구, 클라우드 백업이나 기기 간 가져오기가 내장되어 있지 않습니다. 필요에 따라 중요한 플레이리스트를 기록하고 원본 로컬 음악 파일을 보관하거나, 브라우저·운영체제가 실제 제공하는 신뢰할 수 있는 백업 기능을 사용하십시오.
2. 원격 자료: 원격 처리에는 곡 이벤트뿐 아니라 이벤트, 엔티티 피드백, 검색 자료와 레이더 동기화 경로가 포함될 수 있습니다. 레이더의 내구성 있는 엔진 저장은 미확인입니다. 요약은 완전한 내보내기가 아니며 초기화도 부분 삭제에 불과합니다. 전체 사본이나 더 포괄적인 삭제는 5절의 채널로 요청하고, 필요한 경우 이전 신원까지 포함하십시오.
3. 추천 프로필 요약: 관련 기능이 활성화되고 인스턴스가 설정 페이지나 API를 제공하는 경우에만 조회할 수 있습니다. 실제 서비스에서의 이용 가능 여부는 확인되지 않았습니다. 요약은 완전한 내보내기가 아니므로 모든 개인정보를 얻었다고 주장하는 근거로 삼을 수 없습니다.
4. 로컬 음악: 가져온 원본 파일은 사용자의 기기에 남아 있습니다. 브라우저 안의 복사본을 삭제해도 원본 파일은 영향을 받지 않습니다.

## 4. 삭제 작업

| 작업 | 범위 | 적용 |
| --- | --- | --- |
| 추천 프로필 및 관심 없음 기록 초기화 | 현재 신원의 일부 이벤트·피드백. 이전 식별자, 레이더, 집계, 외부 서비스와 백업이 누락될 수 있음 | RC 경로는 `DELETE /api/sonic/events`. 실패가 표시되지 않을 수 있으며 성공이 완전한 삭제를 입증하지 않음 |
| 모든 로컬 데이터 삭제 | 브라우저 저장소 정리 및 일부 원격 초기화를 요청할 수 있음. Cookie나 URL 자격 증명 삭제 또는 로그아웃을 가정해서는 안 됨 | 결과를 각각 확인해야 함. 설정 삭제 후 다시 로드하면 기본 상태가 복원될 수 있으므로 선택을 재확인해야 함 |

| 로그아웃 | 현재 Cookie 정리. 복제된 자격 증명은 서버에서 폐기해야 함 | 원격 효과는 폐기 저장소 설정과 요청 성공에 달려 있음 |

## 5. 셀프 호스팅 인스턴스

셀프 호스팅 인스턴스의 사용자는 해당 운영자가 공개한 권리 요청 채널로 연락해야 합니다. 이 문서의 사용 예정 Sonic 이메일을 모든 배포자의 컨트롤러 연락처로 보아서는 안 됩니다. 호스팅 인스턴스 사용자의 조회, 정정, 삭제, 처리 제한, 이동, 반대 또는 동의 철회 요청은 [개인정보 처리방침](/ko/privacy-policy/) 9절을 참조하십시오. 이 페이지는 기존 요약 조회나 삭제 기능을 전체 데이터 다운로드로 확대 해석하지 않습니다.

셀프 호스팅 운영자는 SQLite 볼륨뿐 아니라 실제 모든 저장소와 수신자를 파악해야 합니다. 보존 설정 자체가 레이더, 검색 자료, 로그와 백업까지 포함하지는 않습니다. 필요한 보존 기간과 검증된 삭제 절차를 마련하고, 백업을 만료 시 정리할 때까지 격리하며, 복원 후에는 삭제 기록을 다시 적용해야 합니다. [배포 가이드](/ko/deployment/) 3절과 [오픈 소스와 셀프 호스팅 법률](/ko/open-source/) 4절을 참조하십시오.
