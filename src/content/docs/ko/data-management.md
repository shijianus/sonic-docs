**시행일: 2026년 11월 2일｜버전: 1.5**

본 페이지는 Sonic에서 생기는 사용자의 모든 데이터를 정리합니다. 어디에 저장되는지, 어떻게 조회하는지, 어떻게 내보내고 지우는지를 다룹니다. 법적 근거와 권리 체계는 [개인정보 처리방침](/ko/privacy-policy/) 4·6·9절, 기술 조치는 [데이터 처리 및 보안 유지](/ko/data-security/)를 참조하십시오.

## 1. 저장 위치 개요

| 데이터 | 위치 | 신원 연계 | 보존 기간 |
| --- | --- | --- | --- |
| 즐겨찾기, 플레이리스트, 선호 | 브라우저 localStorage | 업로드하지 않음 | 삭제할 때까지 |
| 재생 기록 | 브라우저 localStorage | 업로드하지 않음 | 삭제할 때까지 |
| 다운로드 및 로컬 음악 | 브라우저 IndexedDB | 업로드하지 않음 | 삭제할 때까지 |
| 행동 이벤트 | 서버 SQLite(데이터 플레인) | 가명 처리 해시 | 90일 후 자동 파기 |
| 전역 집계 통계 | 서버 SQLite | 개인과 연결하지 않음 | 데이터베이스 유지 정책에 따름 |
| 검색 기록(기기 내) | 브라우저 localStorage | 업로드하지 않음 | 삭제할 때까지 |

이메일 주소와 같은 계정 식별 정보는 데이터베이스에 영구 저장되지 않고 세션 동안만 유지됩니다. 데이터베이스에는 IP 열이 없습니다.

## 2. 조회: 추천 프로필 개요

`GET /api/sonic/events` 또는 설정 페이지의 프로필 영역에서 서버에 현재 연결된 프로필의 개요를 조회할 수 있습니다. 이벤트 총수, 좋아요와 거부 카운트, 자주 듣는 아티스트, 장르 성향, 최근 검색어, 저장 형태가 표시됩니다. 이 조회는 셀프서비스 열람권(GDPR 제15조)의 즉시 실현입니다. 완전한 기록은 행동 이벤트 그 자체이며, 삭제 후 다시 쌓이는 방식으로 그 범위를 검증할 수 있습니다.

## 3. 내보내기와 백업

1. 브라우저 데이터: 즐겨찾기, 플레이리스트와 다운로드는 사용자의 브라우저에 저장되며 브라우저 자체의 내보내기·동기화 기능으로 백업할 수 있습니다. 본 서비스에는 내장 클라우드 내보내기가 없습니다. 이는 프라이버시 최소화 설계의 대가로, 데이터는 사용자의 기기에 속합니다.
2. 행동 이벤트: 서버에는 가명 처리된 행동 이벤트만 저장되며 내보내기 경로가 없습니다. 삭제가 필요하면 4절의 삭제 작업을 사용하십시오.
3. 로컬 음악: 가져온 원본 파일은 사용자의 기기에 남아 있습니다. 브라우저 안의 복사본을 삭제해도 원본 파일은 영향을 받지 않습니다.

## 4. 삭제 작업

| 작업 | 범위 | 적용 |
| --- | --- | --- |
| 추천 프로필 및 관심 없음 기록 초기화 | 서버의 모든 행동 이벤트 | 즉시(`DELETE /api/sonic/events`) |
| 모든 로컬 데이터 삭제 | 브라우저 localStorage, sessionStorage, IndexedDB 전체와 서버 프로필 | 확인 후 즉시 |
| 브라우저 사이트 데이터 삭제 | 위와 같음(브라우저 측) | 즉시 |
| 로그아웃 | 세션과 키 | 즉시 |

## 5. 셀프 호스팅 인스턴스

셀프 호스팅 인스턴스의 데이터는 배포자의 데이터 플레인(SQLite 네임드 볼륨)에 저장됩니다. 배포자는 보존 일수와 저장 경로를 설정할 수 있습니다([배포 가이드](/ko/deployment/) 3절 참조). 백업 의무와 고지 의무는 [오픈 소스와 셀프 호스팅 법률](/ko/open-source/) 4절에도 설명되어 있습니다.
