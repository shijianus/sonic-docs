Sonic은 개인이 유지·관리하는 무료·비영리 학습 및 공익 테스트 프로젝트입니다. 사용자의 사생활을 존중하며, 합리적인 노력을 기울여 실제 위험에 비례하는 높은 수준의 보호 조치를 마련하는 것을 목표로 합니다. 엄격하고 검증 가능한 보호를 지향하고, GDPR의 데이터 최소화, 목적 제한, 투명한 고지와 사용자 통제 원칙을 참고하여 지속적으로 개선하고자 합니다.

이 보호 목표는 EU 인증을 받았거나 GDPR 및 모든 회원국 법률을 전면적으로 준수한다는 선언이 아닙니다. 절대적인 안전이나 유출·손실이 전혀 없다는 점을 보장하지 않으며, 모든 데이터를 즉시 완전하게 삭제할 수 있다는 기술적 보장도 아닙니다. 법에서 정한 삭제 의무와 요청 처리 기한에는 영향을 주지 않습니다. 실제 보호 수준은 배포 버전, 설정과 제3자의 처리에 달려 있습니다. 아래에서는 목표와 코드에서 확인되는 조치, 알려진 위험 및 미확인 사항을 구분하여 설명합니다. “합리적인 노력”은 적용되는 법적 의무를 줄이지 않으며, 위험 고지는 위법한 처리를 받아들이거나 권리를 포기하라는 요구가 아닙니다.

## 3. 보안 유지 조치

### 3.1 전송과 접근

1. 공개 진입점에 HTTPS, OAuth, 서명 세션, 서비스 간 키를 설정할 수 있으나 코드 제어만으로 실제 진입점·프록시·업스트림 모두의 TLS 사용이 입증되지는 않습니다.
2. 컨트롤·데이터 플레인 사이의 암호화 터널과 데이터 플레인의 루프백 전용 바인딩은 호스팅 설정에 달려 있습니다. 내부 평문 HTTP 경로만으로도 “전 구간 암호화”라는 포괄적 표현은 성립하지 않습니다.
3. 프록시의 대상 검증과 도메인 제한은 실제 프록시를 거치는 요청만 포함합니다. 감사에서는 원본 IP가 Cookie·인증 헤더·맥락과 함께 엔진에 전달될 수 있어 가명 정보만 받는다고 할 수 없습니다.
4. 오디오 스트림 요청은 고정값이 아닌 브라우저 User-Agent를 쓸 수 있습니다. 브라우저가 MV·커버·Google Fonts·아바타에 직접 연결하면 해당 서비스에 IP와 연결 메타데이터가 보일 수 있습니다.

### 3.2 인증과 키

1. 확인된 RC는 OAuth state와 PKCE를 사용하며 서명 세션은 기본 30일입니다. 실제 Cookie 속성과 기간은 배포에서 검증해야 합니다. 서명은 무결성 수단이지 암호화가 아니며 페이로드에 이메일·사용자·역할 식별자가 포함될 수 있습니다.
2. API Key의 버전·서명·시간·`jti` 검증 실패 시 요청을 거부해야 합니다. 이름, 환경 변수, 설계 주석을 완전한 인증 제어의 증거로 삼아서는 안 됩니다.
3. 로그아웃이나 일괄 폐기의 즉시성은 폐기 저장소·스위치·요청 성공에 달려 있습니다. 비활성화되거나 검증되지 않았다면 복제된 모든 자격 증명의 즉시 무효화를 보장할 수 없습니다.

### 3.3 아웃바운드 요청 방어

코드에는 일부 SSRF·사설망·리다이렉트 검사와 음악 도메인 허용 목록이 있습니다. 모든 업스트림·제3자 브라우저 요청이 프록시·정제·익명화된다는 뜻은 아닙니다. DiceBear에는 평문 이메일을 seed로 사용하는 아바타 URL 경로가 있습니다. Google Fonts·MV·커버 직접 연결은 해당 서비스에 IP를 노출할 수 있습니다. 일부 제공자는 HTTP이므로 전 구간 TLS라고 선언할 수 없습니다.

### 3.4 저장과 로그

1. 브라우저의 `auth`, `audio`, `library`, `global`, `settings`, `recommend`, IndexedDB는 기능별 데이터를 보관하며 로그아웃이 모든 기기 데이터를 자동 삭제하지는 않습니다.
2. 서버 행동 데이터가 가명 식별자로 연결되어도 다른 정보와 결합해 식별할 수 있습니다. 가명 처리는 익명화가 아니며 검색·레이더·제3자 데이터까지 포괄하지 않습니다.
3. 애플리케이션·Cloudflare·호스트·업스트림 로그와 백업의 실제 순환, 접근 권한, 만료 파기는 이번 대조에서 일괄 확인되지 않았습니다. 허구의 백업 기간이나 “제로 로그”를 기재해서는 안 됩니다.
4. 선택적 Meilisearch는 검색 원문·카탈로그를 처리할 수 있으며 Gorse 삭제가 로컬 삭제와 동기화되는지는 미확인입니다. 로컬 초기화 성공이 외부 추천·검색 저장소의 처리를 대신할 수는 없습니다.

### 3.5 알려진 한계

1. 개인화와 Auto DJ가 기본 활성화되어 입증 가능한 사전·별도·철회 가능한 선택이 부족합니다. 이는 동의가 아닙니다.
2. 공개 검색 제안은 검색 원문을 재이용해 개인정보·민감정보를 노출할 수 있습니다.
3. 삭제는 주로 현재 신원의 일부 이벤트이며 레이더·백업·로그·외부 서비스·Meilisearch·Gorse·과거 익명 식별자까지의 범위는 미확인입니다. 레이더의 내구성 있는 엔진 경로도 미확인이므로 저장 상태를 단정하지 않습니다.
4. 내부 평문 HTTP, Google Fonts, 직접 MV·커버 요청, 브라우저 User-Agent, DiceBear 평문 이메일 URL 때문에 “전 구간 TLS”나 “이메일 외부 전송 없음”은 부정확합니다.
5. 요청 제한·폐기·로그·제3자 스위치는 인스턴스 환경 변수와 공급업체 설정에 따릅니다. GDStudio는 코드상 미설정이면 활성화되나 환경·Compose에서 끌 수 있어 목록만으로 기본 비활성화라고 할 수 없습니다.

## 4. 개인정보 침해 대응

GDPR이 적용되면 보안 조치는 데이터 성격, 처리 규모, 구현 비용, 실제 위험에 비례해야 합니다(GDPR 제32조). 운영자는 모든 개인정보 침해를 기록하고, 개인의 권리·자유에 위험을 초래할 가능성이 낮은 경우를 제외하고 부당한 지체 없이 가능하면 인지 후 72시간 이내 관할 감독 기관에 통보하며 늦으면 이유를 설명해야 합니다(GDPR 제33조). 고위험이면 법정 예외 외에는 정보주체에게도 부당한 지체 없이 알려야 합니다(GDPR 제34조). 특정 국가 기관에 대한 자동 보고 약속이 아니며 다른 적용 법률도 면제하지 않습니다.

실제 대응에서는 영향을 받은 시스템을 격리하고 자격 증명을 보호·폐기하며 데이터 종류·범위·수신자·시간 흐름을 확인하고 판단과 시정을 기록해야 합니다. 의심 사건은 `privacy@epocanvas.com`으로 제출할 수 있습니다. 비밀번호, 완전한 토큰, 회원 Cookie, 불필요한 개인정보를 보내지 마십시오.

## 5. 설계와 기본값에 따른 데이터 보호

GDPR 제25조는 처리 수단을 정할 때 설계·기본값에 의한 보호를 고려하도록 요구합니다. 프로젝트는 현재 다음을 완전히 이행했다고 주장할 수 없습니다.

1. 선택적 프로파일링은 기본 비활성화하고 수락·거절·철회·기록을 동등하게 편리하게 제공해야 합니다. 현재 코드는 기본 활성화이며 로그인·계속 이용은 동의를 대신하지 못합니다.
2. 공개 검색 제안은 먼저 끄거나 최소 표시·필터·임계값·기간·삭제 통제를 구현해야 합니다.
3. 아바타 seed에 평문 이메일을 쓰지 않아야 합니다. Google Fonts·MV·커버 등 직접 리소스는 IP·Cookie·식별자 전송을 평가한 후 활성화해야 합니다.
4. 연결 가능한 과거 가명 식별자, 레이더, 검색, 공유 곡 정보와 커버, 로그, Meilisearch, Gorse와 백업을 확인하고 법에 따라 적용되는 삭제 범위를 처리하며, 해당하는 경우 수신자에게 통지해야 합니다. 법정 보존 예외의 이유, 범위와 기간을 설명해야 하며, 현재 신원의 일부 정리를 완전한 삭제로 가장해서는 안 됩니다.

## 6. 셀프 호스팅 운영자의 의무

셀프 호스팅 인스턴스는 독립 운영됩니다. 이 점검 안내는 실제 법률·라이선스를 넘는 계약 의무를 만들거나 작성자의 운영 약속을 구성하지 않습니다. GDPR 적용은 지역적 연결과 실제 활동으로 판단해야 하며(GDPR 제3조), 무료·개인 프로젝트라는 이유로 일괄 배제할 수 없습니다. 아래는 각 법정 조건이 충족되는 경우에만 적용됩니다.

1. 데이터 성격·규모·구현 비용·실제 위험에 비례한 조치를 취하고(GDPR 제32조) 전송·키·로그·복원·삭제를 검증합니다. 소규모 프로젝트에 전담팀이나 인증을 일률적으로 요구하지 않습니다.
2. 250명 미만이라고 처리 활동 기록이 자동 면제되지 않습니다. 처리가 비간헐적이거나 권리·자유를 위협할 수 있거나 특수 범주·형사 유죄판결·범죄 데이터를 포함하면 어느 하나만으로도 예외에서 제외될 수 있습니다(GDPR 제30조).
3. 데이터 보호 책임자는 공공기관, 핵심 활동의 대규모 정기적·체계적 모니터링, 특수 범주·형사 유죄판결·범죄 데이터의 대규모 처리 등 해당 조건에 따라 지정합니다(GDPR 제37조).
4. 데이터 보호 영향 평가는 높은 위험을 초래할 수 있는 활동을 처리 전에 평가하는 것이며 모든 해시·로그인·무료 프로젝트에 자동 필요한 것은 아닙니다(GDPR 제35조).
5. 역외 주체에 GDPR 제3조 제2항이 적용되면 보통 EU 대리인을 지정해야 합니다. 제27조의 간헐적 처리 예외는 간헐성, 특수 범주·형사 유죄판결·범죄 데이터의 대규모 처리 미포함, 성격·상황·범위·목적상 위험 가능성이 낮음을 모두 충족해야 합니다. 무료·비영리 자체는 예외가 아닙니다.
6. `SONIC_RECOMMEND_RETENTION_DAYS`, DB 경로, 메모리 폴백, 제3자 경로, 제한·폐기 스위치를 확인하고 실제 값을 자신의 고지·기간·삭제 절차에 반영합니다.
