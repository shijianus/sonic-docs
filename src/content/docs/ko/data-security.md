이 페이지는 Sonic 서비스(이하 「본 서비스」)의 데이터 수명 주기, 각 처리 활동의 성격, 보안 유지 조치, 알려진 한계와 데이터 유출 대응 절차를 설명합니다. 본 페이지는 [개인정보 처리방침](/ko/privacy-policy/) 10절의 전개입니다. 기술적 사실은 오픈 소스 코드의 실제 구현을 따르며 소스 코드 감사로 재확인할 수 있습니다.

| 이용 | 가명 처리 식별자로 연결된 통계 계산(추천, 인기도, 유사도). 사람의 검열이 없고 콘텐츠 심사도 하지 않으며 자동화 의사결정도 하지 않습니다 |
| 공유 | [제3자 공유 및 전송 목록](/ko/sub-processors/)을 참조하십시오. 판매하지 않고 광고 이용도 하지 않습니다 |
| 삭제 | 행동 이벤트는 90일 후 자동 파기(1,500회 기록마다와 기동 시점으로 정리를 트리거). 원클릭 삭제는 즉시 삭제하며 요청 제한 기록은 120초 후 만료 |

## 3. 보안 유지 조치

### 3.1 전송과 접속

1. 전 구간 암호화: 브라우저에서 엣지까지, 엣지에서 데이터 플레인까지 모두 TLS를 거칩니다. 데이터 플레인은 Cloudflare Tunnel 암호화 채널로 접속하며 공인망 포트를 직접 노출하지 않고 호스트 측에는 `127.0.0.1:8080`만 매핑합니다.
2. 서비스 간 검증: 데이터 플레인은 모든 `/api`, `/proxy`, `/palette` 라우트에 X-Sonic-Engine-Key 검증을 강제합니다. 엔진 측은 신뢰할 수 없는 입방 헤더를 제거하고 소켓 주소로 클라이언트 주소 헤더를 재구축하므로 위조는 일절 무효가 됩니다.
3. 저하 즉시 표시: 엣지 저하 모드에서는 응답 헤더에 `X-Sonic-Degraded: 1`을 표시하고 화면도 동시에 저하 안내를 보여주며 조용히 전환하지 않습니다.

### 3.2 인증과 키

1. OAuth 흐름: `state` 매개변수와 PKCE(S256)가 인가 코드 가로채기와 재전송을 방지합니다. 트랜잭션 쿠키의 유효 기간은 600초이고 `/api/auth` 경로로 한정됩니다. 콜백 시 state, PKCE, 인가 코드, 재전송을 검증하며 어느 하나라도 없거나 이상하면 일괄 거부합니다.
2. API Key: `sonic_live_v2` 버전 관리 형식에 HMAC-SHA256 서명. 서버는 Web Crypto `crypto.subtle.verify` 상수 시간 비교를 사용합니다. 버전, `kid`, `iat`/`exp`, `jti`를 엄격히 검사합니다. 서명 없는 키와 구버전 v1 키는 일괄 거부합니다(fail-closed). 발급 유효 기간은 30일, 검증 상한은 90일입니다. 키는 요청 헤더로만 전달되며 `?api_key=` 쿼리 매개변수 채널은 완전히 제거되어 키가 액세스 로그, 브라우저 기록, Referer로 유출되는 것을 막습니다.
3. 폐기 메커니즘: 로그아웃하면 현재 세션을 즉시 폐기합니다. `jti` 폐기 목록, 주체 폐기 목록, 전역 발급 시점 하한(`SONIC_REVOKED_JTIS`/`SONIC_REVOKED_SUBS`/`SONIC_TOKEN_MIN_IAT`)이 일괄 무효화를 지원합니다. KV를 바인딩하고 `SONIC_ENABLE_KEY_REVOCATION=1`을 켜면 즉시 폐기를 지원합니다. 즉시 폐기를 구성하지 않으면 관련 엔드포인트가 501을 반환하고 목록 방식의 사용을 안내하며, 폐기 성공을 가장하지 않습니다.
4. 세션 속성: `HttpOnly; Secure; SameSite=Lax`, 유효 기간 최대 30일. 로그인 콜백 리다이렉트는 `?auth=success` 상태 매개변수만 가지며 키를 회신하지 않습니다.

### 3.3 아웃바운드 요청 방어

1. SSRF 차단: 루프백 주소, RFC 1918 사설 네트워크, Docker 내부 브리지, 클라우드 메타데이터 주소(예: `169.254.169.254`)로의 아웃바운드 요청은 일괄 차단합니다. IPv4와 IPv6 이중 스택 검증을 적용하고, 리다이렉트 시마다 대상과 DNS 조회 결과를 다시 검증합니다.
2. 도메인 화이트리스트: 오디오, 커버, 포워딩 프록시는 관리되는 음악 CDN 도메인 목록(`SONIC_ALLOWED_MUSIC_DOMAINS`) 안의 HTTPS 대상과 표준 포트만 허용합니다.
3. 요청 정화: 업스트림 요청은 `Set-Cookie`와 자격 증명 헤더를 제거하고 고정 User-Agent, 대응 공식 사이트 Referer, 필요한 Range 헤더만 담습니다. 출구 IP는 배포자가 구성한 자리표시자 주소(기본값 RFC 5737 문서 주소)로 표시되며 어떤 사용자의 IP도 아닙니다.

### 3.4 저장과 로그

1. 가명 처리 저장: 행동 이벤트는 단방향 해시 식별자(`usr_`/`anon_` 접두어의 SHA-256 절취 값)로 연결되며 평문 이메일 열도 IP 열도 없습니다. 저장은 총 6개 테이블(곡 표준 데이터, 플랫폼 곡 매핑, 전문 인덱스, 행동 이벤트, 곡 공기, 검색어 집계)로 이루어지며 이 가운데 개인과 연관된 것은 행동 이벤트 테이블뿐입니다.
2. fail-closed 저장: 운영 환경에서 데이터베이스 열기에 실패하면 조용히 저하하는 대신 서비스를 거부합니다. 메모리 폴백은 개발 테스트 또는 명시적 구성 `SONIC_RECOMMEND_ALLOW_MEMORY_FALLBACK=1`에 한정됩니다.
3. 로그 최소화: 데이터 플레인 액세스 로그는 줄 단위 JSON이며 요청 식별자, 메서드, 경로, 상태 코드, 소요 시간만 포함합니다. 쿼리 문자열, IP, User-Agent, Cookie, Authorization, 요청 본문은 일절 기록하지 않습니다. 처리되지 않은 예외는 요청 식별자, 오류 이름, 절취된 메시지만 기록합니다. 로그는 Docker 표준 출력으로 가며 순환 정책은 호스트 Docker 구성을 따릅니다. Cloudflare Pages 측에는 본 프로젝트가 자체 구축한 전역 액세스 로그가 없습니다.
4. 백업: 데이터베이스 백업은 일관성 스냅샷(VACUUM INTO)과 무결성 검사를 함께 실행합니다. 백업 파일에는 가명 처리된 행동 데이터가 있으므로 운영 데이터와 동등한 수준으로 보호해야 합니다.
5. 컨테이너 격리: 데이터 플레인은 Docker 컨테이너 스택에서 실행되며 ncm-api 보조 컨테이너는 compose 내부 네트워크(`ncm-api:3000`)에서만 접근할 수 있고 공인망에 노출되지 않습니다. `.env` 구성 파일 권한은 600을 요구합니다.

### 3.5 알려진 한계

본 서비스는 오픈 소스 프로젝트이며 운영자는 다음 알려진 한계를 공개하고 지속적으로 개선합니다.

1. Cloudflare 네이티브 제한기에 묶이지 않은 배포 형태에서는 요청 제한이 KV 또는 프로세스 메모리 카운트로 이루어져 엄격한 전역 정밀 계산이 아닙니다.
2. DNS rebinding 방어가 완전히 해소되지 않았으므로 배포자는 네트워크 계층 조치를 함께 갖추어야 합니다.
3. `sonic_session` 쿠키에 서명 API Key가 포함되므로 쿠키 도용은 키 도용과 같습니다. 기기 보안과 신속한 로그아웃을 함께 해야 합니다.
4. SQLite는 단일 라이터 아키텍처이므로 동시 쓰기가 많은 배포 형태에 적합하지 않습니다.
5. 내장 Prometheus 지표 엔드포인트가 없으므로 모니터링은 로그와 외부 활성 확인에 의존해야 합니다.

위 한계의 전체 목록은 업스트림 저장소 `docs/OPERATIONS.md`에 있습니다. 셀프 호스팅 운영자는 자신의 배포 형태에 따라 평가해야 합니다.

## 4. 데이터 유출 대응

1. 내부 기록: 모든 개인 데이터 유출 사고를 기록합니다(GDPR 제33조 제5항). 저위험 평가를 이유로 기록을 면하지 않습니다.
2. 감독 기관 통보: 유출이 정보주체에게 위험을 초래할 수 있으면 알게 된 때부터 72시간 안에 운영자 소재지의 관할 감독 기관에 통보하고, 유출의 성격, 관련 데이터 범주와 수량, 가능한 결과, 이미 취한 조치를 설명합니다(GDPR 제33조 제1항, 제3항).
3. 정보주체 통지: 유출이 정보주체에게 고위험을 초래할 수 있으면 사이트 내 공지 등 유효한 방식으로 부당한 지연 없이 영향받는 정보주체에게 통지하고 유출의 성격과 권고 조치를 설명합니다(GDPR 제34조). 위험이 효과적으로 해소되어 고위험이 더 이상 없으면 통지를 면할 수 있으나 그 판단 사유는 기록해야 합니다.
4. 대응 조치: 영향받은 시스템을 즉시 격리하고, 영향받은 키와 세션을 폐기하며(`jti` 목록과 전역 발급 시점 하한 포함), 원인을 평가·수복하고, 조치 전 과정을 기록합니다.

## 5. 설계와 기본값에 반영된 데이터 보호

본 서비스는 설계 단계에서 다음 조치를 실현합니다(GDPR 제25조).

1. 가명 처리가 기본: 행동 이벤트는 수집 초기부터 해시 식별자로 연결되고 이메일 주소는 저장하지 않으며 데이터베이스에 IP 열이 없습니다.
2. 무수집 모드: 개인화가 꺼지면 이벤트가 저장되지 않고, 공개 모드에서는 서버에서 즉시 폐기하며 응답에 무시된 건수를 사실대로 표시합니다.
3. 최소 클라이언트 데이터: 추천 컨텍스트는 건수를 제한한 즐겨찾기, 최근 아티스트, 검색어만 가지며 메모리에서만 사용하고 저장하지 않습니다. 플레이어는 `document.cookie`를 읽고 쓰지 않으며 키는 localStorage에 들어가지 않습니다.
4. 기본 꺼짐의 고위험 경로: 제3자 애그리게이션 업스트림(GDStudio, Lyriva)과 유료 우회 경로는 기본적으로 엄격히 꺼져 있으며 배포자가 명시적으로 켜야(환경 변수를 1로 설정) 효력이 있습니다.
5. 원클릭 삭제: 삭제권은 셀프서비스 기능으로 직접 실현되어 수동 요청이 필요 없습니다. 「모든 로컬 데이터 삭제」는 서버 프로필, localStorage, sessionStorage, IndexedDB를 동시에 정리합니다.

## 6. 셀프 호스팅 운영자의 의무

본 서비스를 직접 배포한 시점부터 사용자는 자신의 사용자의 데이터 컨트롤러이며 다음 의무를 이행해야 합니다.

1. 고지 의무: 자신의 사용자에게 데이터 처리 사항을 고지합니다(본 사이트 [개인정보 처리방침](/ko/privacy-policy/)을 기초 문안으로 삼을 수 있습니다).
2. 처리 활동 기록: 처리 활동 기록을 유지합니다(GDPR 제30조).
3. 영향 평가: 처리가 고위험을 초래할 수 있으면 데이터 보호 영향 평가를 시행합니다(GDPR 제35조). 평가 범위는 최소한 익명 기기 식별자, 행동 이벤트, 요청 제한 IP의 잠시 사용, OAuth 이메일의 해시 파생을 포함합니다.
4. 구성 대조: 다음 매개변수가 자신의 정책 약속과 일치하는지 확인합니다. 행동 이벤트 보존 일수(`SONIC_RECOMMEND_RETENTION_DAYS`, 기본 90, 하한 7), 저장 경로(`SONIC_RECOMMEND_DB_PATH`, `memory`로 설정하면 저장 해제), 메모리 폴백 스위치(`SONIC_RECOMMEND_ALLOW_MEMORY_FALLBACK`), 제3자 경로 스위치(`SONIC_ENABLE_GDSTUDIO` 등), 요청 제한 매개변수(`SONIC_RATE_LIMIT_ANON_RPM`/`SONIC_RATE_LIMIT_AUTH_RPM`).
5. 보안 유지와 감독 수용: 3절의 조치로 구성하고(서비스 키 길이 32문자 이상, `.env` 권한 600, 데이터 플레인의 공인망 비노출 포함) 소재지 법률에 따라 관할 기관의 검사와 감독을 받습니다.

## 7. 감사 가능성

본 서비스의 보안 선언은 소스 코드로 검증할 수 있습니다. 전체 처리 논리, 스위치 기본값, 저장 구조와 로그 형태가 모두 오픈 소스 코드 저장소에 공개되어 있습니다. 업스트림 저장소에는 보안 감사 개선 기록(`docs/AUDIT_REMEDIATION.md`)과 운영 매뉴얼(`docs/OPERATIONS.md`)이 마련되어 있습니다. 본 사이트 문서의 기술적 사실은 버전 업데이트 때마다 대조하며, 소스 코드와 불일치를 발견하면 소스 코드를 우선하여 문서를 즉시 수정합니다.
