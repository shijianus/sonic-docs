**시행일: 2026년 11월 1일｜버전: 1.4**

이 페이지는 본 사이트 법률 문서에 쓰이는 법률 용어와 기술 용어를 정의합니다. 같은 용어는 모든 문서에서 같은 의미로 사용됩니다. 정의가 있으면 정의에 따라 해석하고, 정의가 없으면 통상의 의미를 따릅니다. 법률 용어는 EU 「일반 데이터 보호 규정」(GDPR)의 정의를 바탕으로 합니다.

![Sonic 용어 지도: 법률 용어족(GDPR 어휘)과 기술 용어족 두 족의 정의가 사이트 전체에서 일관되게 사용되며 간체 중국어판을 해석 기준으로 삼음](/images/sonic/key-terms-map.svg)

*그림: 본 사이트 용어의 두 족 구조. 법률 용어족은 GDPR 제4조의 정의에 고정되고, 기술 용어족은 소스 코드 구현을 따르며 버전 업데이트 때마다 대조합니다.*

## 1. 법률 용어

| 용어 | 정의 |
| --- | --- |
| 개인 데이터 | 식별되었거나 식별 가능한 자연인과 관련된 어떤 정보(GDPR 제4조 제1항). Sonic에서는 로그인 식별자, 행동 이벤트 기록 등 |
| 처리 | 개인 데이터에 행해지는 어떤 조작. 수집, 기록, 저장, 이용, 전송, 삭제 등을 포함합니다(GDPR 제4조 제2항) |
| 처리 제한 | 특정 상황에서 처리를 잠시 중단하되 데이터는 보존하는 상태(GDPR 제4조 제3항, 제18조) |
| 프로파일링 | 자동화 처리로 개인의 특성을 평가하고 그에 따라 의사결정이나 분석을 하는 행위(GDPR 제4조 제4항). 본 서비스는 추천 기능에 필요한 범위에서만 하며 원클릭으로 삭제할 수 있습니다 |
| 가명 처리 | 추가 정보가 있어야만 특정 당사자를 식별할 수 있는 방식으로 개인 데이터를 처리하는 것(GDPR 제4조 제5항). Sonic은 솔트한 SHA-256 절취 해시로 구현합니다 |
| 데이터 컨트롤러 | 처리 목적과 수단을 결정하는 자연인 또는 법인(GDPR 제4조 제7항). 호스팅 인스턴스는 운영 팀이고 셀프 호스팅 인스턴스는 배포자입니다 |
| 수탁 처리자 | 컨트롤러를 위해 개인 데이터를 처리하는 자연인 또는 법인(GDPR 제4조 제8항). 예: Cloudflare |
| 수취자 | 개인 데이터를 취득하는 자연인 또는 법인(GDPR 제4조 제9항). 제3자 여부는 무관합니다 |
| 제3자 | 당사자, 컨트롤러, 수탁 처리자, 처리 권한을 부여받은 자 이외의 주체(GDPR 제4조 제10항) |
| 동의 | 정보주체가 자유 의사와 명확한 인식 아래 행하는 긍정적 표시(GDPR 제4조 제11항, 제7조). 부여할 때보다 낮지 않은 편의로 언제든 철회할 수 있습니다 |
| 데이터 유출 | 개인 데이터가 우연 또는 불법적으로 파괴, 분실, 변조, 무단 공개, 무단 열람되게 한 보안 사고(GDPR 제4조 제12항) |
| 감독 기관 | 법에 따라 데이터 보호 의무 이행을 감독하는 공권력 기관(GDPR 제4조 제19항). EU 사용자는 자신 소재지의 감독 기관에 불만을 제기할 수 있습니다(GDPR 제77조) |
| 국제 전송 | EU와 유럽 경제 지역 밖의 제3국 또는 국제기구로의 개인 데이터 전송(GDPR 제5장) |
| 특수 범주 데이터 | 인종, 정치 견해, 건강, 성생활 등 민감한 속성을 드러내는 개인 데이터(GDPR 제9조). 본 서비스는 수집하지 않습니다 |
| 정보주체 | 개인 데이터로 식별되거나 식별 가능한 자연인(GDPR 제4조 제25항), 즉 사용자입니다 |

## 2. 기술 용어

| 용어 | 정의 |
| --- | --- |
| 컨트롤 플레인 | Cloudflare Pages Functions에서 실행되는 엣지 게이트웨이. 라우팅, 요청 제한, 캐시, 서킷 브레이커를 담당합니다 |
| 데이터 플레인 | 운영자의 자체 Linux 노드에서 실행되는 Docker Compose 스택. 프로토콜 파싱, 추천 계산, 저장을 담당합니다 |
| sonic-engine | 데이터 플레인의 메인 컨테이너(Node.js 22). 서비스 간 키 X-Sonic-Engine-Key 검증을 강제하며 호스트 측에는 루프백 주소만 바인딩합니다 |
| ncm-api sidecar | 내부망에 닫힌 NetEase 프로토콜 보조 컨테이너(`ncm-api:3000`). compose 내부 네트워크로만 접근할 수 있습니다 |
| OAuth 2.0 + PKCE | 인가 코드 방식에 코드 교환 증명(S256)을 더한 로그인 흐름. 본 서비스는 Epomail을 신원 제공자로 사용합니다 |
| API Key | `sonic_live_v2.<header>.<payload>.<signature>` 형식의 HMAC-SHA256 버전 관리 서명 키. 페이로드에는 `sub`/`iat`/`exp`/`jti`/`kid`/`role`/`uid`가 포함되며 요청 헤더로만 전달됩니다 |
| jti | API Key 페이로드의 키 식별자. 폐기 목록과 로그아웃 즉시 무효화에 사용됩니다 |
| fail-closed | 검증 실패 시 서비스를 거부하는 보안 정책. Sonic은 서명 없는 키, 구버전 키, 운영 환경 저장 장애에 모두 fail-closed를 적용합니다 |
| SSRF 방어 | 루프백 주소, RFC 1918 사설 네트워크, Docker 브리지, 클라우드 메타데이터 주소로의 아웃바운드 차단. IPv4/IPv6 이중 스택 검증과 리다이렉트 시 재검증을 적용합니다 |
| 도메인 화이트리스트 | 오디오, 커버, 포워딩 프록시는 관리되는 음악 CDN 도메인 목록(`SONIC_ALLOWED_MUSIC_DOMAINS`) 안의 HTTPS 대상만 허용합니다 |
| SQLite WAL | 데이터 플레인의 행동 이벤트와 엔티티 가중치 영구 저장소. Write-Ahead Logging 모드로 네임드 볼륨 `sonic-data`에 저장됩니다 |
| 서킷 브레이커 | 3상태 상태 머신(CLOSED/OPEN/HALF_OPEN). 연속 3회 실패 또는 4.5초 예산 초과로 차단에 진입하고 30초 냉각 후 활성 확인으로 복구합니다 |
| 엣지 저하 모드 | 데이터 플레인 오프라인 시 엣지 계층이 공개 가사와 검색 인터페이스에 직접 연결하는 재해 대응 상태. 응답 헤더에 `X-Sonic-Degraded: 1`을 표시하고 화면에 저하 안내를 보여줍니다 |
| 엣지 캐시 | `sonic:*`를 키로 하는 엣지 캐시. 신선도 유지 기간은 8분이며 만료 후 장애 연장 제공 상태로 전환됩니다 |
| Range 206 | HTTP 분할 로딩 메커니즘. 오디오 스트림은 기본적으로 엣지 프록시가 206 Partial Content로 응답합니다 |
| 직접 연결 모드 | `?mode=redirect`의 302 리다이렉트로 브라우저가 공식 CDN과 직접 연결을 맺습니다. 웹 플레이어는 사용하지 않습니다 |
| YRC/QRC/KRC | NetEase, QQ, KuGou의 글자 단위 가사 형식. 본 서비스는 그 암호화와 압축 캡슐(XOR + Deflate)을 네이티브 파싱합니다 |
| TTML | AMLL 글자 단위 가사의 타임라인 마크업 언어 형식 |
| LRCLIB | 글로벌 개방 싱크 가사 라이브러리. 로컬 가사가 없을 때의 보완 출처입니다 |
| 미리듣기 탐지 | 오디오 엔티티 길이와 메타데이터를 검사하여 공식 30초 미리듣기 절단본을 식별하고 표시로 명확히 밝히는 것 |
| 교차 소스 보완 | 미리듣기 곡이 트리거하는 교차 플랫폼 온전 곡 매칭 메커니즘. 기본 켜짐이며 매칭에 성공하면 대체 출처를 표시합니다 |
| 행동 이벤트 | 재생, 완주, 건너뛰기, 즐겨찾기, 거부 등 추천 신호 기록. 한 배치 최대 50건, 64 KB. 노이즈 이벤트(버퍼링, 미리듣기 절단 곡 전환)는 저장하지 않습니다 |
| 원클릭 프로필 삭제 | `DELETE /api/sonic/events`로 추천 엔진 안의 모든 행동 특징과 기록을 즉시 파기합니다 |
| 추천 프로필 개요 | `GET /api/sonic/events`가 반환하는 프로필 요약. 이벤트 총수, 좋아요와 거부 카운트, 자주 듣는 아티스트, 장르 성향, 최근 검색어, 저장 형태 |
| X-Sonic-Context | 추천 요청에 동봉되는 클라이언트 로컬 컨텍스트(건수를 제한한 즐겨찾기, 최근 아티스트, 최근 검색어). 메모리에서만 사용하고 저장하지 않습니다 |
| 노이즈 필터 | 서버가 6류 비사용자 원인 곡 전환(network_stall/playback_error/trial_end/stream_unavailable/buffer_timeout/auto_switch_error)의 가중치를 0으로 만들어 저장하지 않는 메커니즘 |

## 3. 해석 기준

1. 법률 용어의 해석은 GDPR 공식 문안을 기준으로 합니다. 기술 용어의 해석은 소스 코드 구현을 따르며, 소스 코드와 본 문서가 불일치하면 문서를 수정하고 코드 저장소에 Issue를 제기해야 합니다.
2. 본 사이트의 법률 문서는 간체 중국어 버전이 공식 버전입니다. 영어, 일본어, 한국어 버전에서 용어의 번역명은 본 페이지의 대응 관계를 따릅니다.
