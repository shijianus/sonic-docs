## 1. 프로젝트 포지셔닝

## 3. 기술 아키텍처 개요

### 3.1 컨트롤 플레인(Cloudflare 엣지)

컨트롤 플레인은 Cloudflare Pages와 Pages Functions에서 실행되며 다음 역할을 담당합니다.

1. 라우팅과 인증: API 요청의 통합 진입점으로서 인증 검사와 서명 키 검증을 수행합니다.
2. 단계별 요청 제한: 익명 요청은 분당 240회, 인증 요청은 분당 600회(기본값, 설정 가능)입니다. 인증 엔드포인트에는 분당 IP당 30회의 전용 요청 제한이 별도로 적용됩니다.
3. 다계층 캐시: `sonic:*`를 키로 하는 엣지 캐시로, 신선도 유지 기간은 8분이며 만료 후 장애 연장 제공 상태로 전환됩니다.
4. 3상태 서킷 브레이커: 연속 3회 실패 또는 호출이 4.5초 예산을 초과하면 OPEN 차단 상태로 진입하고, 이후 요청에서 이미 차단된 데이터 플레인을 기다리지 않고 엣지 대체 경로를 시도합니다(QQ·KuGou 공개 검색 인터페이스와 AMLL·LRCLIB). 실제 네트워크에는 지연이 있으며 지연이 0이거나 중단 없는 재생을 보장하지 않습니다. 30초 냉각 후 HALF_OPEN 활성 확인으로 전환하고 성공하면 다시 닫힙니다. 저하 기간에는 응답 헤더에 `X-Sonic-Degraded: 1`이 표시되고 플레이어 상단에 저하 안내 캡슐이 켜집니다.

### 3.2 데이터 플레인(Linux 프로토콜 엔진)

데이터 플레인은 운영자의 자체 Linux 노드 위에서 동작하는 Docker Compose 스택입니다.

| 구성 요소 | 설명 |
| --- | --- |
| sonic-engine 메인 컨테이너 | Node.js 22 HTTP 서비스로 8080 포트에서 수신하며, 호스트 측에는 `127.0.0.1`만 매핑됩니다. 모든 `/api`, `/proxy`, `/palette` 라우트에 서비스 간 키(X-Sonic-Engine-Key) 검증을 강제합니다 |
| ncm-api 보조 컨테이너 | NetEase 프로토콜 보조 서비스로 compose 내부 네트워크(`ncm-api:3000`)에서만 접근할 수 있으며 공인망에 노출되지 않습니다 |
| SQLite 3(WAL 모드) | 행동 이벤트와 엔티티 가중치의 영구 저장소로, 네임드 볼륨 `sonic-data`(컨테이너 내 `/app/data/sonic-recommend.sqlite`)에 저장됩니다. 백업은 일관성 스냅샷(VACUUM INTO)과 무결성 검사를 함께 실행합니다 |
| 네이티브 프로토콜 모듈 | 순수 TypeScript로 구현된 NetEase linuxapi/eapi, QQ, KuGou KRC, Kuwo 프로토콜 파싱 |

컨트롤 플레인과 데이터 플레인은 Cloudflare Tunnel 암호화 채널로 통신하며, 데이터 플레인은 공인망 포트를 직접 노출하지 않습니다.

### 3.3 오디오 스트림 경로

오디오는 기본적으로 엣지 프록시를 거치며 `Range`와 `206 Partial Content` 분할 로딩을 지원하고 `?mode=redirect`로 직접 연결을 요청할 수 있습니다. 프록시 경로는 상류에 프록시 IP를 보이게 할 수 있지만 브라우저 User-Agent가 전달될 수 있고 모든 연결을 익명화하지는 않습니다. Google Fonts, 이메일을 seed로 쓰는 DiceBear 아바타, MV·커버·댓글 이미지의 직접 요청은 외부에 IP와 연결 정보 또는 이메일을 전달할 수 있습니다. 일부 KuGou·Kuwo 상류 요청은 HTTP를 사용합니다. 자세한 수신자와 전송 범위는 [제3자 공유 및 전송 목록](/ko/sub-processors/)을 참조하십시오.

## 5. 스마트 추천 엔진

핵심 추천 엔진은 데이터 플레인에서 실행되며 선택적 외부 제공자와 레이더 동기화는 설정과 경로 이용 가능성에 달려 있습니다. 여기서 「로컬 엔진」은 사용자의 브라우저만을 뜻하지 않습니다. 곡 신호 가중치는 소스 코드에 공개되어 있으며 아티스트, 앨범, 플레이리스트와 MV 피드백도 있습니다.

| 신호 | 가중치 | 설명 |
| --- | --- | --- |
| favorite(즐겨찾기 추가) | +4.0 | 매우 강한 긍정 |
| replay(다시 재생) | +3.5 | 강한 긍정 |
| play_complete(유효 완주) | +2.5 | 표준 긍정 |
| play_progress(진도 청취) | +0.2 ~ +1.8 | 청취 비율에 따라 단계별 점수 |
| skip(빠른 건너뛰기) | -0.8 | 절반 이상 들은 뒤의 곡 전환은 +0.25 |
| dislike(명시적 거부) | -5.0 | 하드 필터 후 블랙리스트 등록 |

노이즈와 가짜 신호 정화: 네트워크 지연(network_stall), 디코딩 실패(playback_error), 미리듣기 절단(trial_end), 스트림 불가(stream_unavailable), 버퍼링 초과(buffer_timeout), 자동 전환 실패(auto_switch_error)로 인한 곡 전환은 가중치가 항상 0이며 저장되지 않습니다.

인기도 모델은 유효 재생(35%), 고유 청취자(25%), 완주 지표(20%), 즐겨찾기 전환(15%), 성장 기울기(5%)를 종합하고, 지수 시간 감쇠(24시간 급상승 차트와 7일 누적 인기 차트)와 베이지안·Wilson Score 평활을 보조로 사용합니다. 유사도 계산은 가수 관계 그래프와 오디오 특징 코사인을 융합하며, MMR 마진 관련성 재정렬로 정확성과 다양성의 균형을 맞춥니다. 세션 의도와 장기 신호에는 각각 가중치를 적용하지만 검색어를 전혀 보관하지 않는다는 뜻은 아닙니다. 개인화를 꺼도 독립적으로 집계된 검색 원문이 공개 검색 제안에 나타날 수 있습니다.

## 6. 보안 설계 개요

1. 인증: 확인한 코드에는 Epomail OAuth 인가 코드 방식과 `state`·PKCE(S256) 검증이 있습니다. OAuth 트랜잭션 쿠키의 기본 유효 기간은 약 600초입니다. 실제 인스턴스의 설정·동작을 보증하지는 않습니다.
2. API Key: RC는 `sonic_live_v2` 서명 자격 증명과 버전, 서명, 시간 및 설정된 폐기 검증을 구현합니다. 기본 발급 기간은 30일이며 검증기가 허용하는 최대 수명 90일은 기본 기간과 다릅니다. 서명은 암호화가 아니며 자격 증명을 URL, 로그나 공개 클라이언트에 넣어서는 안 됩니다. 실제 서비스의 설정과 폐기 전파는 여전히 확인해야 합니다.
3. 폐기: 로그아웃의 쿠키 정리와 서버 측 토큰 무효화는 다릅니다. jti·주체 목록, 발급 시점 하한 및 KV·폐기 스위치와 요청 성공 여부, 캐시 전파에 따라 복사된 토큰이 계속 유효할 수 있습니다.
4. 세션: `sonic_session`은 기본 30일의 HttpOnly·SameSite 쿠키이며 Secure 적용은 HTTPS 등 환경에 따릅니다. 사용자 ID·이메일·닉네임·아바타·역할은 `auth` localStorage에도 저장됩니다. 로컬 데이터 정리는 HttpOnly 쿠키 삭제나 로그아웃을 대신하지 않습니다.
5. SSRF 방어: RC는 내부 주소·메타데이터 주소와 리다이렉트 등을 검사하지만 적용 범위는 라우트에 따라 다릅니다. 모든 요청이 보호된다는 보장은 아니며 브라우저 직접 연결이나 모든 업스트림 HTTP를 포괄하지 않습니다. 코드의 존재만으로 모든 배포·요청 경로가 안전하다고 보증하지 말고 허용 대상과 실제 구성·실패 처리를 확인해야 합니다.

## 7. 프라이버시 설계 개요

1. 가명 처리: 이벤트는 이메일 파생 해시 또는 브라우저의 `anon_` 식별자와 연결됩니다. 해시는 추측·연결이 가능한 가명이지 되돌릴 수 없는 익명화가 아니며, 이메일은 세션과 `auth` localStorage에도 남을 수 있습니다.
2. 개인화 스위치: 개인화와 Auto DJ는 현재 기본으로 켜져 있지만 유효한 명시적 동의가 아닙니다. 개인화를 꺼도 독립적인 검색어 공개 재이용은 중단되지 않으며 모든 레이더 경로가 중단되는 것도 아닙니다. 유효한 근거가 없는 선택적 처리는 중단해야 합니다.
3. 삭제 한계: 초기화는 현재 신원의 일부 이벤트·피드백만 대상으로 하며 이전 익명 신원·레이더·검색 집계·외부 시스템·백업을 포괄하지 않습니다. 실패가 성공으로 표시될 수 있습니다. 로컬 데이터 삭제는 HttpOnly 쿠키를 지우거나 로그아웃하지 않으며 설정 초기화 후 개인화 기본값이 다시 켜질 수 있습니다. 완전한 원격 요청은 `privacy@epocanvas.com`으로 보내십시오.
4. 로그 최소화: 애플리케이션 접근 로그의 필드를 최소화하더라도 오류 로그, 호스트, 프록시와 제공자는 요청 자료를 처리할 수 있습니다. 원본 IP 요청 제한 키가 KV에 들어갈 수 있으며 클라이언트 주소도 엔진으로 전달될 수 있습니다.

프라이버시 약속의 전체 내용은 [개인정보 처리방침](/ko/privacy-policy/)에, 기술적 조치는 [데이터 처리 및 보안 유지](/ko/data-security/)에 있습니다.

## 8. 적합한 사용자와 그렇지 않은 사용자

적합: 자신의 Epomail 계정으로 로그인하고, 추천 프로필의 투명성과 삭제 가능성을 중시하는 개인 청취자. 멀티 소스 애그리게이션 검색과 글자 단위 가사가 필요한 헤비 리스너. Linux와 Docker 기초를 갖추고 운영자 책임을 스스로 질 준비가 된 셀프 호스팅 사용자.

부적합: 상업 음악 서비스의 라이선스 보장을 찾는 경우. 본 프로젝트는 음악 카탈로그 이용 허락을 제공하지 않으며 프록시·캐시·브라우저 저장소를 통한 관련 데이터 처리가 있을 수 있습니다. 어떤 콘텐츠 재라이선스도 부여하지 않습니다. 서비스 수준 협약(SLA)이나 상업 지원을 기대하는 팀. 「미리듣기 구간의 투명한 표시, 최선 노력 기반의 교차 소스 보완」을 받아들일 수 없는 사용자.

## 9. 콘텐츠와 저작권 경계

Sonic은 검색·프록시·재생 도구이며 다운로드와 가져온 파일은 기기에 저장될 수 있습니다. 녹음물·가사·커버·아티스트 이미지·MV·제3자 댓글의 권리는 각 권리자에게 있으며 프로젝트는 콘텐츠 이용 허락을 부여하지 않습니다. 배포자 계정의 `NETEASE_COOKIE`나 기술적으로 접근 가능한 인터페이스만으로 회원 콘텐츠의 공중 제공 권한이 생기지 않습니다. 현재 MV 댓글·답글·좋아요 작성은 로컬 시뮬레이션이고 실제 상류 게시가 아닙니다. 가져온 댓글에는 타인의 닉네임·아바타·ID·본문 등이 포함되어 공개 캐시에 저장될 수 있으며 익명 콘텐츠가 아닙니다.

본 서비스 이용 시 [허용 가능 사용 정책](/ko/acceptable-use/)을 준수해야 합니다. 배포자는 자신의 사용 시나리오가 현지 법률, 업스트림 서비스 약관, 콘텐츠 라이선스 요건에 부합하는지 스스로 확인해야 합니다.

## 10. 배포 형태

| 형태 | 구성 | 요점 |
| --- | --- | --- |
| Cloudflare Pages 엣지 게이트웨이 | 프런트엔드 SPA + Pages Functions | 빌드 후 `wrangler pages deploy`로 배포합니다. `SONIC_SECRET`, `SONIC_ENGINE_SECRET`, `SONIC_LOCAL_ENGINE_URL` 설정이 필요합니다 |

두 형태가 함께 완전한 서비스를 구성합니다. 엣지 게이트웨이만 배포하고 데이터 플레인이 없으면 서비스는 자동으로 엣지 저하 모드로 동작합니다. 환경 변수 전체 목록은 업스트림 저장소의 `.env.example`과 `docs/OPERATIONS.md`에 있습니다.

## 11. 품질 보장

소스와 검증 도구는 검토를 돕지만 안전성·적법성이나 실제 배포의 품질을 보증하지 않습니다. 이번 개정의 정적 검토와 미해결 사항은 `doc/sonic-source-audit-2026-11-02.md`에 기록되어 있으며, 문서 개정이 코드 문제를 해결했다는 뜻은 아닙니다.

1. 보안 감사와 개선: 업스트림 저장소에는 보안 감사 보고서(`SECURITY_AUDIT_REPORT.md`, `SECURITY_FIX_SUMMARY.md`)와 항목별 개선 기록(`docs/AUDIT_REMEDIATION.md`)이 마련되어 있으며, API 서명, OAuth 흐름, SSRF 방어, 프런트엔드 XSS 등을 다룹니다.
2. 자동화 테스트 게이트: 테스트 스위트는 게이트웨이 동작, 인증 호환성, SSRF 케이스, 로컬 엔진과 저하, 추천과 검색, 프런트엔드 XSS, 구성 일관성(config parity), 릴리스 P0/P1 게이트를 포괄하며 버전 릴리스에 맞춰 실행됩니다.
3. 문서 일관성 검증: 본 사이트는 자동화 스크립트로 세 가지를 검증합니다. 페이지 내 앵커와 이미지 참조의 깨진 링크 0건, 다국어 버전 구조의 1:1 대칭, GDPR 조 번호 인용과 검증 대장 화이트리스트의 일치입니다.
4. 사실 확인 절차: 지정된 소스 코드 버전과 실제 설정·데이터 흐름을 대조합니다. 소스 코드 검토는 수정 사항의 배포, 공급업체 계약이나 준법 상태를 입증하지 않으며 잘못된 고지의 책임을 면제하지도 않습니다. 모순을 바로잡고 영향을 받는 사용자에게 알려야 합니다.

## 12. 자주 묻는 질문

**본 서비스는 유료인가요? 광고가 있나요?**
개인이 유지하는 무료·비영리 테스트 프로젝트이며 광고와 인앱 결제가 없습니다. 비영리라는 성격이 데이터 보호나 소비자에 대한 의무를 면제하지는 않습니다.

**로그인 없이 이용할 수 있나요?**
가능합니다. 검색, 재생, 가사와 차트 등의 핵심 기능은 로그인 없이 이용할 수 있지만 비로그인이 익명과 같지는 않습니다. 로그인은 기기 간 클라우드 동기화를 보장하지 않으며 연령이나 프로파일링 동의의 증거도 아닙니다.

**내 데이터는 어디에 저장되나요?**
즐겨찾기, 플레이리스트와 선호는 주로 브라우저 저장소에 보관되며 이메일과 아바타 정보는 `auth`에 저장될 수 있습니다. 음악 파일 본체와 내장 커버는 IndexedDB에 있지만 내장 커버 이미지도 즐겨찾기 이벤트와 함께 원격 곡목 카탈로그에 들어갈 수 있으므로 기기에만 남는다고 보장할 수 없습니다. 메타데이터, 피드백과 추천 맥락은 전송될 수 있으며 원격 자료에는 레이더 프로필과 검색 통계도 있습니다. RC 행동 이벤트의 기본 보존 기간은 90일, 최소 7일이지만 정리·삭제 범위가 불완전하여 전면 자동 삭제를 약속하지 않습니다. [개인정보 처리방침](/ko/privacy-policy/) 4·6절을 참조하십시오.

**내 행동 프로필은 어떻게 삭제하나요?**
설정의 초기화나 `DELETE /api/sonic/events`는 현재 신원의 일부 이벤트·피드백 삭제를 시도합니다. 원격 실패가 숨겨질 수 있으며 이전 익명 신원·레이더·검색 집계·외부 서비스·백업까지 지우지 않습니다. 로컬 삭제도 서버 전체 삭제나 로그아웃이 아닙니다. 완전한 원격 요청은 `privacy@epocanvas.com`으로 보내십시오([인터페이스 및 기능 안내](/ko/interface/) 9절 참조).

**추천이 저를 추적하나요?**
추천은 익명 자료가 아니라 가명 처리된 행동 프로필을 사용합니다. 개인화와 Auto DJ는 기본으로 켜져 있지만 유효한 동의가 아닙니다. 개인화를 꺼도 독립적인 검색어 집계와 공개 검색 제안 가능성은 중단되지 않습니다. 시크릿 모드도 네트워크 요청이나 이벤트를 막지 않습니다.

**어떤 곡은 30초뿐인 이유는 무엇인가요?**
그것은 공식 플랫폼의 미리듣기 절단본입니다. 플레이어는 미리듣기 표시로 사실대로 표기하며 절대 온전한 곡처럼 보이게 하지 않습니다. 교차 소스 보완을 켜면 무료 온전 곡 매칭을 자동으로 시도하고 출처를 표시합니다.

**음질 배지를 신뢰할 수 있나요?**
배지는 확인 가능한 스트림·메타데이터를 표시하는 기능이지 무오류 보증이 아닙니다. 실제 음질과 가용성은 상류 자원에 따라 달라집니다([이용약관](/ko/terms-of-service/) 4절 참조).

**직접 배포하면 어떤 책임이 있나요?**
실제 처리 목적과 수단을 결정하는 운영자가 해당 역할의 의무를 부담합니다. GDPR 적용은 제3조에 따라 판단하며 전 세계 사용자에 대한 일괄 계약 보장이 아닙니다. 제30조의 기록 의무는 소규모라는 이유로 자동 면제되지 않고, 제35조의 DPIA·제37조의 DPO·제27조의 EU 대표는 각각 적용 요건을 확인해야 합니다. 노드 국가·컨트롤러 신원·계약과 이전 근거를 추정하지 말고 실제로 확인하십시오([오픈 소스와 셀프 호스팅 법률](/ko/open-source/) 참조).

**본 서비스는 어떤 언어를 지원하나요?**
플레이어에는 간체 중국어, English, 日本語가 내장되어 있습니다. 본 사이트 문서는 10개 언어 버전을 제공합니다.
