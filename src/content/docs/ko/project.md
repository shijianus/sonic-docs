## 1. 프로젝트 포지셔닝

Sonic은 독자 개발된 멀티 소스 음악 스트리밍 플랫폼이자 애그리게이션 게이트웨이로, 「Cloudflare 엣지 컨트롤 플레인 + Linux 로컬 프로토콜 엔진 데이터 플레인」의 2계층 아키텍처로 동작하며, 고음질 스트리밍, 밀리초 단위 글자 단위 가사, 스스로 통제할 수 있는 추천 경험을 위해 만들어졌습니다. 본 프로젝트는 오픈 소스 소프트웨어로 소스 코드가 공개되어 있어 누구나 직접 배포할 수 있습니다.

## 3. 기술 아키텍처 개요

### 3.1 컨트롤 플레인(Cloudflare 엣지)

컨트롤 플레인은 Cloudflare Pages와 Pages Functions에서 실행되며 다음 역할을 담당합니다.

1. 라우팅과 인증: API 요청의 통합 진입점으로서 인증 검사와 서명 키 검증을 수행합니다.
2. 단계별 요청 제한: 익명 요청은 분당 240회, 인증 요청은 분당 600회(기본값, 설정 가능)입니다. 인증 엔드포인트에는 분당 IP당 30회의 전용 요청 제한이 별도로 적용됩니다.
3. 다계층 캐시: `sonic:*`를 키로 하는 엣지 캐시로, 신선도 유지 기간은 8분이며 만료 후 장애 연장 제공 상태로 전환됩니다.
4. 3상태 서킷 브레이커: 연속 3회 실패 또는 호출이 4.5초 예산을 초과하면 OPEN 차단 상태로 진입하고, 이후 요청은 0ms에 즉시 엣지 직접 연결 대체(QQ·KuGou 공개 검색 인터페이스와 AMLL·LRCLIB)로 전환됩니다. 30초 냉각 후 HALF_OPEN 활성 확인으로 전환하고 성공하면 다시 닫힙니다. 저하 기간에는 응답 헤더에 `X-Sonic-Degraded: 1`이 표시되고 플레이어 상단에 저하 안내 캡슐이 켜집니다.

### 3.2 데이터 플레인(Linux 프로토콜 엔진)

데이터 플레인은 운영자의 자체 Linux 노드 위에서 동작하는 Docker Compose 스택입니다.

| 구성 요소 | 설명 |
| --- | --- |
| sonic-engine 메인 컨테이너 | Node.js 22 HTTP 서비스로 8080 포트에서 수신하며, 호스트 측에는 `127.0.0.1`만 매핑됩니다. 모든 `/api`, `/proxy`, `/palette` 라우트에 서비스 간 키(X-Sonic-Engine-Key) 검증을 강제합니다 |
| ncm-api 보조 컨테이너 | NetEase 프로토콜 보조 서비스로 compose 내부 네트워크(`ncm-api:3000`)에서만 접근할 수 있으며 공인망에 노출되지 않습니다 |
| SQLite 3(WAL 모드) | 행동 이벤트와 엔티티 가중치의 영구 저장소로, 네임드 볼륨 `sonic-data`(컨테이너 내 `/app/data/sonic-recommend.sqlite`)에 저장됩니다. 백업은 일관성 스냅샷(VACUUM INTO)과 무결성 검사를 함께 실행합니다 |
| 네이티브 프로토콜 모듈 | 순수 TypeScript로 구현된 NetEase linuxapi/eapi, QQ, KuGou KRC, Kuwo 프로토콜 파싱 |

컨트롤 플레인과 데이터 플레인은 Cloudflare Tunnel 암호화 채널로 통신하며, 데이터 플레인은 공인망 포트를 직접 노출하지 않습니다.

### 3.3 오디오 스트림 경로

오디오 스트림은 기본적으로 엣지 프록시(동일 출처 바이트 범위 프록시)를 통해 공식 CDN에서 가져오며, HTTP `Range`와 `206 Partial Content` 분할 로딩을 지원합니다. 업스트림 CDN에는 프록시 서버의 주소만 보이고 클라이언트 IP에는 접촉하지 않습니다. `?mode=redirect`의 302 직접 연결 모드는 명시적으로 호출하는 API 사용자에게만 제공되며(웹 플레이어는 사용하지 않음), 직접 연결 모드에서는 사용자의 브라우저가 공식 CDN과 직접 연결을 맺습니다.

## 5. 스마트 추천 엔진

추천 엔진은 데이터 플레인 로컬에서만 실행되며, 행동 신호 가중치는 소스 코드에 공개되어 있습니다.

| 신호 | 가중치 | 설명 |
| --- | --- | --- |
| favorite(즐겨찾기 추가) | +4.0 | 매우 강한 긍정 |
| replay(다시 재생) | +3.5 | 강한 긍정 |
| play_complete(유효 완주) | +2.5 | 표준 긍정 |
| play_progress(진도 청취) | +0.2 ~ +1.8 | 청취 비율에 따라 단계별 점수 |
| skip(빠른 건너뛰기) | -0.8 | 절반 이상 들은 뒤의 곡 전환은 +0.25 |
| dislike(명시적 거부) | -5.0 | 하드 필터 후 블랙리스트 등록 |

노이즈와 가짜 신호 정화: 네트워크 지연(network_stall), 디코딩 실패(playback_error), 미리듣기 절단(trial_end), 스트림 불가(stream_unavailable), 버퍼링 초과(buffer_timeout), 자동 전환 실패(auto_switch_error)로 인한 곡 전환은 가중치가 항상 0이며 저장되지 않습니다.

인기도 모델은 유효 재생(35%), 고유 청취자(25%), 완주 지표(20%), 즐겨찾기 전환(15%), 성장 기울기(5%)를 종합하고, 지수 시간 감쇠(24시간 급상승 차트와 7일 누적 인기 차트)와 베이지안·Wilson Score 평활을 보조로 사용합니다. 유사도 계산은 가수 관계 그래프와 오디오 특징 코사인을 융합하며, MMR 마진 관련성 재정렬로 정확성과 다양성의 균형을 맞춥니다. 세션 단위 검색 의도와 장기 선호는 계층적으로 분리되어, 완주와 즐겨찾기 등 고가치 행동만 장기 프로필에 축적됩니다.

## 6. 보안 설계 개요

1. 인증: Epomail OAuth 2.0 인가 코드 방식. `state` 매개변수와 PKCE(S256)로 인가 코드 가로채기와 재전송을 방지합니다. OAuth 트랜잭션 쿠키의 유효 기간은 600초입니다.
2. API Key: `sonic_live_v2.<header>.<payload>.<signature>` 버전 관리 형식에 HMAC-SHA256 서명. 페이로드에는 `sub`/`iat`/`exp`/`jti`/`kid`/`role`/`uid`가 포함됩니다. 발급 유효 기간은 30일, 검증 상한은 90일입니다. 서버는 Web Crypto 상수 시간 비교를 사용하며, 서명 없는 키와 구버전 키는 일괄 거부합니다(fail-closed). 키는 `X-Sonic-Key` 또는 `Authorization` 요청 헤더로만 전달되고 URL 쿼리 매개변수 채널은 완전히 제거되었습니다.
3. 폐기: 로그아웃하면 현재 세션과 키 식별자(jti)를 즉시 폐기합니다. jti 폐기 목록, 주체(sub) 폐기 목록, 전역 발급 시점 하한을 지원하며, KV 바인딩 시 즉시 폐기를 지원합니다.
4. 세션: `HttpOnly; Secure; SameSite=Lax` 속성의 `sonic_session` 쿠키로 유효 기간은 최대 30일입니다. 키는 URL, localStorage 또는 페이지 스크립트가 닿을 수 있는 곳에 기록하지 않습니다.
5. SSRF 방어: 루프백 주소, RFC 1918 사설 네트워크, Docker 내부 브리지, 클라우드 메타데이터 주소(예: `169.254.169.254`)로의 아웃바운드 요청은 일괄 차단합니다. IPv4와 IPv6 이중 스택 검증을 적용하고, 리다이렉트 시마다 대상과 DNS 조회 결과를 다시 검증합니다.

## 7. 프라이버시 설계 개요

1. 가명 처리가 기본: 행동 이벤트는 수집 초기부터 단방향 해시 식별자로 연결되며, 이메일 주소는 저장하지 않습니다.
2. 개인화 자유 스위치: 플레이어 설정에서 언제든 개인화를 끌 수 있습니다. 끄면 이벤트가 저장되지 않고, 공개 모드에서는 즉시 폐기됩니다.
3. 원클릭 삭제: 설정 페이지의 「추천 프로필 삭제」로 서버의 모든 행동 이벤트를 즉시 파기하고, 「모든 로컬 데이터 삭제」로 브라우저 로컬 저장소와 IndexedDB를 즉시 지웁니다.
4. 로그 최소화: 데이터 플레인 액세스 로그에는 경로, 메서드, 상태 코드, 소요 시간만 포함됩니다.

프라이버시 약속의 전체 내용은 [개인정보 처리방침](/ko/privacy-policy/)에, 기술적 조치는 [데이터 처리 및 보안 유지](/ko/data-security/)에 있습니다.

## 8. 적합한 사용자와 그렇지 않은 사용자

적합: 자신의 Epomail 계정으로 로그인하고, 추천 프로필의 투명성과 삭제 가능성을 중시하는 개인 청취자. 멀티 소스 애그리게이션 검색과 글자 단위 가사가 필요한 헤비 리스너. Linux와 Docker 기초를 갖추고 운영자 책임을 스스로 질 준비가 된 셀프 호스팅 사용자.

부적합: 상업 음악 서비스의 라이선스 보장을 찾는 경우. 본 프로젝트는 음악을 저장하거나 호스팅하지 않으며 어떤 콘텐츠 재라이선스도 부여하지 않습니다. 서비스 수준 협약(SLA)이나 상업 지원을 기대하는 팀. 「미리듣기 구간의 투명한 표시, 최선 노력 기반의 교차 소스 보완」을 받아들일 수 없는 사용자.

## 9. 콘텐츠와 저작권 경계

Sonic은 검색, 애그리게이션, 재생 도구이며 어떤 음악 파일도 저장하거나 호스팅하지 않습니다. 녹음물, 가사, 커버, 아티스트 이미지 등 콘텐츠의 권리는 각 권리자에게 귀속됩니다. 본 프로젝트는 어떤 음악 콘텐츠의 재라이선스도 부여하지 않습니다. 합법 회원 곡은 배포자가 자신의 라이선스 자격 증명으로 마운트하고(예: `NETEASE_COOKIE`, 최종 사용자가 아닌 배포자의 계정), 공개 곡은 공식 개방 프로토콜을 따릅니다.

본 서비스 이용 시 [허용 가능 사용 정책](/ko/acceptable-use/)을 준수해야 합니다. 배포자는 자신의 사용 시나리오가 현지 법률, 업스트림 서비스 약관, 콘텐츠 라이선스 요건에 부합하는지 스스로 확인해야 합니다.

## 10. 배포 형태

| 형태 | 구성 | 요점 |
| --- | --- | --- |
| Cloudflare Pages 엣지 게이트웨이 | 프런트엔드 SPA + Pages Functions | 빌드 후 `wrangler pages deploy`로 배포합니다. `SONIC_SECRET`, `SONIC_ENGINE_SECRET`, `SONIC_LOCAL_ENGINE_URL` 설정이 필요합니다 |
| Linux 로컬 프로토콜 엔진 | sonic-engine + ncm-api + SQLite | `docker compose up -d --build`로 배포합니다. `.env` 권한은 600이며 Cloudflare Tunnel로 연결합니다 |

두 형태가 함께 완전한 서비스를 구성합니다. 엣지 게이트웨이만 배포하고 데이터 플레인이 없으면 서비스는 자동으로 엣지 저하 모드로 동작합니다. 환경 변수 전체 목록은 업스트림 저장소의 `.env.example`과 `docs/OPERATIONS.md`에 있습니다.

## 11. 품질 보장

본 프로젝트는 감사 가능성과 자동화 검증으로 품질을 보장합니다.

1. 보안 감사와 개선: 업스트림 저장소에는 보안 감사 보고서(`SECURITY_AUDIT_REPORT.md`, `SECURITY_FIX_SUMMARY.md`)와 항목별 개선 기록(`docs/AUDIT_REMEDIATION.md`)이 마련되어 있으며, API 서명, OAuth 흐름, SSRF 방어, 프런트엔드 XSS 등을 다룹니다.
2. 자동화 테스트 게이트: 테스트 스위트는 게이트웨이 동작, 인증 호환성, SSRF 케이스, 로컬 엔진과 저하, 추천과 검색, 프런트엔드 XSS, 구성 일관성(config parity), 릴리스 P0/P1 게이트를 포괄하며 버전 릴리스에 맞춰 실행됩니다.
3. 문서 일관성 검증: 본 사이트는 자동화 스크립트로 세 가지를 검증합니다. 페이지 내 앵커와 이미지 참조의 깨진 링크 0건, 다국어 버전 구조의 1:1 대칭, GDPR 조 번호 인용과 검증 대장 화이트리스트의 일치입니다.
4. 사실 확인 절차: 본 사이트의 모든 데이터 처리 사실은 버전 업데이트 때마다 소스 코드(`.env.example`, `server/recommend-sqlite.ts`, `functions/_lib/sonic/security.ts` 등)와 대조하여 갱신합니다. 소스 코드와 불일치하면 소스 코드를 우선하여 문서를 즉시 수정합니다.

## 12. 자주 묻는 질문

**본 서비스는 유료인가요? 광고가 있나요?**
무료이며 광고와 인앱 결제가 없습니다. 호스팅 인스턴스의 운영 비용은 운영 팀이 부담합니다. 본 서비스는 광고 목적의 데이터를 수집하지 않습니다.

**로그인 없이 이용할 수 있나요?**
가능합니다. 검색, 재생, 가사, 순위 차트 등 핵심 기능은 익명으로 이용할 수 있습니다(요청 제한은 더 엄격합니다). 로그인하면 즐겨찾기 클라우드 동기화, 개인화 추천, Auto DJ가 열립니다.

**내 데이터는 어디에 저장되나요?**
세 곳입니다. 즐겨찾기, 플레이리스트, 플레이어 설정은 브라우저의 로컬 저장소에, 다운로드와 로컬 음악은 브라우저의 IndexedDB에 저장됩니다. 서버에는 가명 처리된 행동 이벤트만 저장되며 90일 후 자동 파기됩니다. 이메일 주소는 저장하지 않습니다. 자세한 내용은 [개인정보 처리방침](/ko/privacy-policy/) 4절을 참조하십시오.

**내 행동 프로필은 어떻게 삭제하나요?**
설정 → 프라이버시와 로컬 데이터 → 「추천 프로필 및 관심 없음 기록 초기화」를 실행하거나 `DELETE /api/sonic/events`를 직접 호출하면 즉시 적용됩니다. 「모든 로컬 데이터 삭제」는 브라우저와 서버 데이터를 동시에 지웁니다. 화면 위치는 [인터페이스 및 기능 안내](/ko/interface/) 9절을 참조하십시오.

**추천이 저를 추적하나요?**
추천은 재생 순서 정렬에만 쓰이며 교차 사이트 추적도 광고 프로필도 없습니다. 개인화는 언제든 끌 수 있고, 끄면 순수 공개 모드로 전환되어 더 이상 어떤 이벤트도 기록하지 않습니다.

**어떤 곡은 30초뿐인 이유는 무엇인가요?**
그것은 공식 플랫폼의 미리듣기 절단본입니다. 플레이어는 미리듣기 표시로 사실대로 표기하며 절대 온전한 곡처럼 보이게 하지 않습니다. 교차 소스 보완을 켜면 무료 온전 곡 매칭을 자동으로 시도하고 출처를 표시합니다.

**음질 배지를 신뢰할 수 있나요?**
신뢰할 수 있습니다. 배지는 현재 오디오 스트림의 실제 등급을 반영하며, 업스트림 등급이 바뀌면 실시간으로 따라가고 허위 표시를 하지 않습니다([이용약관](/ko/terms-of-service/) 4절 3항 참조).

**직접 배포하면 어떤 책임이 있나요?**
직접 배포한 시점부터 사용자는 해당 인스턴스의 데이터 컨트롤러입니다. 자신의 사용자에게 고지 의무를 이행하고, 처리 기록을 유지하며, 필요시 영향 평가를 시행하고 보안 유지를 실천해야 합니다. 시작점은 [데이터 처리 및 보안 유지](/ko/data-security/) 6절을 참조하십시오.

**본 서비스는 어떤 언어를 지원하나요?**
플레이어에는 간체 중국어, English, 日本語가 내장되어 있습니다. 본 사이트 문서는 10개 언어 버전을 제공합니다.
