Sonic 검색의 기능과 규칙을 정리합니다. 설명은 2026-11-02에 검토한 공개 후보 브랜치(RC) `rc/sonic-20261031@a75f5cb`(2026-11-01 UTC)에 근거합니다. 이전 `main@ce443c8`(2026-10-27 UTC)과는 구현이 다르므로 같은 검색·통계 처리를 가정할 수 없습니다. RC는 정식 GitHub Release가 아니며 실제 서비스 버전과 설정은 알 수 없습니다. 화면의 위치는 [인터페이스 및 기능 안내](/ko/interface/) 2절을 참조하십시오.

무엇을 입력할 수 있는지, 표기 차이를 어떻게 보정하는지, 결과를 어떻게 구성하는지를 설명합니다.

## 1. 검색 범위

검색 대상은 곡, 가수, 앨범, 플레이리스트의 네 가지입니다. 결과 페이지는 「곡/플레이리스트/MV」 세 탭으로 구성됩니다. 사이드바 상단과 검색 페이지에서는 사이트 내 인기 검색어가 제안될 수 있습니다.

| 버전 식별 | 스튜디오 버전, 라이브 버전, 커버 등으로 구분될 수 있음 | 결과에 표시된 버전 정보를 확인 |

## 3. 다중 소스 병렬 검색과 중복 제거

검색 요청은 당시 활성화되어 이용 가능한 업스트림 소스에 전송되고 정규화 규칙에 따라 결과를 병합합니다. 같은 곡명과 같은 곡을 가리키는 여러 소스의 기록은 하나의 결과로 합쳐질 수 있으며, 재생할 때 이용 가능한 재생 주소를 가져옵니다. 업스트림 소스 목록과 기본 스위치는 [제3자 공유 및 전송 목록](/ko/sub-processors/) 3절에 있습니다.

## 4. 결과 조작

곡 목록의 각 행에는 재생, MV 진입(있는 경우), 즐겨찾기, 다운로드 및 기타 작업이 표시될 수 있습니다. 상단의 「전체 재생」은 결과 순서대로 연속 재생할 수 있습니다. 플레이리스트 결과는 플레이리스트 상세 페이지로, MV 결과는 MV 목록으로 이동하며 실제 작업은 결과와 인스턴스 설정에 따릅니다.

## 5. 검색과 프라이버시

검색어는 다음과 같이 처리합니다.

1. **로컬**: 최근 검색어는 브라우저 localStorage에 저장될 수 있지만 검색을 위해 전송되며 일부 기록이 추천 요청에 포함될 수 있습니다. 로컬 기록을 지워도 이미 생성된 원격 사본은 삭제되지 않습니다;
2. **서버 집계**: 스마트 검색은 원문을 별도로 집계하거나 보관하고 공개 검색 제안에 표시할 수 있습니다. 개인화를 꺼도 이 경로가 없다고 볼 수 없습니다. 계정 식별자가 없어도 개인을 식별할 수 있으므로 개인 정보나 민감한 내용을 입력하지 마십시오. 실제 필터, 표시 기준, 보존 관리와 인스턴스 설정은 별도로 확인해야 합니다;
3. **개인화**: 검색과 클릭 신호가 가명 식별자와 연결될 수 있습니다. 개인화 스위치는 모든 검색 통계 경로를 제어하지 않습니다. 90일 설정이나 초기화 기능도 모든 검색 집계와 사본이 같은 일정으로 삭제된다는 뜻이 아닙니다.
