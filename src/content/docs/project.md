## 1. 专案定位

Sonic 是一套独立研发的多源音乐串流平台与聚合闸道，以「Cloudflare 边缘控制面 + Linux 本地协议引擎数据面」双层架构运行，专为高音质串流、毫秒级逐字歌词与自主可控的推荐体验而建。专案为开源软体，源代码公开发布，任何人得自行部署。

| 项目 | 说明 |
| --- | --- |
| 托管实例 | `sonic.epocanvas.tech`（主站）与 `sonic.epocanvas.com`（备用镜像），由运营团队运行 |
| 自行部署实例 | 任何个人或组织依开源代码部署于自有服务器之私有实例；部署者即为该实例之运营者与数据控制者 |
| 源码授权 | 以仓库根目录 `LICENSE` 文件为准（MIT License）；专案定位为非商业开源专案，历史 README 曾声明 CC BY-NC-SA 4.0 意图，维护者裁决前以 `LICENSE` 文件为准；商标与品牌标识不随源码授权 |
| 登录方式 | Epomail OAuth 2.0（PKCE），本专案不设独立注册系统 |
| 软体组成 | Cloudflare Pages 前端与边缘函数（控制面）、Node.js 22 本地引擎与 ncm-api 辅助容器（数据面）、Vue 3 网页播放器 |

## 3. 技术架构概览

### 3.1 控制面（Cloudflare 边缘）

控制面运行于 Cloudflare Pages 与 Pages Functions，承担以下职责：

1. **路由与认证**：API 请求之统一入口，认证检查与签名金钥验证；
2. **分级限流**：匿名请求每分钟 240 次、认证请求每分钟 600 次（缺省值，可配置），认证端点另有每分钟每 IP 30 次之专用限流；
3. **多层级缓存**：以 `sonic:*` 为键之边缘缓存，新鲜期 8 分钟，过期后进入容灾延长状态；
4. **三态熔断器**：连续 3 次失败或调用超过 4.5 秒预算即进入 OPEN 熔断，后续请求 0ms 立即改走边缘直连兜底（QQ／酷狗公开检索接口与 AMLL／LRCLIB）；冷却 30 秒后进入 HALF_OPEN 探活，成功后闭合。降级期间响应标头标明 `X-Sonic-Degraded: 1`，播放器顶部亮起降级提示胶囊。

### 3.2 数据面（Linux 协议引擎）

数据面为运营者自有 Linux 节点上之 Docker Compose 堆叠：

| 组件 | 说明 |
| --- | --- |
| sonic-engine 主容器 | Node.js 22 HTTP 服务，监听 8080 端口，宿主侧仅映射 `127.0.0.1`；全部 `/api`、`/proxy`、`/palette` 路由强制验证服务间密钥（X-Sonic-Engine-Key） |
| ncm-api 辅助容器 | 网易云协议辅助服务，仅于 compose 内部网络可达（`ncm-api:3000`），不经公网暴露 |
| SQLite 3（WAL 模式） | 行为事件与实体权重之持久化存储，落于命名卷 `sonic-data`（容器内 `/app/data/sonic-recommend.sqlite`）；备份以一致性快照（VACUUM INTO）配合完整性检查执行 |
| 原生协议模块 | 纯 TypeScript 实现之网易 linuxapi/eapi、QQ、酷狗 KRC、酷我协议解析 |

控制面与数据面之间经 Cloudflare Tunnel 加密通道通信，数据面不直接暴露公网端口。

### 3.3 音频流路径

音频流默认经边缘代理（同源字节范围代理）自官方 CDN 拉取，支持 HTTP `Range` 与 `206 Partial Content` 分段加载：上游 CDN 仅见代理服务器之地址，不接触客户端 IP。`?mode=redirect` 之 302 直连模式仅为显式调用之 API 使用者提供（网页播放器不使用）；直连模式下您的浏览器与官方 CDN 直接建立连接。

## 4. 音源与歌词链路

| 来源 | 占比定位 | 状态 |
| --- | --- | --- |
| 本地原生解析（网易／QQ／酷狗／酷我官方接口 + ncm-api） | 主链路（逾 90%） | 默认启用 |
| AMLL TTML 逐字歌词 + LRCLIB 同步歌词库 | 歌词补位（约 10%） | 默认启用 |
| GDStudio／Lyriva 第三方聚合上游 | 应急备用 | 默认严格关闭 |
| ListenBrainz／MusicBrainz 相似艺人增强 | 可选增强 | 默认关闭 |

试听侦测对音频实体长度与元数据进行探测，识别官方 30 秒试听截断；识别结果以试听标识在前端透明呈现，并可触发跨平台全曲匹配（匹配对象为 QQ／酷狗／酷我之免费全曲），匹配成功即平滑切换并标明替代来源。本专案不整合任何绕过付费版权之解灰组件。

## 5. 智慧推荐引擎

推荐引擎完全运行于数据面本地，行为信号权重公开于源码：

| 信号 | 权重 | 说明 |
| --- | --- | --- |
| favorite（加入最爱） | +4.0 | 极强正向 |
| replay（重播） | +3.5 | 强正向 |
| play_complete（有效完播） | +2.5 | 标准正向 |
| play_progress（进度聆听） | +0.2 ～ +1.8 | 按收听比例分阶计分 |
| skip（快速跳过） | -0.8 | 听过半之切歌计 +0.25 |
| dislike（明确拒绝） | -5.0 | 硬过滤并列入黑名单 |

噪声与假信号净化：因网络卡顿（network_stall）、解码失败（playback_error）、试听截断（trial_end）、流不可用（stream_unavailable）、缓冲超时（buffer_timeout）或自动切换失败（auto_switch_error）所致之切歌，权重恒为零且不入库。

热度模型综合有效播放（35%）、独立听众（25%）、完播表现（20%）、收藏转化（15%）与成长斜率（5%），辅以指数时间衰减（24 小时飙升榜与 7 天累计热榜）、贝氏与 Wilson Score 平滑；相似度计算融合歌手关系图谱与音讯特征余弦，并以 MMR 边际相关性重排平衡精准与多样。会话级搜索意图与长期偏好分层解耦：仅完播、收藏等高价值行为沉淀至长期档案。

## 6. 安全设计概览

1. **认证**：Epomail OAuth 2.0 授权码模式，`state` 参数与 PKCE（S256）防授权码拦截与重放；OAuth 事务 Cookie 有效期 600 秒；
2. **API Key**：`sonic_live_v2.<header>.<payload>.<signature>` 版本化格式，HMAC-SHA256 签名，载荷含 `sub`／`iat`／`exp`／`jti`／`kid`／`role`／`uid`；签发有效期 30 日、校验上限 90 日；服务器端以 Web Crypto 常数时间比对，无签名金钥与旧版金钥一律拒绝（fail-closed）；金钥仅经 `X-Sonic-Key` 或 `Authorization` 请求标头传递，URL 查询参数通道已完全移除；
3. **撤销**：登出即时撤销当前会话与金钥识别码（jti）；支持 jti 撤销清单、主体撤销清单与全局签发时间下限，绑定 KV 时支持即时撤销；
4. **会话**：`HttpOnly; Secure; SameSite=Lax` 之 `sonic_session` Cookie，有效期至多 30 日；金钥不写入 URL、localStorage 或页面脚本可及之处；
5. **SSRF 防御**：对回环地址、RFC 1918 私网、Docker 内部网桥与云端中继资料地址（如 `169.254.169.254`）之出站请求一律阻断，IPv4 与 IPv6 双栈校验，每次重定向重新校验目标与 DNS 解析结果。

## 7. 隐私设计概览

1. **假名化为默认**：行为事件自收集之始即以单向哈希标识符关联，电子邮件地址不落盘；
2. **个性化自主开关**：播放器设置中可随时关闭个性化；关闭后事件不入库，公开模式直接丢弃；
3. **一键清空**：设置页「清除推荐画像」即时销毁服务端全部行为事件；「清除全部本地数据」即时清除浏览器本地存储与 IndexedDB；
4. **日志最小化**：数据面访问日志仅含路径、方法、状态码与耗时。

隐私承诺之完整表述见[隐私政策](/privacy-policy/)，技术措施见[数据处理与安全维护](/data-security/)。

## 8. 适合谁与不适合谁

适合：希望以自有 Epomail 帐号登录、在意推荐画像透明与可删除性之个人听众；需要多源聚合搜索与逐字歌词之重度乐迷；具备 Linux 与 Docker 基础、愿意自行承担运营者责任之自部署用户。

不适合：寻求商业音乐服务授权保障之场景——本专案不存储、不托管音乐，亦不授予任何内容再授权；期待服务水准协议（SLA）或商业支持之团队；无法接受「试听片段透明标示、跨源补齐尽力而为」之用户。

## 9. 内容与版权边界

Sonic 是检索、聚合与播放工具，不存储、不托管任何音乐文件。录音、歌词、封面、艺人图像等内容之权利归属各自权利人；本专案不授予任何音乐内容之再授权。合法会员曲目由部署者以自有授权凭证挂载（如 `NETEASE_COOKIE`，为部署者帐户而非终端用户帐户），公开曲目遵循官方开放协议。

您使用本服务时应遵守[可接受使用政策](/acceptable-use/)；部署者应自行确认其使用场景符合当地法律、上游服务条款与内容授权要求。

## 10. 部署形态

| 形态 | 组成 | 要点 |
| --- | --- | --- |
| Cloudflare Pages 边缘闸道 | 前端 SPA + Pages Functions | 构建后经 `wrangler pages deploy` 发布；需配置 `SONIC_SECRET`、`SONIC_ENGINE_SECRET`、`SONIC_LOCAL_ENGINE_URL` |
| Linux 本地协议引擎 | sonic-engine + ncm-api + SQLite | `docker compose up -d --build` 部署；`.env` 权限 600；经 Cloudflare Tunnel 接入 |

两种形态共同构成完整服务；仅部署边缘闸道而无数据面时，服务自动运行于边缘降级模式。环境变量之完整清单见上游仓库 `.env.example` 与 `docs/OPERATIONS.md`。

## 11. 质量保障

本专案以可审计性与自动化核验保障质量：

1. **安全审计与整改**：上游仓库备有安全审计报告（`SECURITY_AUDIT_REPORT.md`、`SECURITY_FIX_SUMMARY.md`）与逐项整改记录（`docs/AUDIT_REMEDIATION.md`），涵盖 API 签名、OAuth 流程、SSRF 防御与前端 XSS 等项；
2. **自动化测试门禁**：测试套件覆盖网关行为、认证兼容性、SSRF 用例、本地引擎与降级、推荐与搜索、前端 XSS、配置一致性（config parity）与发布 P0/P1 门禁，随版本发布执行；
3. **文档一致性核验**：本站以自动化脚本核验三件事——页内锚点与图片引用零断链、多语言版本结构 1:1 对称、GDPR 条号引用与核验底稿白名单一致；
4. **事实核对流程**：本站全部数据处理事实随版本更新对照源码（`.env.example`、`server/recommend-sqlite.ts`、`functions/_lib/sonic/security.ts` 等）刷新，与源码不一致时以源码为准并即时修正文档。

## 12. 常见疑问

**本服务收费吗？有广告吗？**
免费、无广告、无内购；托管实例之运营成本由运营团队承担。本服务不收集任何用于广告目的之资料。

**不登录可以使用吗？**
可以。搜索、播放、歌词、排行榜等核心功能匿名可用（限流较严）；登录后解锁收藏云同步、个性化推荐与 Auto DJ。

**我的资料存在哪里？**
分三处：收藏、歌单、播放器偏好存于您浏览器之本地存储；下载与本地音乐存于您浏览器之 IndexedDB；服务端仅存假名化行为事件（90 日自动销毁）。电子邮件地址不落盘。详见[隐私政策](/privacy-policy/)第 4 节。

**如何删除我的行为画像？**
设置 → 隐私与本地数据 → 「重置推荐画像与不感兴趣记录」，或直接调用 `DELETE /api/sonic/events`，即时生效；「清除全部本地数据」同时清空浏览器与服务端数据。界面位置见[界面与功能导览](/interface/)第 9 节。

**推荐会跟踪我吗？**
推荐仅服务于播放排序，无跨站追踪、无广告画像；个性化可随时关闭，关闭后进入纯公共模式且不再记录任何事件。

**为什么有些歌只有 30 秒？**
那是官方平台之试听截断，播放器以试听标识如实标注，绝不冒充全曲；开启跨源补齐时会自动尝试匹配免费全曲并标明来源。

**音质徽章可信吗？**
可信。徽章反映当前音频流之实际档位；上游档位变动时实时随之，不虚标（见[用户条款](/terms-of-service/)第 4 节第 3 款）。

**自行部署有什么责任？**
自部署之时点起，您即为该实例之数据控制者：需向您的用户履行告知义务、维持处理记录、必要时实施影响评估并落实安全维护。起点见[数据处理与安全维护](/data-security/)第 6 节。

**本服务支持哪些语言？**
播放器内建简体中文、English、日本語；本站文档提供 10 种语言版本。
