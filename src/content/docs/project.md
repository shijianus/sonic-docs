## 1. 专案定位

Sonic 是一套独立研发的多源音乐串流平台与聚合闸道，以“Cloudflare 边缘控制面 + Linux 本地协定引擎资料面”双层架构运行，专为高音质串流、毫秒级逐字歌词与自主可控的推荐体验而建。专案为开源软件，源代码公开发布，任何人得自行部署。

| 项目 | 说明 |
| --- | --- |
| 托管实例 | `sonic.epocanvas.tech` 与 `sonic.epocanvas.com` 中由本个人免费非营利测试专案实际运营者；运营者须公布法律身份与联络资料 |
| 自行部署实例 | 独立部署的实例；运营者与控制者角色依实际决定服务和处理者判断，不仅依部署标签认定 |
| 源代码授权 | 最新公开 RC 的仓库根目录与 `player/LICENSE` 均为 MIT；较早 `main@ce443c8` 的根目录缺失仅作旧版相容性对照。非营利定位不自动禁止代码商业使用；媒体与商标另有权利规则 |
| 登录方式 | 最新公开 RC 使用 Epomail OAuth 2.0（PKCE），本专案不设独立注册系统；较早 `main@ce443c8` 不具备这些 RC 控制，线上版本未知 |
| 软件组成 | Cloudflare Pages 前端与边缘函式（控制面）、Node.js 22 本地引擎与 ncm-api 辅助容器（资料面）、Vue 3 网页播放器 |

## 3. 技术架构概览

### 3.1 控制面（Cloudflare 边缘）

控制面运行于 Cloudflare Pages 与 Pages Functions，承担以下职责：

1. **路由与验证**：API 请求之统一入口，验证检查与签章金钥核验；
2. **分级限流**：匿名请求每分钟 240 次、验证请求每分钟 600 次（默认值，可设置），验证端点另有每分钟每 IP 30 次之专用限流；
3. **多层级缓存**：以 `sonic:*` 为键之边缘缓存，新鲜期 8 分钟，过期后进入灾难备援延长状态；
4. **三态熔断器**：连续 3 次失败或呼叫超过 4.5 秒预算即进入 OPEN 熔断，后续请求不再等待已熔断的数据面，尝试边缘直连备援（QQ／酷狗公开检索 API 与 AMLL／LRCLIB），实际网络仍有延迟；冷却 30 秒后进入 HALF_OPEN 探活，成功后闭合。降级期间回应标头标明 `X-Sonic-Degraded: 1`，播放器顶部亮起降级提示胶囊。

### 3.2 数据面（Linux 协议引擎）

资料面为运营者自有 Linux 节点上之 Docker Compose 堆叠：

| 元件 | 说明 |
| --- | --- |
| sonic-engine 主容器 | Node.js 22 HTTP 服务，监听 8080 连接埠，宿主侧仅映射 `127.0.0.1`；全部 `/api`、`/proxy`、`/palette` 路由强制验证服务间金钥（X-Sonic-Engine-Key） |
| ncm-api 辅助容器 | 网易云协定辅助服务，仅于 compose 内部网络可达（`ncm-api:3000`），不对外公开 |
| SQLite 3（WAL 模式） | 行为事件与实体权重之持久化储存，落于具名磁盘区 `sonic-data`（容器内 `/app/data/sonic-recommend.sqlite`）；备份以一致性快照（VACUUM INTO）配合完整性检查执行 |
| 原生协定模组 | 纯 TypeScript 实现之网易 linuxapi/eapi、QQ、酷狗 KRC、酷我协定解析 |

控制面与资料面之间经 Cloudflare Tunnel 加密通道通讯，资料面不直接对外公开连接埠。

### 3.3 音频流路径

音频串流通常经同源字节范围边缘代理取得，支持 HTTP `Range` 与 `206 Partial Content`，使该上游连线看到代理位址。这不保护全部流量：`?mode=redirect`、MV、封面、外部图片、头像及字型可能直连并揭露您的 IP。目前代码载入 Google Fonts，且可能以明文电子邮件地址作为头像 seed 传送给 DiceBear；部分上游请求使用 HTTP，并非所有链路都加密。见[隐私政策](/privacy-policy/)第 4.4 节。

## 4. 音源与歌词链路

| 来源 | 占比定位 | 状态 |
| --- | --- | --- |
| 本地原生解析（网易／QQ／酷狗／酷我官方 API + ncm-api） | 主链路（逾 90%） | 默认启用 |
| AMLL TTML 逐字歌词 + LRCLIB 同步歌词库 | 歌词补位（约 10%） | 默认启用 |
| GDStudio／Lyriva 第三方聚合上游 | 可选路径 | GDStudio 代码未设置时默认开启，环境／Compose 范例为关闭，须核验实际开关 |
| ListenBrainz／MusicBrainz 相似艺人增强 | 可选增强 | 默认关闭 |

试听侦测对音频实体长度与元数据进行侦测，识别官方 30 秒试听截断；识别结果以试听标示在前端透明呈现，并可触发跨平台全曲匹配（匹配对象为 QQ／酷狗／酷我之免费全曲），匹配成功即平滑切换并标明替代来源。本专案不整合任何绕过付费版权之解灰元件。

## 5. 智能推荐引擎

核心推荐引擎运行于资料面；可选外部提供者与雷达同步依设置及路由可用性而定。曲目讯号权重公开于源代码，另有艺人、专辑、歌单及 MV 反馈：

| 讯号 | 权重 | 说明 |
| --- | --- | --- |
| favorite（加入最爱） | +4.0 | 极强正向 |
| replay（重播） | +3.5 | 强正向 |
| play_complete（有效完播） | +2.5 | 标准正向 |
| play_progress（进度聆听） | +0.2 ～ +1.8 | 按收听比例分阶计分 |
| skip（快速跳过） | -0.8 | 听过半之切歌计 +0.25 |
| dislike（明确拒绝） | -5.0 | 硬过滤并列入黑名单 |

噪声与假讯号净化：因网络延迟（network_stall）、解码失败（playback_error）、试听截断（trial_end）、串流不可用（stream_unavailable）、缓冲逾时（buffer_timeout）或自动切换失败（auto_switch_error）所致之切歌，权重恒为零且不入库。

热度模型综合有效播放（35%）、独立听众（25%）、完播表现（20%）、收藏转化（15%）与成长斜率（5%），辅以指数时间衰减（24 小时飙升榜与 7 天累计热榜）、贝氏与 Wilson Score 平滑；相似度计算融合歌手关系图谱与音频特征余弦，并以 MMR 边际相关性重排平衡精准与多样。会话意图与长期讯号分别加权，不表示搜索从不保留；即使关闭个性化，独立搜索原文计数仍可能出现在公开建议。

## 6. 安全设计概览

1. **认证**：最新公开 RC 使用 OAuth state 与 PKCE，OAuth 事务 Cookie 有效 600 秒；实际部署仍须核验，旧 `main@ce443c8` 仅作相容性对照；
2. **API Key**：RC 实现 `sonic_live_v2` 签名凭证及版本、签名、时间和配置的撤销校验；默认签发 30 日，验证器最大允许生命周期 90 日不等于默认期限。签名不是加密，凭证不得放入 URL、日志或公开客户端；线上设置和撤销传播仍须核验；
3. **撤销**：退出登录、撤销端点和即时失效依实际路由、存储、开关及请求结果；RC 代码提供撤销路径，但对所有部署即时生效仍未证明；
4. **会话**：Cookie 属性、有效期和服务端状态依实际部署核验；前端 `auth` 可能保留电子邮件地址及头像资料；
5. **出站请求防御**：RC 包含私网、回环、云元数据地址、重定向和解析目标的校验；覆盖范围取决于具体路由，不构成所有请求均受保护的保证，也不覆盖浏览器直连。

## 7. 隐私设计概览

1. **假名化**：电子邮件衍生及浏览器产生的识别码仍可能是可关联的个人资料；电子邮件地址与头像信息也保留于浏览器 `auth` 储存；
2. **个性化开关**：个性化与 Auto DJ 目前默认开启，不是有效的明确同意。关闭个性化不会停止独立的公开搜索词再利用，也未必停止每个雷达路径；缺少有效依据的可选处理应暂停；
3. **重置与清理**：重置删除目前身份的部分事件与反馈，未必涵盖旧匿名识别码、雷达资料、搜索聚合、外部提供者或备份，错误也可能未显示；清除本地不等于完整远端删除；
4. **日志最小化**：应用程序访问日志最小化字段，但错误、主机、代理与提供者仍可能处理请求资料；原始 IP 限流键可进入 KV，客户端位址也可能转送引擎。

隐私承诺之完整表述见[隐私政策](/privacy-policy/)，技术措施见[数据处理与安全维护](/data-security/)。

## 8. 适合谁与不适合谁

适合：希望以自有 Epomail 账号登录、在意推荐画像透明与可删除性之个人听众；需要多源聚合搜索与逐字歌词之重度乐迷；具备 Linux 与 Docker 基础、愿意自行承担运营者责任之自部署使用者。

不适合：需要商业音乐目录授权或内容再授权的场景；期待服务水准协议（SLA）或商业支持的团队；不能接受上游资源变化和尽力提供的备援功能的使用者。代理、缓存和本地保存各有数据处理，不应将项目概括为完全不存储或不传输音乐。

## 9. 内容与版权边界

Sonic 是检索、聚合与播放工具，不是音乐目录授权。导入或下载的文件主体留在浏览器存储，仍可能发生代理、缓存及相关元数据请求。录音、歌词、封面与艺人图像的权利仍属权利人；上游界面可用或部署者持有 `NETEASE_COOKIE` 等会员凭证，本身不授权公开访问、再分发或扩大会员权利。

您使用本服务时应遵守[可接受使用政策](/acceptable-use/)；部署者应自行确认其使用场景符合当地法律、上游服务条款与内容授权要求。

1. **安全稽核与改善**：上游仓库备有安全稽核报告（`SECURITY_AUDIT_REPORT.md`、`SECURITY_FIX_SUMMARY.md`）与逐项改善记录（`docs/AUDIT_REMEDIATION.md`），涵盖 API 签章、OAuth 流程、SSRF 防御与前端 XSS 等项；

## 12. 常见疑问

**本服务收费吗？有广告吗？**
这是个人维护、免费、无广告、无内购的非营利测试专案；非营利身份不免除资料保护或消费者义务。

**不登录可以使用吗？**
可以。搜索、播放、歌词及排行榜等核心功能无需登录，但未登录不等于匿名。登录不保证跨设备云端同步，也不证明年龄或画像分析同意。

**我的资料存在哪里？**
收藏、歌单和偏好主要在浏览器存储，邮箱与头像资料可能存于 `auth`；音乐文件主体与内嵌封面在 IndexedDB，但内嵌封面图片也可能随收藏事件进入远端曲目目录，不能保证仅留设备。元数据、反馈及推荐上下文可能传送；远端资料另有雷达画像和搜索统计。RC 行为事件默认 90 日、下限 7 日，但清理和删除覆盖不完整，不承诺全面自动删除。见[隐私政策](/privacy-policy/)第 4、6 节。

**如何删除我的行为画像？**
设置 → 隐私与本地资料 →“重置推荐画像与不感兴趣记录”可请求目前身分的部分重置；RC 提供 `DELETE /api/sonic/events`，但不能承诺服务器端完整删除，失败可能未显示。清除本地不证明远端已删除；较完整请求请联络 `privacy@epocanvas.com`。界面位置见[界面与功能导览](/interface/)第 9 节。

**推荐会追踪我吗？**
推荐使用假名化行为画像，而非匿名资料。个性化与 Auto DJ 默认开启，不是有效同意；关闭个性化不会停止独立搜索词计数及可能的公开建议。无痕模式不会阻止网络请求或事件。

**为什么有些歌只有 30 秒？**
那是上游平台的试听截断。播放器标示试听，启用跨来源补齐时尝试比对可用全曲并标示来源；技术可用不授予内容权利。

**音质徽章可信吗？**
徽章旨在反映可用串流档位，实际音质依上游资源而定。见[用户条款](/terms-of-service/)第 4 节。

**自行部署有什么责任？**
责任依您实际决定处理的角色及适用法律判断。公开处理前应落实身份告知、合法依据、经验证的保存与删除、安全及必要的传输保障。纯个人测试与公开服务须分别评估，不能只凭部署推定 GDPR 适用或服务器所在国家。见[数据处理与安全维护](/data-security/)。

**本服务支持哪些语言？**
播放器内建简体中文、English、日本语；本站文件提供 10 种语言版本。
