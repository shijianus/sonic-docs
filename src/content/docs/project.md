## 1. 产品定位

Sonic 是一套独立研发的多源音乐串流平台与聚合闸道，以「Cloudflare 边缘控制面 + Linux 本地协议引擎数据面」双层架构运行。专案为开源软体，源代码公开发布，任何人得自行部署。

| 项目 | 说明 |
| --- | --- |
| 托管实例 | `sonic.epocanvas.tech`（主站）与 `sonic.epocanvas.com`（备用镜像），由运营团队运行 |
| 自行部署实例 | 任何个人或组织依开源代码部署于自有服务器之私有实例；部署者即为该实例之运营者与数据控制者 |
| 源码授权 | 以仓库根目录 `LICENSE` 文件为准（MIT License）；专案定位为非商业开源专案，商标与品牌标识不随源码授权 |
| 登录方式 | Epomail OAuth 2.0（PKCE），本专案不设独立注册系统 |

## 2. 系统架构

控制面（Cloudflare Pages Functions）负责路由、分级限流（匿名 240 rpm、认证 600 rpm）、多层级缓存与三态熔断（CLOSED／OPEN／HALF_OPEN）；数据面（Linux 节点之 Docker Compose 堆叠）运行 sonic-engine 主容器、内网封闭之 ncm-api sidecar 与 SQLite 3（WAL 模式）持久化存储。数据面经 Cloudflare Tunnel 加密通道接入，所有请求强制验证服务间密钥（X-Sonic-Engine-Key）。

音源解析以本地原生 TypeScript 协议模块为主（网易、QQ、酷狗、酷我官方开放接口），歌词链路原生解析 YRC／QRC／KRC 逐字格式并接续 AMLL TTML 与 LRCLIB；第三方免费聚合上游（GDStudio、Lyriva）默认严格关闭。音频流默认经边缘代理自官方 CDN 拉取并支持 HTTP Range 分段加载，运营者亦可开启 302 直连模式由客户端直取。

## 3. 核心能力

| 能力 | 说明 |
| --- | --- |
| 多源聚合搜索 | 简繁归一、拼音与缩写检索、别名对称匹配、拼写容错；多源并行获取并正则去重合并 |
| 逐字动态歌词 | 网易 YRC、QQ QRC、酷狗 KRC 原生解析，AMLL TTML 与 LRCLIB 补位，支持翻译与罗马音 |
| 音质分级与试听透明 | 严格区分完整曲目与 30 秒试听片段，绝不以试听冒充全曲；试听曲目可自动触发跨源补齐（可配置） |
| 智慧推荐与 Auto DJ | 基于播放、完播、跳过、收藏、拒绝等行为信号之本地推荐引擎；信号权重与噪声过滤规则公开于源码 |
| 一键清空画像 | `DELETE /api/sonic/events` 立即销毁推荐引擎中您的全部行为特征与记录 |
| 零信任安全 | HMAC-SHA256 版本化签名 API Key、PKCE OAuth、全链路 SSRF 拦截、金钥仅经请求标头传递 |

## 4. 内容与版权边界

Sonic 是检索、聚合与播放工具，不存储、不托管任何音乐文件。录音、歌词、封面、艺人图像等内容之权利归属各自权利人；本专案不授予任何音乐内容之再授权。专案不整合绕过付费版权之解灰组件；合法会员曲目由部署者以自有授权凭证挂载，公开曲目遵循官方开放协议。

您使用本服务时应遵守[可接受使用政策](/acceptable-use/)；部署者应自行确认其使用场景符合当地法律、上游服务条款与内容授权要求。

## 5. 隐私与资料保护立场

本专案以欧盟《通用数据保护条例》（GDPR）作为全体用户之最低资料保护标准，无论用户所在地为何。托管实例不收集电子邮件、电话或支付资料；行为事件之收集范围、保存期限与权利行使方式见[隐私政策](/privacy-policy/)，技术措施见[数据处理与安全维护](/data-security/)，第三方共享清单见[第三方共享与传输清单](/sub-processors/)。
