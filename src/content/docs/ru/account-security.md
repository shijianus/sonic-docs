**Дата редакции: 3 ноября 2026 г.｜Версия: 1.9**

На этой странице описаны устройство системы учётных записей Sonic и рекомендации по безопасному использованию. Полная техническая реализация приведена в разделе 3.2 документа [Обработка данных и меры безопасности](/ru/data-security/); договорные положения — в разделе 3 [Условий использования](/ru/terms-of-service/).

Описания функций основаны на публичной ветке-кандидате `rc/sonic-20261031@a75f5cb` (2026-11-01 UTC), проверенной 2026-11-02. Старая версия `main@ce443c8` (2026-10-27 UTC) рассматривается отдельно: у неё есть пути передачи учётных данных через URL и localStorage, а наличие защиты кандидата не предполагается. RC не является официальной GitHub Release, а версия работающего сервиса не проверена.

## 1. Способ входа

Сервис использует учётную запись Epomail через OAuth 2.0 (PKCE) и не имеет отдельной системы регистрации. Порядок входа: нажмите на пункт учётной записи в боковой панели → подтвердите действие на странице авторизации Epomail → возврат в сервис завершает вход. Обратный вызов авторизации проходит проверки state, PKCE, кода авторизации и защиты от повторного воспроизведения; для эндпоинта аутентификации установлен лимит 30 запросов в минуту на IP.

## 2. Механизм сессий

1. **Сессионный cookie**: `sonic_session` по умолчанию действует 30 дней, содержит подписанный ключ и использует `HttpOnly; SameSite=Lax`; `Secure` зависит от HTTPS и может отсутствовать при локальной HTTP-разработке. Подпись защищает целостность, но не шифрует поля, в том числе электронную почту. Это поведение исходного кода, не проверка работающего экземпляра;
2. **Синхронизация между вкладками**: состояние входа автоматически синхронизируется между вкладками одного браузера; выход в одной вкладке становится виден остальным, но это не подтверждение отзыва скопированных ключей;
3. **Границы ключа**: ключ нельзя помещать в URL или параметры запроса; cookie с `HttpOnly` недоступен скриптам напрямую, однако `/api/auth/key` позволяет получить ключ после аутентификации. В localStorage (`auth`) сохраняются сведения о пользователе, включая электронную почту и аватар; в RC также есть пути совместимости для чтения старого хранилища входа. Транзакционные cookie OAuth действуют около 600 секунд.

## 3. Хранение ключа API

Ключ API представляет собой ваши личные учётные данные (формат `sonic_live_v2.…`, подпись HMAC-SHA256):

1. Передаётся только в заголовках запроса и никогда не помещается в URL;
2. Его нельзя передавать третьим лицам или встраивать в публично распространяемый клиент;
3. Повторный выпуск требует действующих учётных данных; при утечке выйдите из системы и запросите подтверждённый отзыв у оператора, не полагаясь только на удаление cookie (см. раздел 4).

## 4. Отзыв и выход из системы

| Действие | Расположение | Эффект |
| --- | --- | --- |
| Выход из системы | В плеере | Очищает текущий cookie; серверный отзыв зависит от конфигурации и успеха запроса |
| Отзыв ключа | `POST /api/auth/revoke` | Требует настроенного хранилища KV и включённого механизма; возможны задержки распространения |
| Массовая недействительность | Конфигурация оператора развертывания | Список jti, список субъектов и глобальная нижняя граница времени выпуска |

Очистка cookie не уничтожает ранее скопированный или экспортированный ключ. Без работающего отзыва он может оставаться действительным до истечения срока. «Очистить все локальные данные» не очищает HttpOnly-cookie и не заменяет выход; после очистки настроек персонализация может снова включиться по умолчанию. При утечке выйдите и свяжитесь с `admin@epocanvas.com` для проверки отзыва.

## 5. Рекомендации по безопасности

1. После использования общего устройства выйдите и при необходимости очистите локальные сведения об учётной записи; аватар DiceBear в текущем коде может передавать почту в URL, поэтому оператору следует заменить его локальным или не содержащим почту вариантом;
2. Рекомендуется включить двухэтапную проверку учётной записи Epomail (в настройках Epomail);
3. Не передавайте и не используйте совместно учётную запись — данные общей учётной записи смешиваются и не подлежат разграничению или восстановлению;
4. При обнаружении необычных записей воспроизведения или сессии неизвестного происхождения немедленно выйдите из системы и напишите на `admin@epocanvas.com`;
5. Сервис не собирает пароли (вход выполняется через Epomail); любой запрос «проверить пароль Sonic» является попыткой выдать себя за сервис.

## 6. Доступ к управлению учётной записью

Пункт учётной записи в нижней части боковой панели показывает текущее состояние входа: без входа он предлагает начать вход, а после входа показывает псевдоним учётной записи и ссылку на управление учётной записью (профиль и почтовый ящик Epomail). Состояние входа синхронизируется между вкладками одного браузера.
