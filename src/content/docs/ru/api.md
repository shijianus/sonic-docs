**Дата вступления в силу: 2 ноября 2026 г.｜Версия: 1.5**

На этой странице описан способ подключения к открытому API Sonic: единая структура ответа, основные эндпоинты, аутентификация ключами API и правила их передачи, ограничение частоты и отзыв. Поведение при подключении регулируется [Условиями использования](/ru/terms-of-service/) и [Политикой допустимого использования](/ru/acceptable-use/); авторитетное изложение спецификаций эндпоинтов приведено в `API.md` вышестоящего репозитория.

## 1. Единая структура ответа

Все эндпоинты внешне гарантируют совместимость по контракту `brand: "Sonic"`; стандартный ответ выглядит следующим образом:

```json
{
  "brand": "Sonic",
  "data": { "id": "191254", "title": "红豆", "quality": "320k" },
  "meta": {
    "cached": true,
    "cacheLevel": "edge",
    "provider": "nexus",
    "degraded": false,
    "circuitState": "CLOSED"
  }
}
```

Поля `meta` честно помечают уровень кэша, поставщика, состояние деградации и состояние предохранителя; клиент может на их основе показывать прозрачные уведомления.

## 3. Аутентификация ключом API

1. **Формат**: версионированный формат `sonic_live_v2.<header>.<payload>.<signature>`, подпись HMAC-SHA256; полезная нагрузка содержит `sub` (адрес электронной почты), `iat`, `exp`, `jti`, `kid`, `role`, `uid`;
2. **Выпуск**: ключ получается через `/api/auth/key` после входа по Epomail OAuth; срок действия при выпуске 30 дней, предел проверки 90 дней;
3. **Передача**: допускаются только заголовки запросов — `X-Sonic-Key: <key>` или `Authorization: Bearer <key>`; канал через параметры запроса URL полностью удалён, чтобы ключи не утекали в журналы доступа, историю браузера или Referer;
4. **Проверка**: на сервере применяется сравнение с постоянным временем выполнения через Web Crypto со строгой проверкой версии, `kid`, `iat`/`exp`, `jti` и списков отзыва; ключи без подписи и устаревшие ключи отклоняются безусловно (fail-closed).

## 4. Ограничение частоты и отзыв

| Пункт | Лимит |
| --- | --- |
| Анонимные запросы | 240 в минуту (значение по умолчанию) |
| Аутентифицированные запросы | 600 в минуту (значение по умолчанию) |
| Эндпоинты аутентификации | 30 в минуту на IP |
| Передача событий поведения | Не более 50 событий в пакете, тело запроса 64 КБ |

Механизм отзыва: выход из системы немедленно отзывает текущую сессию и `jti`; оператор развертывания может настроить статические списки `SONIC_REVOKED_JTIS`/`SONIC_REVOKED_SUBS`/`SONIC_TOKEN_MIN_IAT` либо привязать KV и включить мгновенный отзыв. Обычное личное использование лимитов ограничения частоты не достигает; устойчивое превышение переходит в ступени мер воздействия [Политики допустимого использования](/ru/acceptable-use/).

## 5. Обязанности подключающихся

1. Ключ API является личным удостоверением; передача его третьим лицам и встраивание в публично распространяемые клиенты запрещены;
2. Собственные клиенты должны уважать ограничение частоты запросов, показывать уведомления о деградации (`X-Sonic-Degraded: 1`) и соблюдать перечень запрещённых действий [Политики допустимого использования](/ru/acceptable-use/);
3. Обязанность информировать конечных пользователей при подключении сторонних клиентов лежит на подключающемся; пользователям API экземпляров самостоятельного развертывания следует также прочитать документ [Правовые аспекты открытого кода и самостоятельного развертывания](/ru/open-source/).
