**Дата редакции: 2 ноября 2026 г.｜Версия: 1.8**

На этой странице описан способ подключения к открытому API Sonic: единая структура ответа, основные эндпоинты, аутентификация ключами API и правила их передачи, ограничение частоты и отзыв. Поведение при подключении регулируется [Условиями использования](/ru/terms-of-service/) и [Политикой допустимого использования](/ru/acceptable-use/); спецификации приведены в `API.md` вышестоящего репозитория. Описания функций основаны на публичной ветке-кандидате `rc/sonic-20261031@a75f5cb` (2026-11-01 UTC), проверенной 2026-11-02. Старая версия `main@ce443c8` (2026-10-27 UTC) рассматривается отдельно; наличие в ней обработчиков и защиты кандидата не предполагается. RC не является официальной GitHub Release; версия, фактические маршруты и конфигурация работающего экземпляра не проверены.

## 1. Единая структура ответа

Для стандартных JSON-ответов используется поле `brand: "Sonic"`; пример приведён ниже. Аудиопотоки, перенаправления и отдельные ответы могут иметь другой формат; бесплатный тестовый API не гарантирует неизменную совместимость.

```json
{
  "brand": "Sonic",
  "data": { "id": "191254", "title": "红豆", "quality": "320k" },
  "meta": {
    "cached": true,
    "cacheLevel": "edge",
    "provider": "nexus",
    "degraded": false,
    "circuitState": "CLOSED"
  }
}
```

Поля `meta` честно помечают уровень кэша, поставщика, состояние деградации и состояние предохранителя; клиент может на их основе показывать прозрачные уведомления.

## 2. Навигация по основным эндпоинтам

| Категория | Метод | Эндпоинт | Функция |
| --- | --- | --- | --- |
| Интеллектуальные рекомендации | GET | `/api/sonic/recommend/for-you` | «Возможно, вам понравится» / Auto DJ |
| | GET | `/api/sonic/recommend/trending` | Трендовый чарт (24h/7d/surging/new) |
| | GET | `/api/sonic/recommend/similar` | Похожие треки / изучение исполнителей |
| | GET | `/api/sonic/recommend/discover` | Радар жанров и стилей |
| События поведения | POST | `/api/sonic/events` | Передача событий поведения (пакетами до 50 событий)  |
| | GET | `/api/sonic/events` | Ограниченная сводка текущего профиля, не полный экспорт  |
| | DELETE | `/api/sonic/events` | Частичное удаление событий и обратной связи текущего идентификатора  |
| Агрегированный поиск | GET | `/api/sonic/search/smart` | Интеллектуальный поиск; слова отдельно агрегируются и могут появляться в публичных подсказках |
| | GET | `/api/sonic/search/nexus` | Параллельный многоисточниковый поиск по всем сетям |
| Динамические тексты | GET | `/api/sonic/lyrics/nexus` | Пословные тексты (YRC/QRC/KRC → AMLL → LRCLIB) |
| | GET | `/api/sonic/lyrics/sync` | Межплатформенные синхронные тексты (вывод в нескольких форматах) |
| Аудиомедиа | GET | `/api/music/stream` | Сегментный аудиопрокси (Range/206; `?mode=redirect` — прямое подключение) |
| | GET | `/api/music/cover` | Прокси обложек (приоритет высокого качества, деградация к SVG) |
| | GET | `/api/music/palette` | Анализ цветовой температуры обложки |
| Аутентификация | GET | `/api/auth/user` | Данные текущей сессии |
| | GET/POST | `/api/auth/key` | Просмотр / повторный выпуск ключа API |
| | POST | `/api/auth/revoke` | Отзыв текущего ключа при настроенном механизме (требуется явный заголовок ключа) |
| | POST | `/api/auth/logout` | Очистка текущего cookie и попытка серверного отзыва |

`GET /api/sonic/events` не заменяет полную копию данных. `DELETE` работает с текущим идентификатором (при входе — прежде всего с идентификатором от почты), не охватывает автоматически прежние анонимные идентификаторы, радар, поисковые агрегаты, внешние сервисы или резервные копии. Успешный HTTP-ответ и уведомление интерфейса могут не отражать `cleared: false`, сбой удалённого движка или неполный результат. Полные запросы направляйте на `privacy@epocanvas.com`.

API событий принимает 15 видов `action`, но это не доказывает отправку каждого вида из интерфейса. В проверенном клиенте персонализация и Auto DJ включены по умолчанию без отдельного предварительного согласия; отключение прекращает новые клиентские события профилирования, но не поиск, его отдельные публичные агрегаты или запросы контента. Псевдонимы и агрегация не гарантируют анонимность. Путь радара в Pages может использовать память isolate, а стандартный Node-маршрутизатор его не подключает; постоянная облачная синхронизация не подтверждена.

## 3. Аутентификация ключом API

1. **Формат**: `sonic_live_v2.<header>.<payload>.<signature>`, подпись HMAC-SHA256; поля могут включать `sub` (почту), `iat`, `exp`, `jti`, `kid`, `role`, `uid`. Подпись защищает целостность, а не шифрует данные;
2. **Выпуск**: `/api/auth/key` доступен после Epomail OAuth с PKCE. При выпуске и повторном выпуске срок ключа и сессионного cookie по умолчанию — 30 дней; 90 дней — только верхний предел допустимого срока при проверке, не срок повторного выпуска. Это факты кода, а не подтверждённая конфигурация работающего экземпляра;
3. **Передача**: для ключа используйте `X-Sonic-Key: <key>` или `Authorization: Bearer <key>`, не URL. Веб-сеанс использует HttpOnly-cookie; сведения о пользователе, включая почту, отдельно сохраняются в localStorage (`auth`). Экспортированный ключ нуждается в самостоятельной защите;
4. **Проверка**: код проверяет подпись и поля версии, `kid`, `iat`/`exp`, `jti`; применение динамического отзыва зависит от настроенных KV и переключателей, а не только от формата ключа.

## 4. Ограничение частоты и отзыв

| Пункт | Лимит |
| --- | --- |
| Анонимные запросы | 240 в минуту (значение по умолчанию) |
| Аутентифицированные запросы | 600 в минуту (значение по умолчанию) |
| Эндпоинты аутентификации | 30 в минуту на IP |
| Передача событий поведения | Не более 50 событий в пакете, тело запроса не более 64 КиБ |

Выход очищает текущий сессионный cookie, но не гарантирует недействительность скопированного ключа. Динамический отзыв зависит от KV, включённого механизма и успеха запроса; возможны задержки распространения. Оператор также может применять `SONIC_REVOKED_JTIS`/`SONIC_REVOKED_SUBS`/`SONIC_TOKEN_MIN_IAT`. При утечке требуется проверить результат отзыва, а не только уведомление о выходе.

Лимиты зависят от конфигурации. Анонимные ключи ограничителя могут содержать исходный IP; TTL KV 120 секунд и окно памяти около 60 секунд не гарантируют срок удаления всех инфраструктурных записей. При превышении следуйте [Политике допустимого использования](/ru/acceptable-use/).

## 5. Обязанности подключающихся

1. Ключ API является личным удостоверением; передача его третьим лицам и встраивание в публично распространяемые клиенты запрещены;
2. Собственные клиенты должны уважать ограничение частоты запросов, показывать уведомления о деградации (`X-Sonic-Degraded: 1`) и соблюдать перечень запрещённых действий [Политики допустимого использования](/ru/acceptable-use/);
3. Обязанность информировать конечных пользователей при подключении сторонних клиентов лежит на подключающемся; пользователям API экземпляров самостоятельного развертывания следует также прочитать документ [Правовые аспекты открытого кода и самостоятельного развертывания](/ru/open-source/).
