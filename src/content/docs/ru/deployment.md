**Дата редакции: 2 ноября 2026 г.｜Версия: 1.8**

На этой странице описаны два сценария самостоятельного развертывания Sonic, основные переменные окружения, резервное копирование и восстановление, а также ключевые моменты эксплуатации. Роль контролёра определяется тем, кто фактически устанавливает цели и способы обработки; автор кода не становится оператором всех независимых экземпляров. Обязанности приведены в документе [Обработка данных и меры безопасности](/ru/data-security/) и в документе [Правовые аспекты открытого кода и самостоятельного развертывания](/ru/open-source/); детали операций — в `docs/OPERATIONS.md` вышестоящего репозитория.

Инструкции основаны на публичной ветке-кандидате `rc/sonic-20261031@a75f5cb` (2026-11-01 UTC), проверенной 2026-11-02. Старая версия `main@ce443c8` (2026-10-27 UTC) приведена отдельно для сравнения; примеры ниже закрепляют коммит кандидата. RC не является официальной GitHub Release; версия работающего экземпляра, его безопасность, соответствие требованиям и конфигурация не проверены. Применимость GDPR оценивается по статье 3 GDPR, а не автоматически для любого развертывания.

## 1. Сценарий A: граничный шлюз Cloudflare Pages

```bash
git clone git@github.com:shijianus/sonic.git
cd sonic
git fetch origin rc/sonic-20261031
git checkout --detach a75f5cb54a2fe3593ba0da72b7ee9b1cc5c410a8
corepack enable
corepack prepare pnpm@10.34.5 --activate
npm ci
pnpm --dir player install --frozen-lockfile
npm run build
npx wrangler pages deploy dist --project-name YOUR_PROJECT_NAME
```

Перед выполнением команд замените `YOUR_PROJECT_NAME` на фактическое имя вашего проекта Pages. В панели управления Cloudflare Pages настройте зашифрованные переменные окружения: `SONIC_SECRET`, `SONIC_ENGINE_SECRET` (совпадающие со стороной VPS) и `SONIC_LOCAL_ENGINE_URL` (указывающий на домен туннеля вашей плоскости данных).

## 2. Сценарий B: локальный протокольный движок на Linux (Docker Compose)

```bash
mkdir -p /opt/sonic && cd /opt/sonic
git clone git@github.com:shijianus/sonic.git .
git fetch origin rc/sonic-20261031
git checkout --detach a75f5cb54a2fe3593ba0da72b7ee9b1cc5c410a8
cp .env.example .env
chmod 600 .env    # задайте сильные случайные значения для SONIC_ENGINE_SECRET и SONIC_SECRET
docker compose up -d --build
docker compose ps
curl -H "X-Sonic-Engine-Key: <YOUR_SECRET>" http://127.0.0.1:8080/api/sonic/engine/health
```

Состав стека: основной контейнер sonic-engine (на стороне хоста проброшен только `127.0.0.1:8080`), замкнутый во внутренней сети вспомогательный контейнер ncm-api, постоянное хранение SQLite (именованный том `sonic-data`). Плоскость данных подключается через Cloudflare Tunnel и не публикуется напрямую в интернете.

## 3. Основные переменные окружения

| Переменная | Описание |
| --- | --- |
| `SONIC_SECRET` | Ключ подписи ключей API, длина ≥ 32 символов (`openssl rand -base64 48`) |
| `SONIC_ENGINE_SECRET` | Межсервисный ключ, одинаковый на сторонах Pages и VPS |
| `SONIC_LOCAL_ENGINE_URL` | Адрес туннеля плоскости данных |
| `SONIC_ENABLE_NETEASE/QQ/KUGOU/KUWO` | Переключатели встроенных протоколов источников звука (по умолчанию 1) |
| `SONIC_ENABLE_AMLL/LRCLIB` | Переключатели дополнения текстов (по умолчанию 1) |
| `SONIC_ENABLE_GDSTUDIO/LYRIVA/UNBLOCK` | Сторонние резервные пути; в `.env.example` и Compose GDStudio явно выключен, но в `licensing.ts` при отсутствии переменной включён. Задавайте значения явно; переключатель не предоставляет прав на контент |
| `SONIC_RECOMMEND_DB_PATH` | Путь SQLite; `memory` отключает сохранение этого хранилища на диск, но не обработку в памяти, журналы, иные хранилища или внешние передачи |
| `SONIC_RECOMMEND_RETENTION_DAYS` | По умолчанию 90 дней, минимум 7; используется при запуске, но путь очистки после части записей возвращается к фиксированным 90 дням. Это не точный таймер удаления  |
| `SONIC_RATE_LIMIT_ANON_RPM / AUTH_RPM` | Ограничение частоты запросов (по умолчанию 240/600) |
| `EPOMAIL_BASE_URL` и др. | Конфигурация Epomail OAuth |

Полный перечень приведён в `.env.example` вышестоящего репозитория; требования к согласованности уведомлений по переключателям, связанным с приватностью, изложены в разделе 6 документа [Обработка данных и меры безопасности](/ru/data-security/).

## 4. Резервное копирование и восстановление

1. **Резервное копирование**: `VACUUM INTO` (`npm run backup:db`) копирует всю базу, а не только события; псевдонимизация не превращает её в анонимные данные. Единого автоматического срока удаления копий не найдено — оператор должен установить срок, доступ и удаление;
2. **Восстановление**: после остановки сервиса используется `npm run restore:db`; проверьте совместимость версии и схемы. Восстановление сохраняет прежний снимок, а автоматическое повторное применение удалений не найдено; исключите возвращение ранее удалённых данных в использование;
3. **Ёмкость**: очистка срабатывает при запуске и после части записей, не по непрерывному таймеру; после 1 500 поведенческих записей используется фиксированный срок 90 дней. Радар, поисковые агрегаты и резервные копии полностью не охвачены; SQL-удаление не равно физическому стиранию WAL и свободных страниц. Контролируйте сроки и объём отдельно.

## 5. Проверки работоспособности и откат

1. **Проверка работоспособности**: `GET /api/sonic/engine/health` (требуется сервисный ключ) возвращает состояние движка и предохранителя; граничный предохранитель при подряд идущих неудачах плоскости данных автоматически переходит в режим деградации;
2. **Журналы**: обычный журнал доступа Node минимизирован, но это не гарантия «нулевых журналов» всей системы. Проверьте ошибки, Cloudflare, прокси, sidecar и хост; граничная передача движку может содержать реальный IP, полный Cookie, Authorization и контекст;
3. **Откат**: на стороне Pages достаточно откатиться к предыдущей версии развертывания; на стороне плоскости данных выполняется `git checkout` предыдущего тега и заново `docker compose up -d --build`; перед откатом убедитесь в совместимости схемы SQLite (системы миграций нет).

## 6. Контрольный список развернувшего

Перед выводом в эксплуатацию проверьте по пунктам:

1. Оба ключа — сильные случайные и длиной ≥ 32 символов; права `.env` — 600; проверены PKCE, подпись cookie, HTTPS и фактический отзыв. Cookie по умолчанию действует 30 дней и не зашифрован; очистка cookie не гарантирует отзыва экспортированных ключей без KV и включённого механизма;
2. Проверены фактические получатели, страны, договоры и основания передачи. Учтены прямые MV, обложки, Google Fonts, URL DiceBear с почтой и отдельные HTTP-запросы к источникам; аудиопрокси не скрывает все соединения. Необеспеченные передачи ограничены или приостановлены;
3. Проверены сроки и удаление по всем идентификаторам и хранилищам. Сообщение об успехе сброса не является доказательством: могут остаться старые анонимные идентификаторы, радар, поисковые агрегаты, внешние сервисы и резервные копии;
4. Плоскость данных не открыта в интернет без защиты. Учтено, что радар пытается синхронизацию через Pages и память isolate, но стандартный Node-маршрутизатор не подключает его маршрут; постоянную облачную синхронизацию обещать нельзя;
5. План резервного копирования включает защиту, срок удаления и повторное применение удалений после восстановления; процедура проверена. Очистка настроек не удаляет HttpOnly-cookie, не заменяет выход и может снова включить персонализацию;
6. Опубликованы реальная личность и контакты контролёра и уведомление о фактической обработке. При применимости правил ЕС до запуска устранены включённые по умолчанию без отдельного согласия персонализация и Auto DJ, обеспечен предварительный выбор и приостановлено неконтролируемое публичное повторное использование поисковых слов. Одной новой [Политики конфиденциальности](/ru/privacy-policy/) недостаточно.
