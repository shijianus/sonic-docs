**Дата вступления в силу: 1 ноября 2026 г.｜Версия: 1.4**

Эта страница адресована читателям, участвующим в разработке и вторичной разработке, и описывает структуру репозитория, команды сборки, набор тестов и проверку согласованности документации. Лицензия и правовые границы изложены в документе [Правовые аспекты открытого кода и самостоятельного развертывания](/ru/open-source/).

## 1. Структура репозитория

| Путь | Содержание |
| --- | --- |
| `player/` | Веб-плеер на Vue 3 (встроенный i18n на трёх языках: zh/en/ja) |
| `functions/` | Граничный шлюз Cloudflare Pages Functions (маршрутизация, ограничение частоты, кэширование, предохранитель) |
| `functions/_lib/sonic/` | Общая логика рекомендаций, идентификации, вышестоящих протоколов и безопасности |
| `server/` | Движок плоскости данных на Node.js 22 (включая SQLite-хранилище `recommend-sqlite.ts`) |
| `Dockerfile` / `docker-compose.yml` | Контейнерный стек плоскости данных (sonic-engine + ncm-api) |
| `docs/` | Документация по эксплуатации, соответствию, устранению замечаний аудита и известным проблемам |
| `tests/` | Тесты безопасности, шлюза, рекомендаций и шлюзов выпуска |

## 2. Сборка и локальный запуск

```bash
npm ci                              # 根依赖
pnpm --dir player install --frozen-lockfile
npm run build                       # 播放器构建 + 复制至 dist
npx wrangler pages dev dist         # 本地边缘闸道（无数据面时自动降级模式）
npm run build:engine && npm run start:engine   # 本地数据面引擎
```

## 3. Набор тестов

Перед выпуском выполняется командой `npm test`; охват:

1. Поведение шлюза и деградация (`test-sonic-gateway.mjs`, `test-local-engine-and-degradation.mjs`);
2. Совместимость аутентификации и безопасность OAuth (`test-auth-compatibility.mjs`, `tests/oauth-security.test.ts`);
3. SSRF и усиление безопасности (`tests/ssrf-security.test.ts`, `tests/security*.test.ts`);
4. Рекомендации и поиск (`tests/recommendation-and-search.test.ts`);
5. XSS на фронтенде (`tests/frontend-xss.test.ts`);
6. Согласованность конфигурации — пообъектное сравнение `.env.example` с переменными окружения, читаемыми кодом (`tests/config-parity.test.ts`);
7. Шлюзы выпуска P0/P1 (`tests/release-p0-p1-gate.test.ts`).

## 4. Проверка согласованности документации

Этот сайт (sonicdocs) сверяется с исходным кодом по мере развития версий; цепочка инструментов проверки:

```bash
pnpm validate    # 构建 + 页内锚点断链检查 + 多语言结构对称校验
```

1. `scripts/validate-anchors.cjs`: отсутствие битых внутристраничных якорей и ссылок на изображения по всему сайту;
2. `scripts/check-structure.py`: структурная симметрия 1:1 многоязычных версий по заголовкам / таблицам / изображениям / выделенным блокам;
3. `doc/legal-reference.md`: белый список ссылок на статьи GDPR (проверочная основа EUR-Lex); в документах не должны появляться статьи вне белого списка;
4. Технические факты сверяются с исходным кодом при обновлении версий (`.env.example`, `server/recommend-sqlite.ts`, `functions/_lib/sonic/security.ts`); при расхождении приоритет имеет исходный код, и документация исправляется.

## 5. Участие в развитии

1. Вопросы и обсуждения: Issues репозитория на GitHub (`github.com/shijianus/sonic`);
2. Перед отправкой изменений выполните полный набор тестов и `npm run lint`;
3. Изменения, затрагивающие обработку данных (новые собираемые элементы, изменение политики хранения, новые случаи передачи третьим лицам), требуют синхронного обновления соответствующих документов этого сайта и прохождения проверки согласованности;
4. Введение сторонних зависимостей требует обновления `THIRD_PARTY_NOTICES.md` и оценки влияния на приватность и лицензии.

## 6. Вклад в перевод документации

Сайт имеет многоязычную параллельную структуру: изменения на любом языке синхронизируются с остальными языками (симметрия структур 1:1 проверяется скриптами). При добавлении нового языка: зарегистрируйте locale, дополните все документы, внесите язык в список языков структурных скриптов и сверьте ссылки на правовые нормы по формату цитирования этого языка, приведённому в `doc/legal-reference.md`.
