**Дата вступления в силу: 1 ноября 2026 г.｜Версия: 1.3**

На этой странице определены юридические и технические термины, используемые в юридических документах сайта. Один и тот же термин имеет одинаковое значение во всех документах; определённые термины толкуются по определению, неопределённые — по их обычному значению. Юридические термины основаны на определениях Общего регламента ЕС по защите данных (GDPR).

*Рисунок: структура двух семейств терминов сайта. Семейство юридических терминов опирается на определения статьи 4 GDPR; семейство технических терминов определяется реализацией исходного кода и сверяется при обновлении версий.*

## 1. Юридические термины

| Термин | Определение |
| --- | --- |
| Персональные данные | Любая информация, относящаяся к идентифицированному или идентифицируемому физическому лицу (статья 4, пункт 1 GDPR); в Sonic, например, идентификатор входа и записи событий поведения |
| Обработка | Любая операция с персональными данными, включая сбор, запись, хранение, использование, передачу, удаление и др. (статья 4, пункт 2 GDPR) |
| Ограничение обработки | Состояние временной приостановки обработки при определённых обстоятельствах с сохранением данных (статья 4, пункт 3 и статья 18 GDPR) |
| Профилирование | Автоматизированная оценка личных характеристик и принятие на её основе решений или анализ (статья 4, пункт 4 GDPR); сервис делает это только в объёме, необходимом для рекомендаций, и вы можете очистить всё одним нажатием |
| Псевдонимизация | Обработка персональных данных таким образом, чтобы идентифицировать конкретное лицо можно было только с дополнительной информацией (статья 4, пункт 5 GDPR); в Sonic реализована усечённым хешем SHA-256 с солью |
| Контролёр данных | Физическое или юридическое лицо, определяющее цели и средства обработки (статья 4, пункт 7 GDPR); для управляемого экземпляра — команда эксплуатации, для самостоятельного развертывания — развернувший |
| Обработчик по поручению | Физическое или юридическое лицо, обрабатывающее персональные данные для контролёра (статья 4, пункт 8 GDPR), например Cloudflare |
| Получатель | Физическое или юридическое лицо, получающее персональные данные (статья 4, пункт 9 GDPR), независимо от того, является ли оно третьим лицом |
| Третье лицо | Субъект, помимо субъекта данных, контролёра, обработчика по поручению и лиц, уполномоченных на обработку (статья 4, пункт 10 GDPR) |
| Согласие | Положительное волеизъявление субъекта данных, данное свободно и при ясном понимании (статья 4, пункт 11 и статья 7 GDPR); может быть отозвано в любой момент способом, удобство которого не ниже способа его дачи |
| Утечка данных | Нарушение безопасности, приводящее к случайному или незаконному разрушению, утрате, искажению персональных данных либо их несанкционированному раскрытию или доступу к ним (статья 4, пункт 12 GDPR) |
| Надзорный орган | Публичный орган, по закону надзирающий за исполнением обязанностей по защите данных (статья 4, пункт 19 GDPR); пользователи ЕС могут жаловаться в надзорный орган своего местонахождения (статья 77 GDPR) |
| Международная передача | Передача персональных данных в третьи страны или международные организации за пределами Европейского союза и Европейской экономической зоны (раздел V GDPR) |
| Особые категории данных | Персональные данные, раскрывающие расовое происхождение, политические взгляды, здоровье, половую жизнь и иные чувствительные атрибуты (статья 9 GDPR); сервис их не собирает |
| Субъект данных | Физическое лицо, идентифицированное или идентифицируемое по персональным данным (статья 4, пункт 25 GDPR), то есть вы |

## 2. Технические термины

| Термин | Определение |
| --- | --- |
| Плоскость управления | Граничный шлюз на Cloudflare Pages Functions; отвечает за маршрутизацию, ограничение частоты, кэширование и предохранитель |
| Плоскость данных | Стек Docker Compose на собственном узле Linux оператора; отвечает за разбор протоколов, рекомендательные вычисления и хранение |
| sonic-engine | Основной контейнер плоскости данных (Node.js 22); обязательная проверка межсервисного ключа X-Sonic-Engine-Key, привязка на стороне хоста только к петлевому адресу |
| ncm-api sidecar | Замкнутый во внутренней сети вспомогательный контейнер протокола NetEase (`ncm-api:3000`), доступный только через внутреннюю сеть compose |
| OAuth 2.0 + PKCE | Поток входа по коду авторизации с подтверждением обмена кодом (S256); сервис использует Epomail как поставщика идентификации |
| Ключ API | Версионированный подписанный ключ HMAC-SHA256 формата `sonic_live_v2.<header>.<payload>.<signature>`; полезная нагрузка содержит `sub`/`iat`/`exp`/`jti`/`kid`/`role`/`uid`; передаётся только через заголовки запросов |
| jti | Идентификатор ключа в полезной нагрузке ключа API; служит для списков отзыва и немедленной недействительности при выходе из системы |
| fail-closed | Политика безопасности, при которой отказ проверки означает отказ в обслуживании; Sonic применяет fail-closed к ключам без подписи, устаревшим ключам и сбоям хранения в производственной среде |
| Защита от SSRF | Блокировка исходящих запросов к петлевым адресам, частным сетям RFC 1918, мостам Docker и адресам облачных метаданных; проверка по двойному стеку IPv4/IPv6, повторная проверка при перенаправлении |
| Белый список доменов | Прокси аудио, обложек и пересылки допускает только HTTPS-цели из контролируемого списка музыкальных CDN-доменов (`SONIC_ALLOWED_MUSIC_DOMAINS`) |
| SQLite WAL | Постоянное хранение событий поведения и весов сущностей в плоскости данных в режиме Write-Ahead Logging в именованном томе `sonic-data` |
| Предохранитель | Трёхсостоянийный конечный автомат (CLOSED/OPEN/HALF_OPEN); после 3 подряд неудач или превышения бюджета 4,5 секунды наступает размыкание, после 30 секунд охлаждения выполняется проверка доступности и восстановление |
| Режим граничной деградации | Состояние аварийной устойчивости, при котором при отключении плоскости данных граничный уровень напрямую подключается к открытым интерфейсам текстов и поиска; в заголовке ответа указывается `X-Sonic-Degraded: 1`, в интерфейсе показывается уведомление о деградации |
| Граничный кэш | Кэш на границе с ключами `sonic:*`, период свежести 8 минут, после истечения переходит в расширенный аварийный режим |
| Range 206 | Механизм сегментной загрузки HTTP; аудиопотоки по умолчанию получают ответ 206 Partial Content через граничный прокси |
| Режим прямого подключения | Перенаправление 302 через `?mode=redirect`: браузер соединяется с официальным CDN напрямую; веб-плеер этот режим не использует |
| YRC/QRC/KRC | Форматы пословных текстов NetEase, QQ и Kugou; сервис нативно разбирает их шифрованную и сжатую упаковку (XOR + Deflate) |
| TTML | Формат языка таймкодов пословных текстов AMLL |
| LRCLIB | Глобальная открытая библиотека синхронных текстов; служит дополнением при отсутствии локального текста |
| Обнаружение пробных фрагментов | Проверка длительности аудиосущностей и метаданных, распознающая официальные 30-секундные пробные отрывки с их явной пометкой |
| Межисточниковое восполнение | Механизм межплатформенного подбора полных версий, запускаемый для пробных треков; включён по умолчанию; при успехе указывается источник замены |
| События поведения | Записи рекомендательных сигналов: воспроизведение, дослушивание, пропуск, добавление в избранное, отклонение и др.; не более 50 событий и 64 КБ в пакете; шумовые события (задержки, переключения при обрыве пробного фрагмента) не записываются |
| Очистка профиля одним нажатием | `DELETE /api/sonic/events` немедленно уничтожает все поведенческие признаки и записи в рекомендательном движке |
| Сводка рекомендательного профиля | Сводка профиля, возвращаемая `GET /api/sonic/events`: общее число событий, счётчики избранного и отклонений, часто прослушиваемые исполнители, жанровые предпочтения, недавние поисковые запросы, форма хранения |
| X-Sonic-Context | Локальный контекст клиента, прилагаемый к рекомендательным запросам (ограниченное количество избранных треков, недавних исполнителей и поисковых запросов); используется только в памяти, не сохраняется |
| Фильтрация шума | Механизм на сервере, обнуляющий вес и исключающий из базы переключения треков по 6 невиновным причинам (network_stall/playback_error/trial_end/stream_unavailable/buffer_timeout/auto_switch_error) |

## 3. Основы толкования

1. Юридические термины толкуются по официальному тексту GDPR; технические термины определяются реализацией исходного кода; при несоответствии исходного кода этому документу документ следует исправить и сообщить о проблеме (Issue) в репозиторий.
2. Официальной версией юридических документов сайта является версия на упрощённом китайском языке; перевод терминов в английской, японской и русской версиях соответствует соответствиям, приведённым на этой странице.
