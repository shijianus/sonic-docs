## 1. Позиционирование проекта

Sonic — независимо разработанная многоисточниковая платформа музыкального стриминга и агрегации, работающая на двухуровневой архитектуре «граничная плоскость управления Cloudflare + плоскость данных с локальным протокольным движком на Linux». Проект создан для стриминга высокого качества звука, пословных текстов с миллисекундной синхронизацией и самостоятельного контролируемого рекомендательного опыта. Проект является открытым программным обеспечением; исходный код опубликован, и любой желающий может развернуть его самостоятельно.

| Пункт | Описание |

| Экземпляры самостоятельного развертывания | Независимые экземпляры со своим оператором; роль контролёра зависит от фактического определения целей и способов обработки, автор кода не управляет ими автоматически |

## 3. Обзор технической архитектуры

### 3.1 Плоскость управления (граничный уровень Cloudflare)

Плоскость управления работает на Cloudflare Pages и Pages Functions и выполняет следующие задачи:

1. **Маршрутизация и аутентификация**: единая точка входа для API-запросов, проверки аутентификации и проверки подписанных ключей;
2. **Многоуровневое ограничение частоты запросов**: 240 запросов в минуту для анонимных и 600 в минуту для аутентифицированных (значения по умолчанию, настраиваются); для эндпоинтов аутентификации действует отдельный лимит 30 запросов в минуту на IP;
3. **Многоуровневое кэширование**: граничный кэш с ключами `sonic:*`, период свежести 8 минут, после истечения переходит в расширенный аварийный режим;
4. **Трёхсостоянийный предохранитель**: после 3 подряд неудач или превышения бюджета вызова 4,5 секунды наступает размыкание OPEN, последующие запросы перестают ждать разомкнутую плоскость данных и пытаются использовать граничное прямое резервное подключение (публичные поисковые интерфейсы QQ/Kugou и AMLL/LRCLIB); фактическая сеть всё равно имеет задержку; после 30 секунд охлаждения наступает HALF_OPEN с проверкой доступности, при успехе состояние закрывается. В период деградации в заголовке ответа указывается `X-Sonic-Degraded: 1`, а вверху плеера появляется уведомление о деградации.

### 3.2 Плоскость данных (протокольный движок на Linux)

Плоскость данных представляет собой стек Docker Compose на собственном узле Linux оператора:

| Компонент | Описание |
| --- | --- |
| Основной контейнер sonic-engine | HTTP-сервис Node.js 22, прослушивает порт 8080, на стороне хоста проброшен только `127.0.0.1`; все маршруты `/api`, `/proxy`, `/palette` требуют обязательную проверку межсервисного ключа (X-Sonic-Engine-Key) |
| Вспомогательный контейнер ncm-api | Вспомогательный сервис протокола NetEase Cloud Music, доступен только внутри сети compose (`ncm-api:3000`), не публикуется в интернете |
| SQLite 3 (режим WAL) | Постоянное хранение событий поведения и весов сущностей в именованном томе `sonic-data` (внутри контейнера `/app/data/sonic-recommend.sqlite`); резервное копирование выполняется консистентным снимком (VACUUM INTO) с проверкой целостности |
| Нативные протокольные модули | Разбор протоколов NetEase linuxapi/eapi, QQ, KRC Kugou и Kuwo, реализованный на чистом TypeScript |

Плоскость управления и плоскость данных обмениваются данными по зашифрованному каналу Cloudflare Tunnel; плоскость данных не публикует портов напрямую в интернете.

### 3.3 Маршрут аудиопотока

Аудиопотоки по умолчанию проходят через граничный прокси с поддержкой HTTP `Range` и `206 Partial Content`: при таком маршруте CDN получает соединение от прокси, который также может передать User-Agent браузера. Явный параметр `?mode=redirect` включает прямое соединение с CDN. Это не средство анонимизации всего трафика: MV, обложки, Google Fonts и аватары могут загружаться напрямую, раскрывая IP; URL аватара DiceBear может содержать почту в параметре `seed`. Часть запросов к вышестоящим сервисам использует HTTP, поэтому нельзя обещать шифрование всех участков передачи.

## 4. Источники аудио и цепочка текстов песен

| Источник | Роль и доля | Статус |
| --- | --- | --- |
| Локальный нативный разбор (интерфейсы NetEase/QQ/Kugou/Kuwo + ncm-api) | Основная цепочка; доля запросов не проверена | Включён по умолчанию |
| Пословные тексты AMLL TTML + библиотека синхронных текстов LRCLIB | Дополнение текстов; доля запросов не проверена | Включён по умолчанию |
| Сторонние агрегированные вышестоящие сервисы GDStudio/Lyriva | Аварийный резерв | GDStudio явно выключен в `.env.example` и Compose, но при отсутствии переменной в `licensing.ts` включён; проверяйте конфигурацию |
| Улучшение похожих исполнителей ListenBrainz/MusicBrainz | Опциональное улучшение | По умолчанию отключён |

Обнаружение пробных фрагментов проверяет длительность аудиосущностей и метаданные, распознавая официальные 30-секундные пробные отрывки; результат отображается меткой и может запускать межплатформенный подбор другой доступной версии QQ/Kugou/Kuwo. При успешном подборе указывается источник замены. Подбор не предоставляет прав на контент и не разрешает обход оплаты, ограничений доступа или защиты авторских прав.

## 5. Интеллектуальный рекомендательный движок

Основной рекомендательный движок работает в плоскости данных; при настройке внешних адаптеров данные также могут передаваться Gorse или Meilisearch. Радар сохраняет локальное состояние и пытается передать альбомы и сигналы в граничную память isolate; стандартный Node-маршрутизатор не подключает его маршрут, поэтому постоянная облачная синхронизация и резервная копия библиотеки не подтверждены. Веса основных поведенческих сигналов опубликованы в исходном коде:

| Сигнал | Вес | Описание |
| --- | --- | --- |
| favorite (добавление в избранное) | +4,0 | Очень сильный положительный |
| replay (повторное воспроизведение) | +3,5 | Сильный положительный |
| play_complete (действительное дослушивание) | +2,5 | Стандартный положительный |
| play_progress (прогресс прослушивания) | от +0,2 до +1,8 | Начисление по ступеням в зависимости от доли прослушанного |
| skip (быстрый пропуск) | -0,8 | Переключение после прослушанной половины трека даёт +0,25 |
| dislike (явное отклонение) | -5,0 | Жёсткая фильтрация и занесение в чёрный список |

Очистка от шума и ложных сигналов: переключения треков из-за задержек сети (network_stall), сбоев декодирования (playback_error), обрыва пробного фрагмента (trial_end), недоступности потока (stream_unavailable), тайм-аута буферизации (buffer_timeout) или сбоя автопереключения (auto_switch_error) всегда имеют нулевой вес и не записываются в базу.

Модель популярности объединяет эффективные воспроизведения (35 %), уникальных слушателей (25 %), показатели дослушивания (20 %), конверсию в избранное (15 %) и наклон роста (5 %), дополненные экспоненциальным затуханием по времени (список стремительного роста за 24 часа и сводный чарт популярности за 7 дней), байесовским сглаживанием и Wilson Score; вычисление похожести объединяет граф связей исполнителей и косинусную меру аудиопризнаков, а переранжирование по предельной релевантности MMR балансирует точность и разнообразие. Поисковые интенты уровня сессии и долгосрочные предпочтения разделены по слоям, но веса не определяют сроки хранения и не означают, что сохраняются только дослушивания и избранное. В RC также есть обратная связь по сущностям, данные радара и отдельные поисковые агрегаты.

## 6. Обзор архитектуры безопасности

1. **Аутентификация**: режим кода авторизации OAuth 2.0 Epomail; параметры `state` и PKCE (S256) защищают от перехвата и повторного воспроизведения кода авторизации; срок действия OAuth-cookie транзакции 600 секунд;
2. **Ключи API**: версионированный формат `sonic_live_v2.<header>.<payload>.<signature>`, подпись HMAC-SHA256, полезная нагрузка содержит `sub`/`iat`/`exp`/`jti`/`kid`/`role`/`uid`; срок при выпуске и повторном выпуске по умолчанию 30 дней, а 90 дней — только верхний предел проверки, не срок повторного выпуска; на сервере применяется сравнение с постоянным временем выполнения через Web Crypto; ключи без подписи и устаревшие ключи отклоняются безусловно (fail-closed); ключи передаются только через заголовки запросов `X-Sonic-Key` или `Authorization`, RC не принимает ключи в параметрах URL; это не удаляет старые учётные данные из URL и хранилищ `main`;
3. **Отзыв**: выход очищает текущий cookie; отзыв скопированных ключей зависит от KV, переключателей и успеха запроса, возможны задержки распространения. Статические списки jti, субъектов и нижняя граница времени выпуска — отдельные средства оператора, не гарантия немедленной глобальной недействительности;
4. **Сессии**: `sonic_session` по умолчанию действует 30 дней, использует `HttpOnly; SameSite=Lax` и `Secure` при HTTPS; локальная HTTP-разработка может отличаться. Подпись не шифрует содержимое, включая почту. Отдельные сведения о пользователе сохраняются в localStorage (`auth`), а аутентифицированный пользователь может экспортировать ключ;
5. **Защита от SSRF**: RC выполняет проверки частных сетей, петлевых адресов, облачных метаданных, DNS и перенаправлений на отдельных исходящих серверных маршрутах. Охват зависит от маршрута; он не распространяется автоматически на все вышестоящие запросы или прямые подключения браузера.

## 7. Обзор архитектуры приватности

1. **Псевдонимизация**: события связываются с производным от почты хешем или идентификатором `anon_`; детерминированный хеш с публичным префиксом можно сопоставлять, поэтому это не необратимая анонимизация. Почта и другие сведения о пользователе сохраняются в localStorage (`auth`);
2. **Управление персонализацией**: персонализация и Auto DJ включены по умолчанию без отдельного предварительного согласия. Отключение прекращает новые клиентские события профилирования, но не поиск, публичную агрегацию поисковых слов или запросы контента и не отменяет уже отправленные запросы;
3. **Очистка**: сброс затрагивает часть событий и обратной связи текущего идентификатора, но может скрыть сбой и не охватывает старые анонимные идентификаторы, радар, поисковые агрегаты, внешние сервисы и резервные копии. Локальная очистка может быть заблокирована, не удаляет HttpOnly-cookie и не заменяет выход; после очистки настроек персонализация может снова включиться по умолчанию;
4. **Минимизация журналов**: обычные журналы доступа Node минимизированы; это не подтверждает отсутствие IP, cookie или иных данных в журналах ошибок, хоста, прокси, Cloudflare и третьих лиц.

Полное изложение обязательств о приватности приведено в [Политике конфиденциальности](/ru/privacy-policy/), технические меры описаны в документе [Обработка данных и меры безопасности](/ru/data-security/).

## 8. Кому подходит и кому не подходит

Подходит: частным слушателям, желающим входить через собственную учётную запись Epomail и учитывающим известные ограничения согласия и частичного удаления рекомендательного профиля; активным меломанам, которым нужны многоисточниковый агрегированный поиск и пословные тексты; пользователям самостоятельного развертывания, обладающим основами Linux и Docker и готовым принять на себя обязанности оператора.

Не подходит: сценариям, требующим лицензионных гарантий коммерческих музыкальных сервисов, поскольку проект не предоставляет лицензий на контент; командам, ожидающим соглашения об уровне обслуживания (SLA), коммерческой поддержки или надёжной облачной резервной копии; пользователям, которым необходимы подтверждённые полное удаление и отсутствие необязательного профилирования по умолчанию.

## 9. Границы в отношении контента и авторских прав

Sonic — инструмент поиска, агрегации и воспроизведения: сервер может проксировать ресурсы, а браузер хранит загруженные и импортированные файлы. Тело локального файла не загружается, но метаданные могут передаваться для текстов и рекомендаций. Права на записи, тексты, обложки, MV и иной контент принадлежат правообладателям; MIT и доступность интерфейса не предоставляют музыкальную лицензию. Учётные данные подписчика также не означают разрешения передавать каталог другим пользователям.

Текущие записи комментариев, ответов и отметок «нравится» к MV являются локальной имитацией. Полученные от источника комментарии могут содержать чужие имена, аватары, идентификаторы и текст и попадать в публичный кэш; это не анонимные данные.

Пользуясь сервисом, соблюдайте [Политику допустимого использования](/ru/acceptable-use/); операторы развертывания обязаны самостоятельно убедиться, что сценарий их использования соответствует местному законодательству, условиям вышестоящих сервисов и требованиям лицензирования контента.

## 10. Формы развертывания

| Форма | Состав | Ключевые моменты |
| --- | --- | --- |
| Граничный шлюз Cloudflare Pages | Фронтенд SPA + Pages Functions | Публикация после сборки через `wrangler pages deploy`; требуется настроить `SONIC_SECRET`, `SONIC_ENGINE_SECRET`, `SONIC_LOCAL_ENGINE_URL` |

Обе формы вместе образуют полный сервис; при развертывании только граничного шлюза без плоскости данных сервис автоматически работает в режиме граничной деградации. Полный перечень переменных окружения приведён в `.env.example` и `docs/OPERATIONS.md` вышестоящего репозитория.

Код не заменяет точного информирования или законного основания обработки, а статическая проверка не подтверждает работу экземпляра в сети.

## 12. Частые вопросы

**Платный ли это сервис? Есть ли реклама?**
Бесплатно, без рекламы и встроенных покупок; расходы управляемого тестового экземпляра несёт его фактический оператор. Некоммерческая цель не отменяет применимые обязанности по защите данных.

**Можно ли пользоваться без входа в систему?**
Да. Основные функции и локальная библиотека доступны без входа, но это не гарантирует анонимность. Персонализация и Auto DJ уже включены по умолчанию; общей облачной синхронизации избранного нет.

**Где хранятся мои данные?**
Библиотека, настройки и сведения учётной записи (`auth`, включая почту) — в localStorage; тело аудиофайлов и обложки — в IndexedDB, но обложки могут попасть в общий каталог. События, обратная связь, поисковые агрегаты и другие данные могут храниться на сервере и в настроенных внешних сервисах. Значение 90 дней для части событий не гарантирует точное и полное удаление по сроку. Подробнее — разделы 4 и 6 [Политики конфиденциальности](/ru/privacy-policy/).

**Как удалить мой поведенческий профиль?**
Настройки → Приватность и локальные данные → «Сбросить рекомендательный профиль и записи о неприязни» запускает частичное удаление текущего идентификатора. Уведомление может не отразить сбой или `cleared: false`; старые анонимные идентификаторы, радар, агрегаты, внешние сервисы и резервные копии не охватываются автоматически. Для полной копии или удаления обращайтесь на `privacy@epocanvas.com`. Расположение средств управления — в разделе 9 [Руководства по интерфейсу и функциям](/ru/interface/).

**Отслеживают ли меня рекомендации?**
Они используют профилирование для подбора контента, а не для рекламы. Отключение прекращает новые клиентские события профилирования, но не поиск, отдельные публичные поисковые агрегаты или запросы контента. Инкогнито само по себе не останавливает события и запросы.

**Почему некоторые песни длятся только 30 секунд?**
Это официальные пробные отрывки платформ; плеер помечает обнаруженные фрагменты и при включённом межисточниковом подборе пытается найти другую доступную версию с указанием источника. Техническая доступность не предоставляет прав на контент.

**Можно ли доверять значкам качества звука?**
Значок предназначен для отображения качества текущего потока; доступность и точность метаданных зависят от источника. Гарантии каталога или качества не предоставляются (см. раздел 4 [Условий использования](/ru/terms-of-service/)).

**Какая ответственность возникает при самостоятельном развертывании?**
Она зависит от фактической роли и применимого права, включая условия статьи 3 GDPR. Оператор, определяющий обработку, должен проверить уведомления, основания, безопасность, записи и необходимые оценки; автор кода не отвечает автоматически за все экземпляры. Подробнее — [Правовые аспекты открытого кода и самостоятельного развертывания](/ru/open-source/).

**Какие языки поддерживает сервис?**
Плеер имеет встроенные языки: упрощённый китайский, English, 日本語; документация сайта доступна на 10 языках.
