## 1. Позиционирование проекта

Sonic — независимо разработанная многоисточниковая платформа музыкального стриминга и агрегации, работающая на двухуровневой архитектуре «граничная плоскость управления Cloudflare + плоскость данных с локальным протокольным движком на Linux». Проект создан для стриминга высокого качества звука, пословных текстов с миллисекундной синхронизацией и самостоятельного контролируемого рекомендательного опыта. Проект является открытым программным обеспечением; исходный код опубликован, и любой желающий может развернуть его самостоятельно.

| Пункт | Описание |
| --- | --- |
| Управляемые экземпляры | `sonic.epocanvas.tech` (основной сайт) и `sonic.epocanvas.com` (резервное зеркало), работают под управлением команды эксплуатации |
| Экземпляры самостоятельного развертывания | Частные экземпляры, которые любое лицо или организация развертывает на собственных серверах на основе открытого кода; развернувший является оператором и контролёром данных такого экземпляра |
| Лицензия на исходный код | Определяется файлом `LICENSE` в корне репозитория (MIT License); проект позиционируется как некоммерческий проект с открытым кодом; в историческом README декларировалось намерение CC BY-NC-SA 4.0, до решения сопровождающих действует файл `LICENSE`; товарные знаки и брендовые обозначения не передаются вместе с лицензией на исходный код |
| Способ входа | Epomail OAuth 2.0 (PKCE); отдельная система регистрации в проекте отсутствует |
| Состав программного обеспечения | Фронтенд и граничные функции Cloudflare Pages (плоскость управления), локальный движок Node.js 22 и вспомогательный контейнер ncm-api (плоскость данных), веб-плеер на Vue 3 |

## 3. Обзор технической архитектуры

### 3.1 Плоскость управления (граничный уровень Cloudflare)

Плоскость управления работает на Cloudflare Pages и Pages Functions и выполняет следующие задачи:

1. **Маршрутизация и аутентификация**: единая точка входа для API-запросов, проверки аутентификации и проверки подписанных ключей;
2. **Многоуровневое ограничение частоты запросов**: 240 запросов в минуту для анонимных и 600 в минуту для аутентифицированных (значения по умолчанию, настраиваются); для эндпоинтов аутентификации действует отдельный лимит 30 запросов в минуту на IP;
3. **Многоуровневое кэширование**: граничный кэш с ключами `sonic:*`, период свежести 8 минут, после истечения переходит в расширенный аварийный режим;
4. **Трёхсостоянийный предохранитель**: после 3 подряд неудач или превышения бюджета вызова 4,5 секунды наступает размыкание OPEN, последующие запросы за 0 мс немедленно переключаются на граничное прямое резервное подключение (публичные поисковые интерфейсы QQ/Kugou и AMLL/LRCLIB); после 30 секунд охлаждения наступает HALF_OPEN с проверкой доступности, при успехе состояние закрывается. В период деградации в заголовке ответа указывается `X-Sonic-Degraded: 1`, а вверху плеера появляется уведомление о деградации.

### 3.2 Плоскость данных (протокольный движок на Linux)

Плоскость данных представляет собой стек Docker Compose на собственном узле Linux оператора:

| Компонент | Описание |
| --- | --- |
| Основной контейнер sonic-engine | HTTP-сервис Node.js 22, прослушивает порт 8080, на стороне хоста проброшен только `127.0.0.1`; все маршруты `/api`, `/proxy`, `/palette` требуют обязательную проверку межсервисного ключа (X-Sonic-Engine-Key) |
| Вспомогательный контейнер ncm-api | Вспомогательный сервис протокола NetEase Cloud Music, доступен только внутри сети compose (`ncm-api:3000`), не публикуется в интернете |
| SQLite 3 (режим WAL) | Постоянное хранение событий поведения и весов сущностей в именованном томе `sonic-data` (внутри контейнера `/app/data/sonic-recommend.sqlite`); резервное копирование выполняется консистентным снимком (VACUUM INTO) с проверкой целостности |
| Нативные протокольные модули | Разбор протоколов NetEase linuxapi/eapi, QQ, KRC Kugou и Kuwo, реализованный на чистом TypeScript |

Плоскость управления и плоскость данных обмениваются данными по зашифрованному каналу Cloudflare Tunnel; плоскость данных не публикует портов напрямую в интернете.

### 3.3 Маршрут аудиопотока

Аудиопотоки по умолчанию поступают с официальных CDN через граничный прокси (прокси с поддержкой диапазонов байтов того же происхождения), поддерживающий сегментную загрузку HTTP `Range` и `206 Partial Content`: вышестоящий CDN видит только адрес прокси-сервера и не получает IP клиента. Режим прямого подключения 302 (`?mode=redirect`) предоставляется только пользователям API при явном вызове (веб-плеер его не использует); в режиме прямого подключения ваш браузер устанавливает соединение с официальным CDN напрямую.

## 4. Источники аудио и цепочка текстов песен

| Источник | Роль и доля | Статус |
| --- | --- | --- |
| Локальный нативный разбор (официальные интерфейсы NetEase/QQ/Kugou/Kuwo + ncm-api) | Основная цепочка (свыше 90 %) | Включён по умолчанию |
| Пословные тексты AMLL TTML + библиотека синхронных текстов LRCLIB | Дополнение текстов (около 10 %) | Включён по умолчанию |

Обнаружение пробных фрагментов проверяет длительность аудиосущностей и метаданные, распознавая официальные 30-секундные пробные отрывки; результат распознавания прозрачно отображается во фронтенде меткой пробного фрагмента и может запускать межплатформенный подбор полной версии (подбираются бесплатные полные версии QQ/Kugou/Kuwo); при успешном подборе происходит плавное переключение с указанием источника замены. Проект не интегрирует никаких компонентов обхода платных механизмов и защиты авторских прав.

## 5. Интеллектуальный рекомендательный движок

Рекомендательный движок полностью работает локально в плоскости данных; веса поведенческих сигналов опубликованы в исходном коде:

| Сигнал | Вес | Описание |
| --- | --- | --- |
| favorite (добавление в избранное) | +4,0 | Очень сильный положительный |
| replay (повторное воспроизведение) | +3,5 | Сильный положительный |
| play_complete (действительное дослушивание) | +2,5 | Стандартный положительный |
| play_progress (прогресс прослушивания) | от +0,2 до +1,8 | Начисление по ступеням в зависимости от доли прослушанного |
| skip (быстрый пропуск) | -0,8 | Переключение после прослушанной половины трека даёт +0,25 |
| dislike (явное отклонение) | -5,0 | Жёсткая фильтрация и занесение в чёрный список |

Очистка от шума и ложных сигналов: переключения треков из-за задержек сети (network_stall), сбоев декодирования (playback_error), обрыва пробного фрагмента (trial_end), недоступности потока (stream_unavailable), тайм-аута буферизации (buffer_timeout) или сбоя автопереключения (auto_switch_error) всегда имеют нулевой вес и не записываются в базу.

Модель популярности объединяет эффективные воспроизведения (35 %), уникальных слушателей (25 %), показатели дослушивания (20 %), конверсию в избранное (15 %) и наклон роста (5 %), дополненные экспоненциальным затуханием по времени (список стремительного роста за 24 часа и сводный чарт популярности за 7 дней), байесовским сглаживанием и Wilson Score; вычисление похожести объединяет граф связей исполнителей и косинусную меру аудиопризнаков, а переранжирование по предельной релевантности MMR балансирует точность и разнообразие. Поисковые интенты уровня сессии и долгосрочные предпочтения разделены по слоям: в долгосрочный профиль переносятся только ценные действия, такие как дослушивание и добавление в избранное.

## 6. Обзор архитектуры безопасности

1. **Аутентификация**: режим кода авторизации OAuth 2.0 Epomail; параметры `state` и PKCE (S256) защищают от перехвата и повторного воспроизведения кода авторизации; срок действия OAuth-cookie транзакции 600 секунд;
2. **Ключи API**: версионированный формат `sonic_live_v2.<header>.<payload>.<signature>`, подпись HMAC-SHA256, полезная нагрузка содержит `sub`/`iat`/`exp`/`jti`/`kid`/`role`/`uid`; срок действия при выпуске 30 дней, предел проверки 90 дней; на сервере применяется сравнение с постоянным временем выполнения через Web Crypto; ключи без подписи и устаревшие ключи отклоняются безусловно (fail-closed); ключи передаются только через заголовки запросов `X-Sonic-Key` или `Authorization`, канал через параметры запроса URL полностью удалён;
3. **Отзыв**: выход из системы немедленно отзывает текущую сессию и идентификатор ключа (jti); поддерживаются список отозванных jti, список отозванных субъектов и глобальная нижняя граница времени выпуска; при привязке KV поддерживается мгновенный отзыв;
4. **Сессии**: cookie `sonic_session` с атрибутами `HttpOnly; Secure; SameSite=Lax`, срок действия не более 30 дней; ключи не записываются в URL, localStorage или иные места, доступные скриптам страницы;
5. **Защита от SSRF**: исходящие запросы к петлевым адресам, частным сетям RFC 1918, внутренним мостам Docker и адресам облачных метаданных (например, `169.254.169.254`) блокируются безусловно; выполняется проверка по двойному стеку IPv4 и IPv6; при каждом перенаправлении цель и результат разрешения DNS проверяются заново.

## 7. Обзор архитектуры приватности

1. **Псевдонимизация по умолчанию**: события поведения связываются с однонаправленным хеш-идентификатором с самого момента сбора; адреса электронной почты не сохраняются на диск;
2. **Самостоятельное управление персонализацией**: персонализацию можно отключить в настройках плеера в любой момент; после отключения события не записываются, а в публичном режиме сразу отбрасываются;
3. **Очистка одним нажатием**: кнопка «Очистить рекомендательный профиль» на странице настроек немедленно уничтожает все поведенческие события на сервере; «Очистить все локальные данные» немедленно очищает локальное хранилище браузера и IndexedDB;
4. **Минимизация журналов**: журналы доступа плоскости данных содержат только путь, метод, код состояния и время обработки.

Полное изложение обязательств о приватности приведено в [Политике конфиденциальности](/ru/privacy-policy/), технические меры описаны в документе [Обработка данных и меры безопасности](/ru/data-security/).

## 8. Кому подходит и кому не подходит

Подходит: частным слушателям, желающим входить через собственную учётную запись Epomail и ценящим прозрачность и удаляемость рекомендательного профиля; активным меломанам, которым нужны многоисточниковый агрегированный поиск и пословные тексты; пользователям самостоятельного развертывания, обладающим основами Linux и Docker и готовым принять на себя обязанности оператора.

Не подходит: сценариям, требующим лицензионных гарантий коммерческих музыкальных сервисов, поскольку проект не хранит и не хостит музыку и не выдаёт никаких сублицензий на контент; командам, ожидающим соглашения об уровне обслуживания (SLA) или коммерческой поддержки; пользователям, не готовым принять принцип «пробные фрагменты помечаются прозрачно, межисточниковое восполнение выполняется на основе максимальных усилий».

## 9. Границы в отношении контента и авторских прав

Sonic — инструмент поиска, агрегации и воспроизведения, не хранящий и не хостящий никаких музыкальных файлов. Права на записи, тексты, обложки, изображения исполнителей и иной контент принадлежат соответствующим правообладателям; проект не выдаёт никаких сублицензий на музыкальный контент. Треки для законных подписчиков подключаются развернувшим с использованием его собственных учётных данных (например, `NETEASE_COOKIE`, относящихся к учётной записи развернувшего, а не конечного пользователя); публичные треки следуют официальным открытым протоколам.

Пользуясь сервисом, соблюдайте [Политику допустимого использования](/ru/acceptable-use/); операторы развертывания обязаны самостоятельно убедиться, что сценарий их использования соответствует местному законодательству, условиям вышестоящих сервисов и требованиям лицензирования контента.

## 10. Формы развертывания

| Форма | Состав | Ключевые моменты |
| --- | --- | --- |
| Граничный шлюз Cloudflare Pages | Фронтенд SPA + Pages Functions | Публикация после сборки через `wrangler pages deploy`; требуется настроить `SONIC_SECRET`, `SONIC_ENGINE_SECRET`, `SONIC_LOCAL_ENGINE_URL` |
| Локальный протокольный движок на Linux | sonic-engine + ncm-api + SQLite | Развертывание через `docker compose up -d --build`; права `.env` 600; подключение через Cloudflare Tunnel |

Обе формы вместе образуют полный сервис; при развертывании только граничного шлюза без плоскости данных сервис автоматически работает в режиме граничной деградации. Полный перечень переменных окружения приведён в `.env.example` и `docs/OPERATIONS.md` вышестоящего репозитория.

## 12. Частые вопросы

**Платный ли это сервис? Есть ли реклама?**
Бесплатно, без рекламы и встроенных покупок; расходы на эксплуатацию управляемого экземпляра несёт команда эксплуатации. Сервис не собирает никаких данных в рекламных целях.

**Можно ли пользоваться без входа в систему?**
Да. Поиск, воспроизведение, тексты, чарты и другие основные функции доступны анонимно (с более строгим ограничением частоты запросов); после входа открываются облачная синхронизация избранного, персональные рекомендации и Auto DJ.

**Где хранятся мои данные?**
В трёх местах: избранное, плейлисты и настройки плеера хранятся в локальном хранилище вашего браузера; загрузки и локальная музыка хранятся в IndexedDB вашего браузера; на сервере хранятся только псевдонимизированные события поведения (автоматическое уничтожение через 90 дней). Адреса электронной почты не сохраняются на диск. Подробнее — раздел 4 [Политики конфиденциальности](/ru/privacy-policy/).

**Как удалить мой поведенческий профиль?**
Настройки → Приватность и локальные данные → «Сбросить рекомендательный профиль и записи о неприязни», либо прямой вызов `DELETE /api/sonic/events`; действие наступает немедленно. «Очистить все локальные данные» одновременно очищает данные браузера и сервера. Расположение в интерфейсе описано в разделе 9 документа [Руководство по интерфейсу и функциям](/ru/interface/).

**Отслеживают ли меня рекомендации?**
Рекомендации служат только упорядочиванию воспроизведения: без межсайтового отслеживания и рекламных профилей; персонализацию можно отключить в любой момент, после чего включается чисто публичный режим и никакие события больше не записываются.

**Почему некоторые песни длятся только 30 секунд?**
Это официальные пробные отрывки платформ; плеер честно помечает их меткой пробного фрагмента и никогда не выдаёт за полные треки; при включённом межисточниковом восполнении автоматически подбирается бесплатная полная версия с указанием источника.

**Можно ли доверять значкам качества звука?**
Да. Значок отражает фактический уровень текущего аудиопотока; при изменении уровня на вышестоящем источнике он меняется в реальном времени, без завышения (см. пункт 3 раздела 4 [Условий использования](/ru/terms-of-service/)).

**Какая ответственность возникает при самостоятельном развертывании?**
С момента развертывания вы становитесь контролёром данных своего экземпляра: необходимо исполнять обязанность информирования перед вашими пользователями, вести записи обработки, при необходимости проводить оценку воздействия и обеспечивать меры безопасности. Отправная точка — раздел 6 документа [Обработка данных и меры безопасности](/ru/data-security/).

**Какие языки поддерживает сервис?**
Плеер имеет встроенные языки: упрощённый китайский, English, 日本語; документация сайта доступна на 10 языках.
