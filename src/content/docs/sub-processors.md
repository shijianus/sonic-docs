## 1. 基础设施与受托处理关系

| 对象 | 功能 | 可能涉及的数据与配置边界 |
| --- | --- | --- |
| Cloudflare Pages 与 Functions | 托管、边缘 API、缓存与限流 | IP、请求路径、标头及连接元数据；具体记录依实例和供应商配置 |
| Cloudflare Tunnel | 边缘与数据面之间的通道 | 请求流量及连接元数据；隧道不使所有内部或上游 HTTP 路径自动加密 |
| Cloudflare KV 与限流器 | 限流、凭证撤销等可配置存储 | IP 或身份派生键、撤销标识；是否启用及期限须核实 |
| 数据面宿主或托管方 | 引擎、数据库及日志所在环境 | 引擎可能收到边缘转发的原始 IP、Cookie、认证头和上下文；宿主主体与节点国家未核实 |

是否属于受托处理，取决于谁决定目的、谁依指示处理及实际安排，不能只凭产品名称判断。GDPR 适用且存在受托处理关系时，应落实第 28 条要求的安排；此处不声称已签署或核验任何合同。控制者完整身份和可送达资料仍须补充，见[隐私政策](/privacy-policy/)第 2 节。

## 2. 身份提供方（登录所必需）

Epomail（`mail.epocanvas.com`）提供 OAuth 登录。浏览器与身份服务交互，Sonic 交换授权码、查询用户资料，可能取得用户标识、邮箱及其验证标记、昵称、头像 URL 和角色；部分资料保存在浏览器 `auth` 存储及签名会话中，不是“只在内存”。

Epomail 不因登录接入或共同品牌而自动成为 Sonic 的受托处理者。其帐号体系的独立处理和受指示处理应按实际目的及安排分别判断；Sonic 仍须对自己决定的接收、保存和后续披露负责。

## 3. 上游内容来源与浏览器直连

| 来源 | 主要用途 | 可能传递或取得的资料 |
| --- | --- | --- |
| 网易云音乐、QQ 音乐、酷狗、酷我及相关 CDN | 搜索、音频、MV、封面和内容资料 | 搜索原文、内容标识与元数据；代理出口或浏览器直连的连接信息 |
| AMLL、LRCLIB | 歌词查询与补位 | 歌曲标识或标题、艺人等匹配信息，以及连接元数据 |
| Google Fonts | 字体加载 | 浏览器 IP、User-Agent 等连接信息 |
| DiceBear | 外部头像 | 当前路径可能在 URL 的 seed 中包含明文邮箱，并暴露浏览器连接信息 |

音频代理可使内容 CDN 看到代理出口，但不代表所有请求均不含个人资料。流请求可能使用浏览器 User-Agent，而非统一固定值；MV、封面、字体和头像可能直接由浏览器请求。部分提供方使用 HTTP，不能保证全链路 TLS。DiceBear 邮箱 seed 应改为本地头像或不含邮箱的标识。

上游评论含其他人的姓名或昵称、头像和文本，并可能进入公共缓存；其目的包括展示所请求 MV 的评论。评论作者不是本服务登录合同的当事人，不能仅以 GDPR 第 6 条第 1 项第 b 款处理其资料。GDPR 适用时，公开来源不自动免除第 14 条的间接收集告知要求；运营者应评估并记录独立处理依据、保存期限及告知例外，在法定时限内提供适用告知；必要保障未落实时应停用抓取或公共缓存，不承诺总能逐一联系每位作者。本地编写的评论目前仅保存在 localStorage，未发现向评论服务器发布的路径。

本地音频 Blob 未发现上传路径，但歌词匹配或推荐上下文可能发送标题、艺人、专辑、时长或标识；内嵌封面提取为 data URL 后也可能随收藏事件发送并进入远端共享曲目目录，供全站搜索或公共建议返回。因此，“音频文件主体留在设备”不等于封面图片或相关信息不外传，个人画像重置也不保证清理曲目目录及其外部索引。

## 4. 可选链路与开关差异

| 链路 | 用途与可能涉及的数据 | 核对边界 |
| --- | --- | --- |
| GDStudio（`music-api.gdstudio.xyz`） | 聚合检索、跨源补齐；查询或内容标识 | 未设置开关时源码默认开启，环境示例与 Compose 配置为关闭；实际状态须核验 |
| Lyriva（`api.lyriva.xyz`） | 歌词备源；内容标识或匹配参数 | 受 `SONIC_ENABLE_LYRIVA` 等配置控制 |
| Musixmatch（`apic-desktop.musixmatch.com`） | 歌词补位 | RC 保留实现，但 `isSourceEnabledByPolicy` 没有该来源分支，实际调用受 false 门槛阻止；旧 `main` 歌词 fallback 可能可调用，须按实际部署确认；不能视为 RC 已启用或普通开关可启用 |
| 运营者配置的告警服务 | 仅在设置有效的 `SONIC_ALERT_WEBHOOK_URL` 且告警触发时发送系统计数、发布版本、时间、凭证脱敏摘要和发送节点出口 IP | 是否启用、接收方、角色、传输和保存期限均依实例核实；管理员备注和错误信息可能含个人资料，脱敏不等于匿名化 |
| ListenBrainz / MusicBrainz | 相似艺人增强；艺人或录音标识 | 受 `SONIC_ENABLE_LISTENBRAINZ` 等配置控制 |
| Gorse | 外部推荐；假名标识、行为反馈、时间、曲目标识、标签与标题等目录信息 | 按 `SONIC_GORSE_URL` 等配置接入；当前重置不保证同步删除外部反馈或曲目资料 |
| Meilisearch | 可选检索服务；原始查询及目录资料 | 是否接入和保存期限按实例核实，不能视为匿名查询 |
| 跨源补齐 | 跨平台内容匹配；歌曲元数据 | 实际请求依匹配路径；功能可用不等于已获内容授权 |

开关配置不等于用户同意。当前个性化及 Auto DJ 默认开启的同意缺口见[隐私政策](/privacy-policy/)第 5 节；未落实必要依据与选择的可选处理应暂停，不应靠更换第三方名称绕过要求。

## 5. 法律要求下的共享

收到调取要求时，应核实请求者身份、管辖权、具体依据与范围，只提供依法必要的资料，并记录处理理由。是否通知个人依适用法律及有效限制判断；举报、怀疑违规或终止服务不自动导致向警方共享全部资料。

披露所依赖的法律义务也不能替代国际传输要求。向公开 Issue 或社区提交问题前，请移除个人资料、凭证和他人评论中的私密信息。

1. 适用 GDPR 的第三国传输应逐项满足第 44 条要求，核实是否有适用的充分性决定（第 45 条）或其他有效保障（第 46 条）。
2. 使用标准合同条款时，仍须确认适用主体、处理范围、传输评估及必要补充措施；供应商公开提供条款不代表本实例已经落实。
3. ISO／SOC 认证、供应商隐私政策或同意本页本身均不自动构成合法传输依据；搜索文本、IP 和假名标识也不能笼统排除在个人资料之外。
4. 依法可通过 `privacy@epocanvas.com` 请求有关保障的说明或副本；必要商业秘密可适当遮盖，但不能以保密为由取消法定透明义务。
