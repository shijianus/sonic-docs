## 1. 資料生命週期

| 階段 | 目前可核對的事實與邊界 |
| --- | --- |
| 蒐集 | 登入由 Epomail OAuth 提供；播放、搜尋和推薦可能產生事件。個人化在最新公開 RC 中預設開啟，不能把該預設值當作可選輪廓分析的同意；線上版本未知。 |
| 傳輸 | 瀏覽器、邊緣、資料面和上游之間的路徑依部署而變。內部及部分上游路徑使用明文 HTTP，不能聲稱全鏈路 TLS；MV、封面、字型或頭像可能由瀏覽器直接請求。 |
| 儲存 | 瀏覽器可保存帳號資料、佇列、歷史、偏好、本機音樂和快取；行為資料、日誌、備份及供應商記錄的實際位置和期限須按部署核實。 |
| 使用與共享 | 搜尋、播放和登入用於回應請求；輪廓分析、Auto DJ、搜尋統計和公開建議可能使用行為或搜尋上下文。接收者和開關見[第三方共享與傳輸清單](/zh-tw/sub-processors/)。 |
| 刪除 | 目前輪廓重置主要針對目前身分的部分事件或回饋，不保證涵蓋雷達、搜尋聚合、備份、日誌、外部服務或舊匿名識別碼；撤銷也取決於撤銷儲存設定和請求是否成功。 |

| 限流和安全 | 原始 IP、Cookie、驗證標頭、User-Agent、上下文及帳號或工作階段衍生鍵 | 可能隨請求轉送至資料面引擎；僅限防濫用、連線和安全所需的說法須以實際路由核實。 |

## 3. 安全維護措施

### 3.1 傳輸與接入

1. 公開入口可設定 HTTPS、OAuth、簽章工作階段和服務間金鑰；這些程式碼控制不能證明實際入口、代理和上游均使用 TLS。
2. 控制面與資料面是否經加密通道、資料面是否只繫結回環位址，取決於託管設定。內部明文 HTTP 路徑已足以否定「全鏈路加密」的籠統表述。
3. 代理路由的目標校驗和網域限制僅涵蓋實際經過代理的請求。稽核發現原始 IP 可能隨 Cookie、驗證標頭和上下文轉送到引擎；不能把引擎稱為只接收假名資料。
4. 音訊串流的請求可能使用瀏覽器 User-Agent，而非固定值；瀏覽器直連 MV、封面、Google Fonts 或頭像服務時，對應服務可能看到 IP 和連線中繼資料。

### 3.2 驗證與金鑰

1. 已核對的 RC 使用 OAuth state 和 PKCE，簽章工作階段預設有效期 30 日；實際 Cookie 屬性和期限仍須核驗部署。簽章用於完整性而非加密，憑證酬載可能含電子郵件地址、使用者或角色識別碼。較早 `main@ce443c8` 的 URL 憑證問題僅作舊版相容性警示，不證明其具備 RC 保護。
2. API Key 的版本、簽章、時間和 `jti` 校驗失敗時應拒絕請求；不得把名稱、環境變數或設計註解當作完整驗證控制證明。
3. 登出或批次撤銷是否即時生效取決於撤銷儲存、開關和請求是否成功；未啟用或未驗證時不能保證所有已複製憑證立即失效。

### 3.3 對外請求防禦

程式碼包含部分 SSRF、私有網路和重新導向校驗以及音樂網域白名單。它們不等於所有上游或第三方瀏覽器請求都被代理、淨化或匿名化。DiceBear 目前存在以明文電子郵件地址作為 seed 的頭像 URL 路徑；Google Fonts、MV 和封面直連可能使相應服務看到 IP。部分提供者使用 HTTP，不能聲明全鏈路 TLS。

### 3.4 儲存與日誌

1. 瀏覽器端的 `auth`、`audio`、`library`、`global`、`settings`、`recommend` 及 IndexedDB 會按功能保留資料，登出不自動清除全部裝置資料。
2. 伺服器端行為資料如以假名識別碼關聯，假名化仍可能與其他資料結合識別；它不是匿名化，也不涵蓋搜尋、雷達或第三方資料。
3. 應用程式、Cloudflare、主機和上游日誌，以及備份的實際輪替、存取權限和到期銷毀未由本次核對統一確認；不能填寫虛構備份期限或「零日誌」承諾。
4. 可選 Meilisearch 可能處理原始查詢或目錄資料。Gorse 可能收到假名回饋和曲目目錄中繼資料；刪除是否與本機刪除同步未核實。本機重置成功不能代替從共享曲目目錄或外部推薦、搜尋儲存刪除。

### 3.5 已知侷限

1. 個人化及 Auto DJ 預設開啟，缺少可證明的事前、獨立和可撤回選擇；這不是同意。
2. 公開搜尋建議可能再利用原始搜尋詞，存在暴露個人或敏感資訊的風險。
3. 刪除主要涵蓋目前身分的部分事件，未核實涵蓋雷達、搜尋聚合、共享曲目目錄及內嵌封面、備份、日誌、外部服務、Meilisearch、Gorse 和舊匿名識別碼；雷達耐久引擎路由未確認，不對其儲存狀態作肯定斷言。
4. 內部明文 HTTP、Google Fonts、直接 MV／封面請求、瀏覽器 User-Agent 及 DiceBear 明文電子郵件 URL 使「全鏈 TLS」或「電子郵件不外傳」的表述不準確。
5. 限流、撤銷、日誌和第三方開關依執行個體環境變數及供應商設定；GDStudio 程式碼在未設定時預設開啟，但環境或 Compose 可設為關閉，不能僅憑清單聲稱預設關閉。

## 4. 資料外洩應變

GDPR 適用時，安全措施應依資料性質、處理規模、實施成本和實際風險保持相稱（GDPR 第 32 條）。營運者應記錄每宗資料外洩；除不太可能對個人權利和自由造成風險外，應無不當遲延且可行時在知悉後 72 小時內向有管轄權的監督機關通報，遲報說明原因（GDPR 第 33 條）；高風險時還應無不當遲延通知當事人，適用法定例外除外（GDPR 第 34 條）。這不是自動向某一國家機關報告的承諾，也不免除其他適用法律。

實際處置應隔離受影響系統，保護或撤銷憑證，確認資料類別、範圍、接收者和時間線，並記錄判斷和補救。可透過 `privacy@epocanvas.com` 提交疑似事件；不要傳送密碼、完整權杖、會員 Cookie 或不必要的個人資料。

## 5. 資料保護的設計與預設

GDPR 第 25 條要求在確定處理方式時考慮設計與預設保護。本專案目前不能聲稱已完全落實：

1. 可選輪廓分析應預設關閉，並提供同等便利的接受、拒絕、撤回和記錄；目前原始碼預設開啟，登入或繼續使用不能替代同意。
2. 公開搜尋建議應先停用或實作最小展示、過濾、門檻、期限和刪除控制。
3. 頭像 seed 不應使用明文電子郵件地址；Google Fonts、MV、封面和其他直連資源應在評估 IP、Cookie 和識別碼傳輸後再啟用。
4. 應核查可關聯的舊假名識別碼、雷達、搜尋、共享曲目及封面、日誌、Meilisearch、Gorse 和備份，依法處理適用刪除範圍，並在適用時通知接收者；法定保留例外應說明理由、範圍和期限，不能以目前身分部分清理冒充完整刪除。

## 6. 自行部署營運者的義務

自行部署執行個體獨立營運。本頁的檢查提示不對部署者創設超出實際法律與授權的契約義務，也不構成作者的營運承諾。GDPR 是否適用須按地域連結和實際活動判斷（GDPR 第 3 條），不能因免費或個人專案一概排除。以下要求僅在各自法定條件滿足時適用：

1. 按資料性質、規模、實施成本和實際風險採取相稱措施（GDPR 第 32 條），核對傳輸、金鑰、日誌、還原和刪除，而非預設要求小型專案配置專職團隊或認證。
2. 不滿 250 人不自動豁免處理活動記錄；處理並非偶發、可能危及個人權利和自由、涉及特殊類別或刑事定罪及犯罪資料，任一情況均可能排除該例外（GDPR 第 30 條）。
3. 資料保護官按觸發條件指定，包括公務機關，以及核心活動涉及大規模定期且系統性監測，或大規模特殊類別、刑事定罪及犯罪資料處理等情形（GDPR 第 37 條）。
4. 資料保護影響評估針對處理前可能導致高風險的活動，不是每次雜湊、登入或每個免費專案都自動需要（GDPR 第 35 條）。
5. 境外主體適用 GDPR 第 3 條第 2 項時，通常須指定歐盟代表。第 27 條的偶發處理例外須同時滿足偶發、不包括大規模特殊類別或刑事定罪及犯罪資料處理、且結合性質、情境、範圍和目的不太可能造成風險；免費或非營利本身不構成例外。
6. 核對 `SONIC_RECOMMEND_RETENTION_DAYS`、資料庫路徑、記憶體回退、第三方鏈路、限流和撤銷開關，並以實際值寫入自己的告知、期限和刪除流程。
